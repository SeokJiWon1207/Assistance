## 배포와 보존

- 운영 EBS를 8GiB에서 20GiB로 늘리고 기존 ext4 파티션과 파일시스템을 온라인 확장했다. 최종 루트 파일시스템은 약 19GiB, 여유는 약 12GiB다. 볼륨 유형·IOPS·처리량은 기존 gp3/3000/125를 유지했다. [AWS 공식 확장 절차](https://docs.aws.amazon.com/ebs/latest/userguide/recognize-expanded-volume-linux.html)에 따라 파티션과 파일시스템을 각각 확장하고 `lsblk`·`df`로 확인했다.
- 별도 설치한 CPython 3.12.16으로 릴리스 전용 가상환경을 만들었다. 시스템 Python과 이전 운영 가상환경은 유지했다. 운영 `pyasn1`은 0.6.5이며 `pip check`를 통과했다.
- 기존 운영 `.env`의 모든 값, Gemini 키와 Firebase 서비스 계정을 대조해 보존을 확인했다. 기존에 없던 OpenAI 키만 추가했다. 비밀값을 출력하거나 로컬로 반출하지 않았다.
- 서버 내부 제한된 백업 디렉터리에 기존 환경·자격 증명과 사용자·대화·감사 DB를 보관했다. 스키마 버전 3/5/3을 유지했고, 백업의 모든 원본 행을 운영 DB와 `EXCEPT`로 대조해 누락·변경 0건을 확인했다. 백업 시점 사용자는 15명, 대화는 13개, 메시지는 72개였다. 이후 검증용 새 대화 2개를 실제 앱에서 실행했다.
- 기존 검색 스냅샷 31,029건을 재사용했다. SQLite 무결성, Chroma 문서 수·구조화 인덱스·메타데이터 일치를 확인했다. 이전 활성 릴리스 `20261030T013331Z`는 보존했다.

## 검사와 운영 상태

원본 작업 트리와 실제 배포 후보에서 테스트 2,796개, 커버리지 90%, 프런트 빌드 일치, Python 컴파일, 셸 문법, ruff, mypy 250개 파일 검사를 통과했다. 보안 검사도 기존 승인 예외 5건을 유지한 상태로 통과했다. 배포 후 운영 파일 798개의 SHA256이 검증 후보와 일치했다. 서버에서 전체 개발 검사 묶음을 다시 실행한 것은 아니며, 실제 런타임·DB·모델·HTTPS·브라우저 경로를 추가로 검증했다.

공개 HTTPS의 `/health`와 `/ready`가 정상이며 사용자·대화·감사·검색·구조화 인덱스 DB 점검이 모두 정상이다. 인증서 검증을 끄지 않았다. 미인증 `/api/models`는 401을 반환했다. production 모드, Secure 인증 쿠키, localhost의 앱 바인딩을 유지했다. 현재 서비스는 active이며 설치 의존성 충돌과 배포 이후 동기화 오류는 확인되지 않았다.

디스크 부족으로 10월 30일에 멈췄던 전체 이슈 저장본은 배포 후 자동 전체 동기화로 갱신됐다. 두 차례 수집의 ID 집합 일치 후 31,328건과 검색 투영 버전 2가 원자적으로 게시됐다. 저장본 기준 시각은 2026-11-02 14:54:18 KST다. 최종 readiness는 `fresh`다. 초기 동기화의 메모리 사용이 가라앉은 뒤 가용 RAM은 약 865MiB, 압축 스왑 사용은 약 353MiB였다.

업무 질문은 원본 payload를 서버 안에서 독립적으로 날짜·미종료 상태·기본 팀 범위에 따라 계산했다. 고객사별 건수와 총계가 실제 답변 표와 일치했다. 원본 이슈·담당자 정보는 서버 내부 검증 디렉터리에만 보관하고 로컬에는 집계 건수와 일치 여부만 기록했다.

**남은 품질 제약:** 업무 질문의 계획 계약·전체 저장본·표 합계 검사는 통과했지만 `aggregation_narrative`는 warning이다. LLM 설명문을 채택하지 않고 서버 계산 표만 응답하는 기존 검증 경로가 동작했다. UI의 ‘확인 필요’는 이 설명문 경고 때문이다. 응답 전체가 모든 검증을 통과했다고 판단하지 않는다. 일반 인사 응답도 업무 근거가 없는 대화이므로 검증 표시와 실제 모델 연결 성공은 구분했다.

기존 보안 예외는 변경하지 않았다. Chroma 관련 예외 4건의 재검토 기한은 2026-11-12이고, 미사용 회사 모델의 기존 HTTP 예외는 2026-12-31까지다. 이번 기본·대체 모델 호출은 OpenAI/Gemini의 HTTPS endpoint를 사용했다.

## 기록과 복구

비공개 검증 기록은 로컬 `assistant_web/runtime/production-deploy-20261102T052833Z/`에 있다. 배포·파일 해시·보존 검사·모델 호출·집계 대조·최종 상태 로그와 집계 응답 화면을 포함한다. 원본 이슈와 운영 키는 로컬 기록에 포함하지 않았다. 자동 승인 검토에서 비밀키·이슈 원문의 로컬 저장을 거절한 뒤, 키 보관과 원본 대조 모두 서버 내부에서 수행했다.

운영 키·사용자 DB 백업과 서버 내부 원본 대조는 `/var/lib/content-ai-assistant/deployment-backups/20261102T052833Z/`에 보관했다. 배포 스크립트가 생성한 외부 DB 사본은 `/var/backups/content-ai-assistant/`에 있다. 이전 릴리스와 DB 스키마가 유지되어 기존 원자적 롤백 절차를 사용할 수 있다. 롤백이 필요하면 배포·롤백 공용 잠금을 잡고 정해진 절차를 사용하며, 현재 사용자 DB를 과거 사본으로 무조건 덮어쓰지 않는다.

이 배포는 검증한 현재 작업 트리 기반의 불변 패키지다. Git 커밋·원격 push는 수행하지 않았다.
