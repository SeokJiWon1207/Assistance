# 집계 명세·Python 실행기 검증

## 구현 범위

기존 통합 플래너 호출의 JSON에 `aggregation`을 추가했다. 기존 scalar `group_by`와 공수 `total/ranking/trend` 경로는 그대로 사용할 수 있다. 별도 집계 계획 LLM 호출과 SQL 실행은 추가하지 않았다.

```json
{
  "operation": "aggregate",
  "source": "mantis",
  "group_by": null,
  "limit": null,
  "aggregation": {
    "group_by": ["customer", "platform", "month"],
    "metrics": ["issue_count", "effort"],
    "period": {
      "from": "2026-08-01",
      "to": "2026-09-30",
      "evidence": "2026년 8월부터 9월까지"
    },
    "comparison": "previous_month",
    "top_n": 3,
    "explain": true
  }
}
```

위 예시는 집계 관련 필드만 표시했다. 원천·범위·상태·필터·후속 여부 등 기존 필수 계약은 계속 필요하다.

- 그룹: customer/platform/status/owner/issue_type/month 중 최대 3개.
- 지표: issue_count와 effort. 날짜 기준은 각각 등록일과 고객사전달일로 서버가 고정한다.
- 기간: 필수, 최대 36개월. 미래 날짜는 실제 관측 종료일 이후 0으로 표시하지 않는다.
- 표시: 상위 1~20개 그룹과 기타. 요청 지표 중 첫 지표의 전체 표시 기간 합계로 선정하며 모든 월에 같은 그룹을 적용한다.
- 기간은 aggregation.period에 둔다. 별도 등록 조건 등 추가 제한은 기존 filters로 검증·적용한다.
- 내 건수와 내 공수의 혼합 요청은 담당자와 공수 기입자 범위가 다르므로 지표별로 구분하도록 확인한다.
- 모델이 지정할 수 있는 SQL, 수식, date_basis는 없다. 미지원 날짜·지표는 명세 단계에서 거부한다.

## 데이터와 계산

`trend_rows`가 여는 검증된 전체 Mantis 원본 저장본을 사용한다. 추가 필터는 정규화 전에 기존 원본 필터 검사로 적용한다. 이슈 ID 중복을 제거하고 공수는 기존 파서와 기입자 필터를 사용한다. 내부 합산에는 Decimal을 사용한다.

전체 기간·그룹을 계산한 뒤 표시 상한을 적용한다. 월 축은 유지하고 기타에도 숨긴 그룹 전체를 합산한다. 내부 그룹 버킷이 100,000개를 넘으면 부분 숫자를 반환하지 않고 범위를 좁히도록 안내한다.

전월 비교는 필요하면 표시 시작 월 이전 달까지 읽는다. 0→양수는 신규 발생, 0→0은 변동 없음, 양수→0은 -100%다. 부분 월에는 전체 월 대비 증감률을 붙이지 않는다. 기존 월 추이 포맷의 누락 월은 실제 0과 구별한다.

기여도는 그룹의 증감 / 전체 증감으로 계산한다. 현재 구성비와 구분하고 전체 증감이 0이면 비율을 만들지 않는다. 기여도는 산술 분해이며 실제 업무 원인을 의미하지 않는다.

## 전환과 감사

`MANTIS_AGGREGATION_MODE`의 기본값은 `shadow`다.

| 모드 | 응답 |
| --- | --- |
| off | 표현 가능한 기존 빌더만 사용 |
| shadow | 기존 응답을 유지하고 새 결과를 비교 |
| primary | 새 집계 표와 검증된 설명을 사용 |

shadow 비교는 동일한 요청의 저장본 트랜잭션을 공유한다. 양쪽의 완전성과 수집 시각을 확인한 뒤 총계와 전체 그룹 해시를 대조한다. 일치/불일치/비교 불가/실행 불가를 구분한다. 기존 빌더로 표현할 수 없는 복합 그룹은 비교 불가이며, shadow에서 단순 숫자로 축소해 응답하지 않는다.

기존 비교 대상은 건수 총계·단일 그룹, 공수 총계다. 기존 유형별 공수 추이는 자체 유형 제외 규칙이 있어 동등 비교 대상으로 간주하지 않는다. 동일 결과는 회귀 일치 근거이며 정답 보증은 아니다. 새로운 복합 형태는 손계산 정답 테스트를 사용한다.

배포나 실제 환경변수 전환은 이 작업에서 수행하지 않았다. primary 전환은 이후의 명시적 운영 단계이며 off로 기존 경로를 선택할 수 있다.

## 모델 설명

서버가 계산한 사실에 ID를 붙이고 모델은 최대 4개의 설명 문장을 고른다. 모델 입력 사실은 최근 월과 큰 증감을 우선해 최대 64개로 제한한다. 계산 모집단은 이 제한과 무관하다.

문장별 사실 ID, 현재 값, 숫자·부호·기간·그룹·지표·증감 방향을 검사하고 별도 LLM 의미 검토도 수행한다. 생략한 기간·지표는 연결 사실로 명시하며, 잘못 쓴 날짜나 숫자는 교정해 통과시키지 않는다. 2026년 9월과 2026-09, +100.0%와 +100% 같은 동치 표기만 정규화한다.

설명은 요청했을 때만 실행한다. 작성·검토 각각 최대 6초로 제한하며, 검토 실패나 모델 장애 시 표만 응답한다. 단순 건수에는 설명 호출이 없다. 새 설명은 기존 결정형 내용의 자동 통과 분기로 보내지 않고 별도 평가 항목을 기록한다.
