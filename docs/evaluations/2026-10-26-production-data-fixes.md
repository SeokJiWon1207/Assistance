# 운영 데이터 대조 후 코드 수정과 재검증

2026-10-26 KST. 기준 코드는 `782b52d`이며 아래 변경은 로컬 작업 트리에 적용했다. **운영 배포·커밋은 하지 않았다.** 사용자가 디스크 증설을 하지 않고 코드 수정만 진행하도록 선택했으므로 운영 인프라·DB·백업도 변경하지 않았다.

## 우선순위별 처리

| 우선순위 | 확인한 문제 | 처리 |
| --- | --- | --- |
| 1 | 디스크 부족으로 전체 Mantis 동기화 보류 | 증설 제외 결정에 따라 미해결. 안전 여유 기준을 낮추거나 원본·백업을 지우지 않았다. |
| 2 | 조회 범위 밖의 고위험 미종료 #29765·#29766 누락 | 전체 동기화 보류에 따른 제약으로 남음. 재검증에서 두 건이 여전히 현재 미종료임을 직접 확인했다. |
| 3 | 최신 이슈의 원문 팝업 404 | 검색 저장본이 없을 때 설정된 Mantis에서 해당 ID의 원문을 직접 조회한다. 기존 저장 원문은 그대로 유지한다. 현재 원문에는 출처·조회 시각·과거 저장본 없음을 표시한다. |
| 4 | 브리핑 생성 시각 9시간 오류 | ISO 문자열 절단을 제거하고 공통 사용자 시간대 표시 함수를 적용했다. 한국 시간 09:00으로 표시된다. |
| 5 | 알림 수집 보류를 알림 없음으로 표시 | 개요와 알림 화면에서 수집 보류를 명시한다. 전체 대신 ‘확인한 알림’으로 범위를 표시하고, 이미 확인한 알림과 안 읽음 필터도 보존한다. |

원문 API의 인증과 권한 경로는 그대로다. 잘못된 ID는 422, 원천에 없는 이슈는 404, 권한 거부는 해당 응답을 유지하며, 원천 연결 실패는 내부 연결 정보를 노출하지 않는 502로 구분한다. 본문·추가 정보·재현 단계·노트는 기존 원문 렌더러로 자르지 않고 제공한다.

기존 `design_system.css`의 관련 이슈 배지 수정은 보존했다. 이번 변경과 무관한 파일을 수정하지 않았다.

## 실제 데이터 재비교

- 운영 API를 기존 로그인 세션으로 읽고, 서버의 읽기 전용 SQL 및 별도의 Mantis GET으로 독립 계산했다. DB 파일을 반출하지 않았다.
- 11:29~11:32 KST 재조회에서 팀 대시보드는 최근 원천 1,000건 중 팀 범위 933건을 확인했다. 미종료 **72건 이상**, 일정 지연 **6건 이상**, 30일 이상 **34건 이상**, 고위험 **9건 이상**, 최근 30일 신규 **127건 이상**이었다. 이전 점검 이후 신규 이슈가 추가되어 이전의 71·126과 달라졌으며, 새 원천 계산과는 일치한다.
- 미종료 72개 ID 집합, 각 행의 상태·담당자·일정·경과·위험·지연, 팀원·고객사 집계, 내 업무, 저장 팀 브리핑의 **573개 비교 항목이 모두 일치**했다. 전체 데이터 정확도 성공률을 의미하지 않는다.
- 누락된 두 건을 포함해 직접 확인한 미종료는 **최소 74건**, 고위험은 **최소 11건**이다. 최신 전체 원천을 수집하지 않았으므로 확정 전체 건수라고 표시하지 않는다.
- 내 업무의 미종료 1건·지연 0건·장기 0건, #31631의 예정일 10/29는 현재 원천과 일치했다.
- 수정된 원문 API 함수로 #31631·#31666을 실제 조회한 뒤 별도 원천 GET과 제목·본문·추가 정보·재현 단계 및 전체 노트를 대조했다. 모두 일치했다. #31411은 기존 검색 저장 원문을 유지했다.
- 저장 팀 브리핑 `2026-10-26T00:00:31+00:00`은 수정된 브라우저 화면에서 **10월 26일 오전 9:00**으로 표시됐다. 저장 집계는 재생성하지 않았다.
