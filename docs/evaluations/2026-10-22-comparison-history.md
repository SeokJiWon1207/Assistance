# 비교 본문 이력 보존과 실험 조건 분류 검증

## 최종 판정

운영 릴리스 `20261021T230902Z`에 반영했다. 이전 미흡 두 문항에서 빠졌던 #25656 본문의 방문 처리 실패·소스 두 번 전달·추정적 완료 처리를 보존했다. #8634 노트33034의 진단 실험 조건도 확정 원인과 미확정 원인 양쪽에서 제외되는 것을 실제 질문으로 확인했다.

다만 **전체 답변 품질 목표를 달성한 상태는 아니다.** 수정에 사용하지 않은 H9의 최종 내용·근거·질문 대응 판정은 **충족 5건, 미흡 4건**이다. 동일한 기준으로 변경 전은 충족 3건, 미흡 6건이었다. 새 비교 답변 4건은 자연 요약을 채택하지 못해 근거 표로 대체됐다. 원래 결함의 제거와 답변 전체의 완전성은 별도로 판정했다.

## 변경 범위

- 본문과 노트의 실패 시도·소스 전달·추정적 완료를 기술 수정과 구분하는 처리 이력으로 추출한다. 본문/노트 번호를 보존하고 모든 비교 사례와 요약 모델에 전달한다. 이력이 있는데도 조치 전체가 없다고 보이지 않도록 완료된 기술 수정의 미확인과 처리 이력을 구별한다.
- 요약에서 해당 사례의 필수 이력을 연결하지 않거나 실패·전달 횟수·불확실성을 생략하면 거절한다. 표 대체 경로에서도 이력을 유지한다. 행정 종료를 확정 기술 수정이나 효과 입증으로 바꾸지 않는다.
- return·로딩 제외 등의 실험 문단을 원인으로 승격하지 않는다. 문단이 줄바꿈으로 나뉘면 ‘이 때에도’가 참조하는 앞 실험 문맥까지 대조한다. 별도로 적힌 실제 진단은 보존한다.
- 회귀 R1에서 비교 사례의 중복 종료 이력이 ‘기준 이슈’로 표시되는 문제를 발견해 실제 이슈 번호를 명시했다.
- 변경한 제품 코드는 비교 리포트 관련 4개 파일이다. 집계·조건 해석과 기존 원문 갱신 예산은 변경하지 않았고 새 모델 호출 단계도 추가하지 않았다. 작업 폴더의 다른 변경은 배포 패키지에 포함하지 않았다.

## 평가 방법

G 질문은 6개를 실행해 줄바꿈으로 분리된 실험 결과의 경계 문제를 확인하는 데 사용하여 개발용으로 전환했다. 나머지 집계 3개를 실행하기 전에 별도 H9로 교체했다. H는 기본 질문 3개와 후속 질문 6개이며 구현 수정에 사용하지 않았다.

- H 입력 SHA-256: `f290fa395e76147691ec1b22847ff6455ce1d43eb326a0672a0f7b7b33db24a8`.
- 운영 기준본 `20261021T051500Z`와 최종본에서 같은 H9를 실제 Chrome 화면으로 순차 실행했다. 첫 수정본의 H 결과는 별도로 보존했고 마지막 문구 보완 후 최종본에서 H9를 다시 실행했다.
- 최종 수집은 H9와 기존 회귀·보조 질문 R1~R5, 총 14건이다. 회사 모델을 사용했고 최종 답변·조건 계획·원문 발췌·근거 노트·독립 SQL·감사 시간·배포 해시를 대조했다. 자동 통과 배지나 요약 채택을 내용 정답률로 사용하지 않았다.
- 원천은 31,277건이다. 변경 전 집계 수집 시각은 `2026-10-21T10:05:04.798981+00:00` 및 `12:07:08.070528+00:00`, 최종 집계는 `23:10:13.776787+00:00`였다. 마지막 독립 대조 시각의 원천 갱신은 `23:20:22.018543+00:00`였다. 시간만 바꿔 신선도를 우회하지 않았다.
- 원천 시각·캐시·선택 후보가 달라 완전히 통제된 성능 실험은 아니다. 질문당 각 비교 단계의 1회 실행이며 검색 재현율이나 장기 응답시간 보장을 뜻하지 않는다.

## 기존 결함 재검증

- **R1:** #25893 기준 비교에서 #17954의 중복 종료 이력을 해당 이슈 번호와 노트62548로 표시했다. 기준 건의 종료 이력으로 잘못 귀속하지 않았다. 13.237초.
- **R2, 이전 F5:** 카카오페이증권 MTS 후속 질문에서 #25656의 실패 시도·2회 소스 전달·추정적 완료를 핵심 요약과 표에 모두 표시했다. 본문 출처도 연결했다. 확정된 기술 수정 완료는 확인되지 않는 것으로 구분했다. 11.144 → **15.590초**.
- **R3, 이전 F6:** 고객사 제한을 해제해도 같은 본문 이력이 유지됐다. 자연 요약은 의미 검증에서 거절되어 표로 대체됐다. 기준·MTS·고객사 해제와 팀 범위는 이전 저장 계획과 같았다. 11.983 → **17.008초**.
- **R4, 이전 D4:** #28579 본문의 정적 Activity 참조 진단은 보존됐다. 최종 후보가 #179/#26070/#25656으로 바뀌어 #8634가 포함되지 않았다. 따라서 이 결과만으로 실험 오분류 해결을 판정하지 않았다. 11.513 → **12.282초**. #179의 미조치·행정 종료 이력 등 응답 전체의 추가 누락 한계도 남는다.
- **보조 R5:** 같은 기준에서 우리선물로 한정해 #8634를 실제 포함시켰다. 노트33034의 return·차트 DLL 제외 실험을 확정 원인과 미확정 원인 모두에 넣지 않았고, 노트33184의 소스 변경과 33185의 전달은 유지했다. 기준 본문의 진단도 남았다. 실제 분류 호출을 거쳤고 10.052초였다.

본문 누락 두 문항과 실험 오분류라는 목표 결함은 재현되지 않았지만, 이를 R4 전체 응답이나 모든 비교 답변의 정답 판정으로 확대하지 않는다.

- 최종 배포 패키지에서 `check.sh tests compile shell ruff mypy` 통과: **2,208 tests**, coverage88%, mypy150개 파일. 새 회귀10개로 실패 재현과 정상 진단·출처 보존 조건을 확인했다.

- 최종 코드·테스트5개 파일의 로컬/패키지/운영 해시 일치. 보안·복제 DB 무결성·스키마 사전 검사를 통과했다. 최초 패키지의 data 문서 디렉터리 때문에 검색 스냅샷 연결이 잘못돼 readiness가 거절됐고, 이전 정상본으로 자동 복구했다. 문서를 보존하며 링크를 교정한 뒤 새 불변 릴리스로 활성화했다.
