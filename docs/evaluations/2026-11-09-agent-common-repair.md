# 하네스 공통 보정 흐름 통합

검증된 항목은 고정하고 실패 항목만 한 번 보정하는 거래를 `backend/evidence/repair.py`에 구현했다. 보고서와 서비스가 상위 평가 계층에 역으로 의존하지 않도록 하위 공통 모듈에 두었다. 구조 검사 기준선이나 기존 조건·근거·수치 검증 문턱을 변경하지 않았다.

## 동작과 범위

| 실패 유형 | 처리 |
|---|---|
| 표현·인용 | 확보한 원문과 실패 문장만 보정 대상으로 지정. 기존 검사 뒤 별도 의미 검토 |
| 수치·단위·기간·그룹 | 원문 또는 서버 계산 사실과 대조. 집계 사실 ID 변경 금지. 서버 표·건수·목록은 모델이 수정하지 않음 |
| 원문 부족 | 재작성으로 채우지 않음. 현재 근거와 미완료 항목을 표시 |
| 조건 불일치·권한 거절·취소 | 보정 제외. 기존 조건·전송 정책과 취소 경계를 유지 |

일반 설명, 다건 업무 문서, 기간별 집계 설명, Mantis 원문 인용 요약의 보정이 공통 거래를 사용한다. 기존 유사 사례 보고서의 내부 사실 선택·독립 검토는 앞 단계의 공통 실행기와 엄격한 실패 처리를 유지한다. 이번에 유사 사례의 추가 재작성 기능을 확대한 것은 아니다.

정상 문장은 복사해 고정하며 모델이 반환한 다른 ID는 무시한다. 수정분은 기존 경로의 원문·수치 검사와 독립 검토를 거쳐야 한다. 최종 조합 검사에 실패하면 수정분을 채택하지 않는다. 요청 취소와 반영은 기존 `ExecutionBudget.publish`로 직렬화한다. 문서에서 같은 항목(slot)의 실패 문장 하나를 고칠 때 정상 문장까지 사라지는 문제도 수정했다.

집계는 정상 설명을 보존하고 잘못된 설명만 다시 쓴다. 검증을 끝내지 못한 설명이 있으면 미완료 안내를 붙인다. 원문 인용 요약은 같은 질문 항목·근거를 보존하고, 근거가 부족한 요청 항목을 생략하는 대신 미확인으로 남긴다. 조건·건수·표시 순서·근거 등급·서버 계산표는 보정 범위에 포함하지 않는다.

보정과 독립 검토도 같은 16회 모델 호출·180초 요청 예산을 쓴다. 보정+검토 2회가 남아 있을 때만 시작하며 허용 모델·마스킹·최종 검증 예약을 유지한다. 감사의 `agent.repairs`에 경로·실패 사유·보존/수정/미해결 항목·대상 밖 변경을 남긴다. 원문 전체나 모델 입력·출력 전문을 새로 저장하지 않는다.

## 검증 기록

- 신규 회귀 16건: 정상 항목·같은 slot 문장 보존, 범위 밖 변경 차단, 원문 전달, 독립 검토 거절, 허위 수치·사실 ID 변경 거절, 본문 부족·정책 거절·취소·검토 예산 부족, 최종 조합 거절, 실제 하네스 호출/사용량 집계를 확인했다.
- 실제 하네스를 사용하는 모의 실행은 판단 2회 + 보정 1회 + 독립 검토 1회 = 모델 4회였으며, 정상 문장 변경 시도는 무시하고 보정 문장은 기존 최종 검증을 통과했다.
- 전체 **3,300 테스트**, 커버리지 **91%**, 컴파일·셸·Ruff·mypy **312파일** 통과. `git diff --check` 통과. `full-final.log`에 최종 검사 결과를 보관했다.
- 초기 전체 검사에서 새 공통 모듈의 계층 위치와 테스트 대역의 인자 계약 오류를 발견해 수정했다. 보고서→평가 계층 의존을 허용하는 식으로 구조 검사 기준선을 바꾸지 않았다. 기존 인용 보정 테스트도 전체 재작성 대신 구조화된 변경분·독립 검토 프로토콜로 갱신했다.

## 한투 3회 반복 비교

비교 기준은 [직전 보고서 도구 확장](2026-11-09-agent-report-expansion.md)의 동일 문항·정답·관련성 판정이다. 질문은 아래 세 가지이며 복합→후속을 같은 대화로 실행했다.

1. `전사 범위에서 한투 미해결 이슈가 몇 건이야? 최근 3건을 보여주고, 두 번째 이슈와 관련된 Notion 가이드도 설명해줘.`
2. `그중 두 번째 이슈 번호와 제목만 다시 알려줘.`
3. `전사 한투 미해결 이슈를 상태별로 몇 건인지 알려줘.`

실제 한투 프로젝트 ID 8을 기준으로 독립 SQL을 실행했다. 미해결은 **5건**, 최근 순서는 **#31659 → #29186 → #28764**, 상태별 **정보 부족 3건·할당된 이슈 2건**이었다.

| 미해결 조건·건수 / 목록·순서 / 후속 ID·제목 / 상태별 집계 | 각 3/3 | 각 3/3 |
| 현재 Notion 본문 / 같은 화면의 참고 근거 | 각 3/3 | 각 3/3 |

직접 가이드의 이번 실패는 관련 참고 문서만 확인한 1건과 추가로 읽은 원문 버전에 대한 독립 판정이 없는 2건이다. 미판정을 통과시키지 않았으며 문서 부재로 단정하지 않는다. 직접 가이드 탐색을 이번 보정 작업으로 해결했다고 주장하지 않는다.

**이번 실측 9응답에는 보정 거래가 발생하지 않았다.** 서버 계산·목록·후속 순번·참고 발췌 경로에서 기존 검증을 통과했기 때문이다. 실제 감사 DB의 `agent.repairs`가 모두 빈 배열임을 확인했다. 따라서 이 실측은 기존 응답의 회귀 확인이며 보정 성공률의 실측 근거는 아니다. 보정의 보존·실패 분류·재검증은 위 실패 주입 테스트로 검증했다. 모의 응답을 실제 모델의 보정 성공 사례로 세지 않았다.
