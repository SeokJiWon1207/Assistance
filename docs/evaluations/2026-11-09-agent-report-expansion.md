# 남은 보고서 도구 연결과 내부 호출 통합

고객사 프로필·처리시간·공수/처리시간 결합·유사 사례·초동 대응·특수 업무조회를 일반 에이전트 경로에 연결했다. 모델이 보고서 도구와 후속 조회 순서를 정하고, 기존 서버 계산기·검증기가 조건·수치·원문을 대조한다. 이번 범위는 하네스의 도구 확장이다. 문서 초안 기능 확대나 실제 병렬화는 포함하지 않는다.

## 지원 범위와 정확성 계약

기존 공수·주간·월간 3종에 아래 14종을 추가하여 `build_issue_report`가 17종을 지원한다.

| 종류 | 처리 및 한계 |
|---|---|
| `profile` | 확정 고객사·상태·기간으로 현황·장기 미종료·등록→수정 처리기간 근사 계산 |
| `sla`, `effort_sla` | 고객사·상태·등록/전달일 조건을 보존하며 공수와 처리시간 계산. 결측·역전 날짜는 평균에서 제외 |
| `similar` | 확인한 기준 이슈와 과거 후보를 분리. 사실 선택·초안·독립 검토를 공통 모델 실행기로 호출 |
| `triage` | 입력 증상의 확인 절차와 플랫폼 범위의 참고 사례. 해당 고객사의 실제 원인으로 단정하지 않음 |
| `priority`, `aging`, `due`, `customers` | 우선순위·장기 미종료·목표일·고객사 현황. 명시 등록 기간·전사 범위를 임의 삭제하지 않음 |
| `comparison`, `completed`, `waiting` | 현재 자료로 확정할 수 없는 과거 상태·완료 시점·고객 회신 대기는 미완료로 표시. 이력 수집을 새로 구현한 것은 아님 |
| `pivot`, `spike` | 기존 월별 교차표·급증 계산. 확정 집계 축과 원천의 전체 조회 상태를 전달 |

`report_contracts.py`가 종류·날짜 기준·결측·참고 범위를 만들고 도구 인자의 `kind`, `effort`, `options`와 대조한다. 모델이 기간이나 계산 의미를 바꾼 인자는 거부한다. 공수의 기간 생략은 기존 회사 기본값인 올해 전달일로 표시하지만, 질문의 명시 연도·기간을 누락한 경우는 이 기본값으로 통과시키지 않는다.

기한은 고객사전달·개발완료·QC 완료 등의 목표일 중 우선순위가 앞선 유효 날짜이며 완료 실적일과 다르다. 목표일이 없으면 포함 여부 미확인이다. 처리시간은 정확한 종료 시각이 아닌 등록일→최종수정일 근사다. 현재 처리시간 계산기의 조회 범위 제한은 그대로이며, 일부 조회를 전체로 표시하지 않는다.

유사 후보와 초동 참고는 원장의 `reference`로 분리한다. 기준 ID·후보 ID 상한·적용 범위를 단계 검증에서 대조한다. 제한된 후보 검색 결과가 없다는 이유로 전체 부재나 동일 원인을 확정하지 않는다. 기존 보고서 검증 모드를 보존하고, 복합 답변에서도 각 부분의 기존 검증과 최종 조합 검증을 수행한다. 보고서 실패를 일반 자유 서술로 우회하지 않는다.

## 내부 호출·예산·취소

유사 보고서의 사실 선택, 초안, 독립 검토는 주입된 공통 실행기 콜백을 사용한다. 재시도·허용 대체 모델도 모델 호출 한도 16회에 포함하며, 실패 시도의 사용량 미보고도 기록한다. 요청 180초, 도구 16회, 최종 검증 예약, 허용 모델·전송 목적지·마스킹·문맥 제한을 유지한다.

보고서 도구는 여러 하위 단계를 포함하므로 최종 검증 예약을 제외한 조사 시간을 사용한다. 내부 모델의 개별 짧은 마감은 유지한다. 정책 거절·요청 취소·서빙 변경은 선택적인 요약 실패로 삼키지 않는다. 취소 이후 원장 반영 차단과 호출별 상태 격리도 기존 구현을 사용한다. 실제 도구 병렬 실행은 켜지 않았다.

모의 실행에서 판단 2회와 내부 사실·초안·독립 검토 3회가 합계 5회로 집계됐다. 내부 전용 HTTP 함수를 직접 호출하면 테스트가 실패하도록 검사했다. 독립 검토가 부정한 문장은 표시하지 않는다.

## 검증

- 신규 테스트 20건과 라우팅 사례 14건: 지원 종류, 조건·옵션 변경 차단, 전체 0건/부분 조회, 날짜 결측·역전, 목표일 우선순위, 등록 기간 보존, 참고 등급, 내부 호출·재시도·대체 모델·예약·정책·취소, 보고서 실패의 우회 차단, 복합 응답 검증을 확인한다.
- 공수/처리시간 결합에서 다른 고객사·전달 기간 밖 이슈가 양쪽 결과에 들어오지 않는지 확인했다. 공수 수치를 변조하면 기존 재계산·표시 검증이 차단한다. 업무조회 건수와 최종 조합 내용의 변조도 차단한다.
- 전체 테스트 3,284건, 커버리지 91%. 컴파일·셸·Ruff·mypy 310파일 통과. 마지막 명시 기간 누락 방어를 포함한 관련 회귀 320건도 통과했다.
- 초기 전체 검사에서 순환 의존성이 발견되어 공통 종료 신호를 독립 모듈로 옮겼다. 구조 검사 기준선을 완화하지 않았다. 새 보고서 모드를 조합할 때 기존 부분 검증이 거부하는 문제도 연결 후 재검증했다.

## 한투 실측

직전 [호출 상태·예산·취소 기준선](2026-11-09-agent-call-ownership.md)과 같은 질문·정답·관련성 판정으로 복합·후속·집계 3회씩 실행했다. 초기 저장본은 운영에서 새로 갱신된 것을 일관된 SQLite 백업으로 복제했다. 기존 만료 시간을 늘리지 않는다. 같은 저장본의 독립 SQL 정답은 미해결 5건, 최근 #31659→#29186→#28764, 정보 부족 3건·할당된 이슈 2건이다.

모든 최종 반복에서 코드·설정·초기 저장본 버전을 고정한다. 직전 단계와는 저장본 세대와 실행 시각이 다르므로 지연 차이를 코드 변경의 인과 효과로 해석하지 않는다. 직접 기능 가이드와 단순 관련 문서를 구분하는 채점도 유지한다. 별도 프로필 실측은 동일 미해결 5건만 사용한다.

| 평가 항목 | 직전 기준선 | 이번 최종 3회 |
|---|---:|---:|
| 미해결 조건·5건 / 표시 목록·순서 / 후속 순번 / 상태별 집계 | 각 3/3 | 각 3/3 |
| 현재 Notion 본문 / 같은 화면의 참고 근거 | 각 3/3 | 각 3/3 |
| 직접 기능 가이드 관련성 통과 | 0/3 | 0/3 |
| 요청 항목 통과 | 21/24 | 21/24 |
| 전체 요청 완료 / 부분 완료 | 6/9 / 3/9 | 6/9 / 3/9 |

직접 관련성 0/3 중 2건은 같은 화면의 참고 문서여서 직접 기능 가이드 기준을 충족하지 못했고, 1건은 추가로 읽은 원문 버전의 독립 판정이 없다. 미판정을 통과로 바꾸거나 문서 부재로 단정하지 않았다. 기존 조건·수치·근거 검사와 전송 정책을 유지했으며, 제품의 종료 표시만으로 복합 요청 완료를 인정하지 않는다.

별도 질문 `전사 범위에서 한투 미해결 이슈만 대상으로 고객사 프로필을 보여줘.`는 **1/1 통과**했다. 실제 `prepare_query`→`build_issue_report` 경로를 사용했고, 5건·출처 ID 집합과 12개 기존 검사가 모두 일치했다. 모델 3회·도구 2회, 10.020초였으며 유효 저장본을 사용해 원천 HTTP 요청은 없었다. 나머지 신규 보고서의 날짜·근거·내부 모델 경계는 결정형/모의 모델 테스트로 검증했으며, 모든 보고서를 외부 모델로 반복 검증한 결과로 확대해 해석하지 않는다.

| 지연(초, 평균 / 관측 p95) | 직전 기준선 | 이번 최종 |
|---|---:|---:|
| 복합 | 93.350 / 126.917 | 61.911 / 89.555 |

최종 실행은 **09:54:47~09:58:38 KST**이며 프로필 확인을 이어서 수행했다. Mantis 저장 시각은 **09:40:19**, Notion 240 DB 목록 갱신은 **09:11:13~09:13:48**이다. 최종 반복의 Notion 나이는 **2,615~2,844초**로 기본 TTL 7,200초 안이었다. 모든 최종 실행에서 코드·설정·초기 저장본 해시가 같고 작업 파일과 실행 복제본도 일치함을 `compare.py`로 확인했다.

- 원시 응답·관측 이벤트·실행별 manifest·채점·실패/성공 테스트 로그: `assistant_web/runtime/agent-report-expansion-20261109/`.

순환 의존성·응답 조합·기본 기간 방어 보완 전 예비 **21응답**은 코드 버전별 `pilot-*`에 별도로 보존했다. 예비 사용량은 모델 112회·도구 98회·원천 364회·입력 1,520,239(캐시 1,265,766)·출력 10,036토큰이다. 예비+최종+프로필의 정상 네트워크 측정은 **31응답·모델 160회·도구 141회·원천 492회·입력 2,138,778·출력 14,503토큰**이다. 샌드박스 네트워크 제한 실행 3응답은 별도로 보존했으며, 모델 연결 시도 4회가 실패하여 사용량 미보고다. 이 실패를 검색 품질 점수에 섞지 않았다.


예비 실행과 네트워크 제한으로 연결하지 못한 실행은 최종 표본과 섞지 않고 원시 기록·사용량을 보존한다. 금액은 단가 미등록으로 미산정이며, 사용량 미보고·미등록 단가를 0원으로 처리하지 않는다. 실측 원문은 Git 제외 런타임에 둔다.

## 운영과 다음 단계

이 구현만으로 [운영 적용 기준](../../assistant_web/docs/AGENT_EVALUATION.md)을 통과한 것은 아니다. 직접 가이드 확보, 여러 고객사·표현·후속 문항의 표본, 지연·비용 기준을 계속 확인해야 한다. 운영 플래그·서버 재시작·배포는 변경하지 않았다.

다음 단계는 공통 보정 흐름 통합이다. 표현·인용, 수치 불일치, 원문 부족을 구별하고 검증된 부분을 보존한 채 실패한 부분만 보정한다. 이후 독립성 판정과 병합 규칙을 추가해 동시 실행 2개 수준의 제한 병렬화를 검증하고, 기능별 운영 기준을 통과한 뒤 기존 경로의 중복을 제거한다.
