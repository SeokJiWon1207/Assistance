## 실행·상태 계약

- 모델이 한 턴에 제안한 인접 호출을 서버가 판정한다. 모델의 복수 호출 지원과 턴당 호출 상한도 유지한다. 저장본 건수·목록·집계, 이미 확인한 서로 다른 이슈 상세, 순번/가이드 복구 의존성이 없는 Notion과 Mantis 조합만 병렬 후보로 삼는다.
- 신규 근거/조건 참조, 근거 필드에 의존하는 추가 조사, 최근 N건 API 모집단, 계획 변경, 내부 모델 호출이 있는 보고서는 순차 실행한다. 새 목록이 있어야 정할 수 있는 상세와 Notion 순번 탐색도 먼저 목록을 확정한다. 두 Notion 호출은 참조 번호·본문 무효화·가이드 대체 탐색을 공유하므로 순차 실행한다.
- 호출마다 기준 상태와 작업 사본을 고정한다. 작업자는 원장에 직접 게시하지 않는다. 조정자가 변경한 키/단계만 병합하고 `condition_steps.stage_indices`를 재계산한다. 내용 충돌은 해당 결과를 거절하고, 요청 외부의 소유자 버전 변경은 묶음 전체를 거절한다. 일반 `execute`의 기존 동시 갱신 거절도 유지한다.
- 공통 정책·취소·마감 문맥을 작업자에 전달한다. 원자적 예산 차감, 최종 검증 예약, 취소 이후 게시 차단, 동일 Notion 연결의 429 대기를 재사용한다.
- 최초 요청 저장본 캐시의 중복 읽기 경합과 공통 단계 시간 합산 누락을 재현해 잠금으로 보정했다. 논리 도구 시도·원천 HTTP·단계 작업 시간·요청 경과 시간을 구분하며, 게시가 거절된 본문은 근거 읽기 성공으로 집계하지 않는다.

구현: `backend/tools/parallel.py`, `call_state.py`, `registry.py`, `services/agent/orchestrator.py`, `policy.py`, `sources/mantis_store.py`, `timing.py`. 평가기는 병렬 묶음/최대 동시 수와 병렬 실행 시도도 기록한다. 자세한 계약은 `assistant_web/docs/AGENT_HARNESS.md`와 `AGENT_EVALUATION.md`에 반영했다.
