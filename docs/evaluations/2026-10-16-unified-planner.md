# 단일 LLM 질문 해석 적용과 검증

질문 전체를 한 번의 모델 호출로 계획하고, 백엔드가 원문 근거·허용 필드·인증 사용자·상속 조건을 검증한 뒤 기존 도구로 실행한다. 건수는 모델이 계산하지 않는다. 설명 답변의 검색어 생성 및 근거 기반 답변 호출은 질의 해석 호출과 별도로 유지한다.

## 변경

- 기본 경로는 `UNIFIED_QUERY_PLANNER_ENABLED=true`. `false`로 이전 해석 경로를 실행할 수 있다.
- 기존 상태 전용 모델 호출과 일반 계획 호출을 단일 구조화 계획으로 통합했다.
- “남아 있는 이슈 모두”의 ‘모두’를 전체 상태로 확장하지 않는다. 미종료는 해결·종료 제외, 개발완료 포함이다.
- `registered_reporter`는 Mantis 등록 계정만 조회한다. 기존 `reporter`의 본문 메일 발신자 포함 의미는 유지한다.
- 후속 질문은 같은 사용자·질문에 묶인 서버 감사 기록에서 조건을 상속하고 변경한 차원만 교체한다. 클라이언트 답변 텍스트를 확정 조건으로 신뢰하지 않는다.
- 모델이 이전 확정 필터를 반복해 출력하면 정확히 일치하는 필터만 중복으로 처리한다. 새 값에는 현재 질문의 근거가 필요하다.
- 계획/상태 JSON이 잘못됐거나 모델이 실패하면 확인 질문으로 종료한다. 조건을 버린 전체 집계로 우회하지 않는다.
- 단일 계획의 건수 응답은 대표 이슈 5개를 표시한다. 기존 문장 규칙이 ‘수는’을 목록 개수로 다시 해석해 근거 수보다 많은 이슈를 출력하는 문제를 방지한다.

## 검증 방법

- 원본: Mantis 31,243건의 동일한 동결 SQLite 저장본. 수집 시각 2026-10-15T21:07:30.798467+00:00.
- 모델: 설정된 회사 `company-qwen3.6-35b-a3b`. 실제 회사 모델 호출, 데이터 원천의 라이브 조회는 차단했다.
- 기존 코드: main `4f72c9a2aa299c282f4ace472bff663db9631ad1`의 backend/config 사본.
- 최종 답변: `ChatService.build_response`를 통해 해석→집계/검색→답변→검증→감사 저장까지 실행했다. HTTP/브라우저/운영 부하는 포함하지 않는다.
- 후속 질문에는 부모 답변의 실제 감사 ID와 대화 기록을 전달했다.
- 건수 정답은 제품 파서/매처를 사용하지 않고 raw JSON의 담당자·등록자·상태·고객사·매체·등록일·제목에서 산출했다.
- 설명은 요구 사실, 요청/완료의 구분, 노트 ID, 원문 인용을 직접 대조했다. 제품 자체의 검증 점수를 정답률로 사용하지 않았다.
- 개발 질문 24개와 평가 질문을 분리했다. 최초 새 평가 U01–U24에서 드러난 후속 중복 필터 형식을 보완한 뒤 V 묶음을 별도로 고정했다. V07은 대표 목록/근거 개수 오류 수정에 사용하여 최종 미사용 평가에서는 제외하고 V25로 교체했다. 이후 V09의 상태 근거 생략부호 형식을 보완하고 해당 문항을 V26으로 교체했다. 수정에 사용한 문항은 회귀 검증 대상으로 별도 보관하며 최종 미사용 평가 점수에 넣지 않는다.
- V24의 초기 정답 작성에서 누락했던 구조화 ‘사유 및 원인/조치 및 개선’ 필드를 검수에서 확인했다. 메모리 비정상 해지와 방어코드는 기록된 사실이므로 허용하며, 고객 검증/운영 반영 완료는 단정하지 않는다. 질문/제품 코드를 이에 맞춰 튜닝하지 않았다. 원래 manifest와 정답 정정 기록을 모두 보존했다.

## 재현 자료

로컬 `assistant_web/runtime/unified_planner_20261016/`에 manifest와 SHA-256, baseline 사본, 문항별 모델 출력/최종 답변/시간, 원문 검수, 코드 불변 해시, 검사 로그가 있다. 실제 이슈 원문과 실행 원본은 Git에 추가하지 않는다.

전체 회귀에서는 이전 경로 호환성 테스트와 새 경로를 명시적으로 활성화한 통합 테스트를 함께 실행한다. 기존 테스트의 통과를 모든 질문에 대한 새 모델 해석 정확도로 간주하지 않는다. 실제 모델 정확도 범위는 아래 표의 문항에 한정한다.

## 회귀와 범위

기존 개발 24문항은 실제 모델 재검증에서 24/24였고, 최종 코드에서도 보관한 동일 모델 출력으로 실행·검증 경로를 재생해 24/24 집계를 확인했다. 원래 남은 두 오류는 미종료 2건(Q11), 등록 요청자 138건(Q19)으로 맞았다. 기존 메일 발신자 포함 요청자 검색의 의미는 그대로 유지한다.

`check.sh tests compile shell ruff mypy` 통과: 1,970개 테스트, 커버리지 88%, 137개 소스 파일 mypy 통과. `check.sh audit`는 기존에 문서화된 예외 5개를 적용하여 통과했다. 권한·CORS·쿠키·모델 endpoint 보안 설정은 변경하지 않았다.

100%는 이 고정 문항에서의 결과이며 운영 전체 정확도 보장이 아니다. 전후 각각 한 차례 측정한 소규모 비교로, 운영의 동시 부하·HTTP/브라우저 전송 시간은 측정하지 않았다. Notion 실제 모델 질의와 모든 특수 보고서 조합을 이 평가에 포함하지 않았다. 코드 변경은 로컬 작업 트리에 있고 운영 배포/커밋은 이번 작업에서 수행하지 않았다.
