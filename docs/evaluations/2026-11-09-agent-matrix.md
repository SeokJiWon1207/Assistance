## 결론

운영 적용 범위를 넓힐 기준을 충족하지 못했다. 명시 조건의 건수·목록·집계와 후속 대화의 조건 승계는 분리해서 봐야 한다. 고객사 변경 후속에서 이전 상세 이슈 번호가 남거나 미해결 조건이 사라지는 문제가 양쪽 설정에서 나타났다. `위 목록 2번` 표현도 안정적으로 해석하지 못했다. 본문 읽기 성공을 직접 가이드 확보로 승격하지 않았다.

최종 72개 예정 요청 중 70개를 실행했고, 병렬 2개 후속 요청은 선행 실패로 실행하지 못했다. 전체 평균 지연은 순차 26.738초/병렬 28.401초, p95는 118.815초/119.561초다. 실행 요청당 평균 비용은 병렬이 19.3%, p95 비용은 41.8% 높았다. 요청 수와 실패 형태가 달라 병렬화 자체의 효과로 해석할 수 없으며, 이번 표본에서는 속도·비용 우위를 확인하지 못했다.

## 남은 실패의 성격

1. **목록 범위와 상세 대상의 혼합.** 순번 질문으로 한 이슈를 본 뒤 고객사만 바꾸면 직전 `issue_id`가 상속되고 `open`이 사라지는 사례가 있다. 이 잘못된 조건으로 0건을 계산하면 서버의 조건/수치 대조는 통과할 수 있지만 독립 정답에는 실패한다. 일부 실행은 ID를 제거해도 미해결을 복구하지 못해 승인 범위 밖 모집단을 조회했고, 평가 보호 장치가 중단했다.
2. **순번 표현 의존.** `backend/intent/context.py:144`의 순번 파서는 `두 번째`, `2번째`를 지원하지만 `2번`은 반환하지 않는다. NH 순번 후속은 순차 1/3, 병렬 0/3만 성공했고 나머지는 확인 질문 또는 범위를 잃은 새 조회로 이어졌다. 정규식 한 표현의 추가뿐 아니라 모델이 표시 목록의 참조와 순번을 선택하고 서버가 실제 표시 ID와 대조하는 계약이 필요하다.
3. **본문 읽기와 직접 근거의 차이.** 한투의 알려진 문서는 같은 7695 화면의 저장·불러오기 설명이며 화살표 메모 기능의 직접 가이드가 아니다. KB·NH 등 새 반환 본문의 사전 판정이 없으면 `unassessed`를 유지했다. 이 결과로 문서가 없다고 결론 내리거나 모든 미확인을 검색 실패로 해석하지 않는다.
4. **본문 확보 전에 남은 탐색 예산을 소진.** 순차 3회차 KB는 상세 조회 인자 거절 2회, Notion 검색 약 101초 뒤 `retrieval_budget_exhausted`로 본문을 확보하지 못했다. 병렬 3회차 NH는 상세 조회 `condition_mismatch` 6회를 포함해 탐색하다 `call_limit`으로 종료했다(모델 호출 14회, 상한 16회 중 최종 검증 예약 2회). 해당 본문 실패 2요청에서는 429가 관측되지 않았다. 호출 한도/최종 검증 예약을 느슨하게 하기 전에 상세 대상과 단계별 조건 인자를 제대로 연결하도록 보완해야 한다.

다음 수정 우선순위는 목록의 모집단 조건과 상세 조회 대상을 분리하고, 순번/고객사 변경 후속의 참조를 검증하는 것이다. 그 뒤 같은 고정 문항으로 다시 비교한다. 이번 작업은 해당 제품 로직을 보정하거나 운영에 병렬 설정을 적용한 작업이 아니다.

## 전송 범위와 예비 실행

초기 예비 실행의 KB 계획 기대 키가 표시명 `KB`로 설정돼 실제 정규 키 `kb`를 오채점했다. 이를 수정한 새 문항 버전으로 최종 비교를 다시 시작했으며, 예비 결과를 최종 통계에 섞지 않았다.

예비 순차 실행에서 NH 순번 해석 실패로 승인 대상 밖 이슈 #31741, #31738, #31737, #31735, #31733의 조회 결과가 후속 Luna 호출에 포함됐다. 실행을 중단한 뒤 `benchmark_scope.approved_mantis_issues`를 추가했다. 승인한 27건 밖 결과/모집단은 모델 전달을 위한 원장에 게시하기 전에 예외로 중단한다. 조건을 승인 ID로 바꿔 정답을 만드는 방식이 아니며, 해당 요청은 실패다. 관련 Notion 읽기는 기존 권한·전송 정책을 그대로 적용한다.

예비 순차 12요청의 관측 비용은 $0.027758140, 원문 없는 가격 계측 확인 1회는 $0.000009000, 사전 Notion 읽기는 HTTP 39회다. 중단한 예비 병렬 요청은 관측기가 사용량을 파일로 저장하기 전에 종료돼 전체 비용이 미확인이다. 따라서 최종 비교 비용은 정확히 구분하되, 이번 작업 전체 청구 비용을 확정했다고 주장하지 않는다.
