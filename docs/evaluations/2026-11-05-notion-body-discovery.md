# Notion 미수집 본문·연결 페이지 조사와 재검증 — 2026-11-05

**비교차트 기술 절차는 존재하며 이전 저장본에도 들어 있었다.** 「SK증권 KRX 차세대 구축 정보 및 진행상황」과 연결된 「SK KRX 차세대 진행상황 및 내용정리」에 비교차트 업종코드 변환, 설정 파일, 테스트 절차가 있다. 제목이 가이드가 아닌 진행 기록의 본문을 후보로 올리지 못했고, 후보를 올린 뒤에도 모델이 제목만 같은 문서를 우선 읽는 문제가 있었다.

이 자료는 **SK HTS의 비교차트 기술 참고자료**다. 한투 MTS `#31659`의 장중 실시간 업데이트 장애를 직접 해결하는 문서가 확보됐다는 뜻은 아니다. 두 문서에는 같은 절차가 중복돼 있으므로 독립된 가이드 2개로 세지 않는다. 한투 전용 가이드나 전사 가이드의 부재도 확정하지 않는다.

이전 [가이드 탐색 검증](2026-11-05-notion-guide-recovery.md)의 ‘비교차트 가이드 미확보’와 ‘연결 후보 본문 읽기 실패’를 이어서 조사했다. 해당 보고서의 당시 결과는 그대로 유지한다.

## 조사 범위와 원문 확인

관련 제목·저장 본문 후보 205개와 기술문서 시작점 2개를 조사했다. 205개 안에는 비교차트 제목 82개, 차트 도움말·가이드 성격의 제목 73개, 본문 미수집·현재 본문 미확인 후보 56개가 포함된다. 이 분류는 서로 겹친다.

관측된 연결을 최대 2단계까지 따라가 **380페이지의 현재 본문**을 읽었다. 시작점 207개, 1단계 62개, 2단계 111개다. 첫 연결은 현재 읽기 범위에 있는 대상을 조사하고, 다음 단계는 하위 페이지 또는 차트·가이드 주제의 연결로 제한했다. 전체 Notion 그래프를 전수 조사한 것은 아니다.

- 비어 있지 않은 본문 141개, 빈 본문 239개. 380개 모두 접근 가능한 텍스트 조회는 완료했다.
- 262개는 전체 지원 블록 조회도 완료했다. 118개는 `unsupported_block`이 남아 있다. 이미지·첨부파일 OCR이나 지원되지 않는 블록까지 모두 확인했다고 주장하지 않는다.
- 관측 연결 944개, 고유 대상 435개. 연결 대상 중 고유 17개는 HTTP 404, 4개는 HTTP 400이었다. 실패·범위 밖·깊이 제한 대상은 완료한 380개와 구분한다.
- 「신버전 차트 도움말 작성」과 「구버전 차트 도움말 작성」의 도움말 링크는 읽기 API와 연결된 Notion 조회에서 모두 404였다. 삭제됐는지 현재 연결에 공유되지 않았는지는 구분할 수 없다. 이 두 작성 기록의 지원되지 않는 블록은 버튼으로 확인됐으며 숨은 도움말 본문으로 취급하지 않았다.

현재 원문에서 확인한 비교차트 절차:

| 문서 | 확인 내용 | 근거 범위 |
| --- | --- | --- |
| [SK증권 KRX 차세대 구축 정보 및 진행상황](https://www.notion.so/5bdf9e81f54d40ce9f74956843386274) | 구 업종코드→신 업종코드 변환, 사용자 설정·기본 비교차트 파일, 호환성 테스트 | SK HTS 공통 기술 참고 |
| [SK KRX 차세대 진행상황 및 내용정리](https://www.notion.so/74e696a163b6456cbc36eba2c3cb52d4) | 같은 비교차트 절차와 `USER_GROUPLIST.dat`, `BASE_GROUPLIST.dat`, `compbaselist.dat` 설명 | 위 문서와 중복된 절차 |

이전 검증에 사용한 저장본과 새 저장본의 해당 구간을 비교했으며 **두 문서 모두 같은 절차가 이미 있었다**. 따라서 이번 발견을 새 수집만의 효과로 설명할 수 없다. 이전 최종 3회에서 부모 문서는 검색 결과에 없었고, 연결 문서는 1회 후보로 반환됐지만 현재 본문까지 읽지 않았다. 이번 중간 실행에서도 순위를 고친 뒤 모델이 후보를 읽지 않고 검색만 반복했다. 후보 순위와 모델의 본문 선택을 함께 보완했다.

비어 있지 않은 주제 관련 본문 56개는 승인된 Luna로 별도 검토하고 실제 구간과 대조했다. 모델의 가이드 분류는 참고로만 사용했다. 멀티차트의 `NIGHT_DAY` 절차를 비교차트 가이드로 분류한 결과는 제외했고, 같은 비교차트 구간이 있는 부모·연결 문서는 실제 원문 대조로 확인했다. 일부 검토 행이 빠진 첫 보조 실행은 폐기하고 56개 모두 반환된 실행만 보관했다.

## 본문 읽기 실패 원인과 수정

이전에 읽지 못했던 「2022-10-07 한투 버전처리(10-14서버 반영추가)」는 현재 API로 **33.665초·30요청**에 본문 2,485자를 완전히 읽었다. 같은 페이지를 6초 예산으로 읽으면 **6.061초에 `time_limit`**으로 실패했다. 이전 흐름은 여러 부모 문서를 먼저 읽느라 연결 문서에 약 6초만 남았고, 이를 재시도 가능한 원천 장애로 표시해 즉시 다시 실패했다.

다음과 같이 수정했다.

- 현재 속성에서 이미 확인한 링크는 부모 본문 전체를 먼저 수집하지 않고 따라간다. 연결 대상의 현재 접근·DB 소속·조건은 계속 검증한다.
- 설명 경로에서 현재 본문을 완전히 읽어 최종 근거가 확보되면 마무리 예약 시간을 45초에서 15초로 줄여 연결 본문 읽기에 돌려준다. 인용 검증 모델 호출 2회는 유지한다. 후보·미완료·참고 등급만으로 예약을 풀지 않는다.
- 시간·요청 한도 또는 남은 시간보다 긴 `Retry-After`는 `retrieval_budget_exhausted`, `retryable=false`로 구분한다. 이전 본문·발췌·검증 표시는 근거 원장에서 내린다. 다른 근거가 있어도 요청한 본문 읽기가 실패하면 `partial_evidence`로 남긴다.
- 모델이 실패 내용을 생략해도 서버가 최종 답변에 해당 문서명과 본문 조회 미완료 사유를 붙인다. 단순히 선택하지 않은 검색 후보를 읽기 실패로 세지는 않는다.
- 관측된 링크를 읽지 못한 경우 `unavailable_link_count`와 사유를 남긴다. 연결이 없다는 결과로 바꾸지 않는다.
- 진행 기록의 기능별 구간에 실제 설정·변환·저장 절차와 파일/API가 있으면 후보 순위에 반영한다. 다른 기능의 구간 및 예정·요청만 있는 기록은 제외한다.
- `procedure_candidate`와 `unread_procedure_refs`로 아직 읽지 않은 절차 후보를 모델에 전달한다. 해당 이슈의 기능명이 없는 후보는 제외하고, 새 검색보다 현재 본문 확인을 우선하도록 안내한다. 저장본 힌트만으로 근거·가이드로 승격하지 않는다.
- 최종 참고자료에도 문서별 미적용 조건과 ‘대상 이슈의 실제 원인·조치·완료 근거가 아님’을 표시한다.

요청 전체 180초, 모델·도구 각 16회, Notion 목록 유효기간 7,200초는 늘리지 않았다. 모델이 도구 흐름을 선택하고 서버가 접근·조건·근거·완전성·인용을 검증하는 구조를 유지했다.

매회 “그중 두 번째 이슈 번호와 제목만 다시 알려줘.”도 실행했다. 독립 SQL 대조값은 **6건**, 등록일 내림차순 **`[31714, 31659, 29186]`**, 두 번째는 **`#31659 [MTS] 비교차트 내 추가된 종목의 장 중 실시간 업데이트 되지 않는 현상`**이다.

3회 모두 건수·정렬·순번·정확한 제목이 대조값과 일치했다. 현재 본문에 세 설정 파일의 설명이 실제로 있고, `related_guide_verified=true`, `content_complete=true`, `reference` 등급 및 고객사 조건 미적용이 유지됨을 검사했다. 최종 답변에도 미적용 조건이 표시된다. 세 실행 모두 `sufficient_evidence`로 종료했고 도구 오류·시간 한도·호출 한도 중단은 없었다.

실제 429 3건은 동일 요청 재시도로 모두 200을 받았다. 응답 후 다음 시도까지 관측된 대기는 약 1초·2초·10초다. 한투 MTS 장애 해결 가이드 확보 성공률로 해석하지 않고, **같은 기능의 공통 기술 절차 확보 3/3**으로 평가한다.

## 연결 페이지와 서버 가이드

연결 질문은 이전과 동일하다.

> Notion 문서만 이용해서 한투 조건검색 서버 관련 기록과 연결된 페이지의 본문을 읽고, 확인한 내용을 설명해줘.

| 실행 | 답변(초) | 이전 실패 연결 문서 읽기(초) | Notion 요청 / 429 | 전체 결과 |

원래 실패했던 연결 문서의 **현재 본문 2,485자를 3/3회 확인**했다. 검색된 제목만으로 성공 처리하지 않고, 실제 링크의 출발 페이지·읽기 도구·본문 완전성을 대조했다.

두 번째 실행에서는 연결 문서를 읽은 후 추가 후보 「버전처리_한국투자증권(서버)」까지 읽다가 429 대기가 남은 시간을 초과했다. 해당 도구는 `retrieval_budget_exhausted`, `reason=http_429`, `retryable=false`였고 전체 조회는 `partial_evidence`, 종료 사유는 `deadline`이다. **이 실행을 모든 본문 읽기 성공으로 집계하지 않는다.** 180초보다 긴 작업이나 남은 예산보다 긴 원천 대기를 모두 완료하도록 바꾼 것은 아니다.

이 사례에서는 감사 상태와 달리 모델 답변이 실패 문서를 명시하지 않았다. 따라서 최종 표시를 서버가 보장하도록 마지막으로 수정했다. 실제 실패 기록을 재생해 다음 안내가 붙는지 확인했고, 성공 재시도 후에는 안내가 제거되는 회귀도 통과했다.

> 본문 조회 미완료: 버전처리_한국투자증권(서버). 요청 제한 대기를 남은 조회 시간 안에 마치지 못했습니다. 위 답변은 확인한 문서의 범위에 한정됩니다.

별도의 동일 서버 질문 “한투 조건검색 서버 문서에서 서버 접속 방법을 설명해줘.”는 `server-repeat-1`에서 **42.199초**, Notion 요청 14건, 429 0건으로 완료했다. 「한투 인도네시아 서버 조건검색 원격접속방법」의 현재 본문을 읽었다.

처음 6회는 코드와 시작 저장본 지문이 모두 같다. 마지막 수정은 최종 답변에 미완료 안내를 덧붙이는 처리뿐이다. 수정 전후 AST를 대조해 검색·도구 선택 프롬프트·예산·모델 입력이 동일함을 확인했고, 그 코드로 `navigation-disclosure-1`을 추가 실행했다. 모든 실행의 시작 저장본은 동일하며 실행 전후 목록은 `fresh`였다. TTL을 늘려 통과시키지 않았다.
