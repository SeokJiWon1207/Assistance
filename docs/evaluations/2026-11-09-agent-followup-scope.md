# 목록 조건·상세 대상 분리와 순차/병렬 재검증

목록 조건과 상세 대상 분리를 적용한 뒤 동일한 한투·KB·NH 12문항을 순차·병렬 각각 3회, 총 72응답으로 다시 측정했다. 고객사 변경과 순번은 각각 18/18 통과했다. 상태별 집계 2응답과 Notion 직접 근거를 확보하지 못한 복합 18응답은 부분 완료로 남겼다.

## 수정 범위

- 상세 조회의 `queryPlan.list_context`에 원래 목록의 조건·정렬·표시 개수와 감사 ID·변형을 별도로 보존한다. 상세 대상 ID를 목록 필터에 합치지 않는다.
- 모델의 `followup_context=list/current`를 기존 조건 검증기의 상속 기준에 연결한다. 고객사 변경 뒤에도 미해결·기간·팀/전사 범위를 상속하며, 고객사 값의 원문 근거와 조건 해제 검사를 유지한다.
- `위 목록 2번`과 `그중 2번`을 실제 표시 순번으로 해석한다. 상세 턴을 거쳤으면 보존한 목록의 감사 기록을 사용한다. 범위 초과·권한 불일치·차단된 기록은 조회하지 않는다.
- 독립 질문에서는 목록 연결을 끊는다. 원래 목록에 사용자가 지정했던 ID 제한은 보존한다. 과거 결과를 현재 사실 근거로 재사용하지 않는다.
- 전체 건수와 표시 개수를 분리한다. count 계획의 `limit=null`이어도 질문에서 요청한 최근 3건은 목록 도구의 표시 계약에 남는다. 5건을 반환하면 기존 최종 검증이 계속 차단한다.

수정 파일: `backend/intent/conversation_scope.py`, `context.py`, `conversation_contract.py`, `unified.py`, `unified_validation.py`, `backend/services/unified_planning.py`, `backend/services/agent/planning.py`, `backend/tools/query_conditions.py`.

## 확인된 잔여 문제

순차 2·3회차의 한투 상태별 집계는 기간 근거/형식이 잘못된 복합 집계 제안을 보정하면서 `aggregation`을 제거했지만 `group_by=status`를 복원하지 못했다. `operation=aggregate, group_by=null, aggregation=null`이 확정되어 집계 도구 인자와 충돌했고, 전체 5건만 조회한 뒤 “요청한 집계 조회는 완료하지 못했습니다”로 끝났다. 두 상태별 집계 항목은 실패로 유지했다. 미해결·고객사·전체 건수는 보존됐으며, 확인하지 못한 상태별 수치를 생성하지 않았다.

동일한 불완전 계획을 수정 전 `before-code`와 최종 `final-code`의 검증기에 재생했을 때 둘 다 받아들였다. 기존에 허용되던 계획 검증의 허점이며, 실제 이번 반복에서 나타난 실패는 전후 비교 표에서 제외하지 않는다. 후속 보완 대상은 집계 계획의 그룹/지표 완전성 검사와 부분 보정 후 집계 요구 보존이다. 재현 기록은 `aggregate-partial-repro.json`, `aggregate-plan-replay.json`에 남겼다.

Notion 본문 항목이 미완료인 4응답은 모두 NH 복합 질문이었다. 제목이 같은 페이지의 조회는 끝났지만 반환 본문이 비어 있었으므로 본문 읽기 성공으로 평가하지 않았다. 순차 1·2회차는 호출 한도, 병렬 1회차는 마감, 병렬 3회차는 근거 부족으로 끝났다. 해당 이슈 상세의 조건 불일치 재시도도 일부 남아 있어, 본문 탐색과 단계별 상세 조건 보정은 후속 대상이다.
