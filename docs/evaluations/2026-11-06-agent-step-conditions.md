# 단계별 도구 조건 검증과 한투 비교

3단계 구현과 실제 Luna 비교를 완료했다. 모델이 추가 조사 범위를 도구 인자로 정하고, 서버가 질문의 필수 조건·현재 원장의 구조화 필드·실제 집계 그룹 값에 대조한다. 기존 질문 조건·근거·최종 수치 검증은 유지했다.

## 변경 내용

- `purpose=answer`는 질문 전체의 건수·목록·집계를 담당한다. 고객사·미해결·범위·기간·표시 순서를 유지한다.
- `purpose=investigate`는 필수 조건에 근거 있는 필터를 AND로 추가한다. 모델은 조사 정렬과 표시 개수를 선택하고, 성공한 단계의 `condition_ref`로 같은 조건을 재사용한다.
- 추가 값은 질문의 실제 구절, 이번 요청에서 조회한 이슈의 구조화 필드(`M#...`), 실제 반환된 집계 그룹(`Q...`)으로 확인한다. 문서 본문의 지시는 새 조건이나 권한으로 취급하지 않는다. 지정된 순번의 ID는 원래 표시 목록과 대조한다.
- 조건 참조와 저장본 캐시를 원천·필터·정렬·표시 창·집계 기준별로 구분한다. 상세 조회도 현재 단계 조건으로 원천에서 확인한다. Notion의 공통 참고 조건은 본문 읽기·연결 페이지에도 유지한다.
- 추가 조사 수치는 별도 원장에 보관하여 질문 전체의 총건수·목록·집계를 덮어쓰지 못하게 한다. 추가 조사에서 0건이어도 질문 전체의 부재를 주장하지 않는다.
- `agent_step_conditions` 검사를 추가했다. 단계 조건과 참조, 조회 완전성, 일치 ID 수·순서, 집계 합계를 대조하고 불일치 시 전달을 차단한다. 기존 `agent_query_result`, `agent_aggregation_result`, 인용·참고 등급·전송 정책 검사는 유지한다.

주요 구현: `backend/tools/step_conditions.py`, `query_conditions.py`, `registry.py`, `ledger.py`, `mantis_queries.py`, `mantis_tools.py`, `notion_tools.py`, `backend/evaluation/agent_steps.py`, `delivery.py`, `backend/services/agent/orchestrator.py`.

## 비교 조건

- 변경 전은 2단계(앞단 플래너 축소) 완료 코드이며, 변경 후에는 위 10개 하네스 파일만 교체했다. 작업 중 별도로 바뀐 고객사 선택 목록 등의 코드·설정은 비교에 섞지 않았다.
- 동일 Mantis·Notion 저장본을 각각 복제하고 실제 `ChatService` 일반 에이전트 경로를 사용했다. `AGENT_MODE_ENABLED=true`, query-shadow=false. 두 코드의 설정 파일은 동일하다.
- 원천 복제: 2026-11-06 13:06:53 KST. Mantis 갱신 시각 13:06:41 KST. Notion 240 DB의 가장 오래된 목록 갱신은 11:47:48 KST였다. 시작·각 턴·종료 시 모두 7,200초 이내의 정상 목록인지 검사했으며 유효 시간을 늘리지 않았다.
- 원본 Mantis JSON을 독립 SQL로 읽어 정답을 계산했다. 모든 실행의 Mantis 저장본 SHA-256이 같고 실행 중 저장본 및 실행 코드 변경이 없었다.
- 승인된 Luna(`gpt-6-luna`)와 기존 원천·전송 허용 목록·마스킹 정책을 사용했다. Gemini 폴백은 발생하지 않았다. 원천 읽기 및 검색 요청만 허용했다.
- 각 질문을 변경 전·후 3회씩, 총 18회 실행했다. 복합 질문 다음에는 같은 감사 맥락에서 두 번째 항목의 번호·제목을 다시 묻는 후속 질문을 실행했다(6회, 합계 24응답).

질문:

1. 전사 범위에서 한투 미해결 이슈가 몇 건이야? 최근 3건을 보여주고, 두 번째 이슈와 관련된 Notion 가이드도 설명해줘.
2. 전사 한투 미해결 이슈를 상태별로 몇 건인지 알려줘.
3. 2026년 10월 전사 한투 미해결 이슈를 매체별로 집계해줘. 표만 보여줘.
4. 후속: 그중 두 번째 이슈 번호와 제목만 다시 알려줘.

## 결과

| 검증 항목 | 원본 저장본 정답 | 변경 전 | 변경 후 |
|---|---|---:|---:|
| 복합 질문의 전체 건수·조건·순서 | 5건, #31659 → #29186 → #28764 | 3/3 | 3/3 |
| 상태별 집계 | 정보 부족 3건, 할당된 이슈 2건 | 3/3 | 3/3 |
| 10월 매체별 집계 | MTS 1건, #31659 | 3/3 | 3/3 |
| 후속 질문의 두 번째 번호·제목 | #29186 및 원문 제목 | 3/3 | 3/3 |

변경 후 9회 모두 `agent_step_conditions`를 통과했고 모든 응답의 전달이 허용됐다. 미해결·한투·전사 범위와 10월 기간이 유지됐다. 집계 질문의 최종 검증은 pass다. 복합 질문은 기존과 같이 `model_content_review=review` 때문에 전체 상태가 warning이며, 수치·조건·근거 경계 검사에는 실패가 없다.

실제 모델의 단계 선택도 확인했다. 개선 복합 1회차는 전체 건수·목록을 얻은 뒤 `issue_id=29186`, `evidence_ref=M#29186`을 추가하여 상세를 읽었다. 처음에는 answer 참조와 investigate 필터를 함께 보내 거부됐고, 모델이 참조를 제거한 명시적 단계 인자로 고쳐 성공했다. 이 과정에서 고객사와 미해결 조건은 보존됐다. 2회차는 상세 조회 후 Notion을 investigate 용도로 선택했고, 3회차는 목록의 제목으로 Notion을 직접 검색했다. 모델이 모든 질문에 불필요한 추가 조사를 강제받지는 않는다.

상태별·기간별 질문은 모델이 필요한 집계 도구를 바로 호출했다. 집계 결과를 근거로 범위를 좁혀 후속 조회하는 기능은 결정형 회귀 테스트로 별도 확인했다. 이 단순 집계 질문에서 실제 모델이 추가 조사를 했다고 보지는 않는다.

| 질문 | 변경 전 소요 시간(초) | 변경 후 소요 시간(초) |
|---|---|---|
| 복합 | 44.0 / 47.6 / 59.2 | 42.0 / 46.7 / 49.8 |
| 상태별 | 8.8 / 7.3 / 6.9 | 9.8 / 7.2 / 6.7 |
| 10월 매체별 | 6.9 / 7.1 / 7.3 | 8.7 / 12.1 / 7.2 |

Luna HTTP 호출은 후속 질문까지 포함해 양쪽 각각 43회였다. 모두 성공했고 429·모델 장애·시간 또는 호출 한도 종료는 없었다. 개선 3회차의 prepare_query 상태 연산자 오류 1회와 상세 인자 오류 1회는 검증 거부 후 복구됐다. 변경 전에도 상태 연산자 오류가 2회 복구됐다. 3회씩의 측정이므로 속도 개선을 일반화하지 않는다.

## 검증과 남은 범위

- 전체 테스트 3,179건 통과, 커버리지 90%. compile·프런트엔드 빌드 확인·shell·ruff·mypy(293파일) 통과. 새로운 단계별 테스트 18건은 서로 다른 모집단·캐시·정렬·창, 누락 조건, 조작된 근거·참조, 순번, 미완료/0건, 상세 읽기, 집계 후속 조회, Notion 참고 조건, 수치·단계 변조 차단을 포함한다.
- 첫 전체 검사에서 이번 변경으로 추가된 검사 항목과 상세 순서 증명이 없는 테스트 저장본을 발견하여 기대 검사와 저장본 메타데이터를 보완했다. 검증기를 약화하지 않았다. 동시에 바뀌던 작업 범위 밖 고객사 목록 코드의 실패는 해당 파일을 수정하지 않고 후속 전체 검사에서 정상 통과를 확인했다.
- 실제 실행용 코드 복사본과 최종 워크스페이스의 하네스 차이는 `available: set[str]` 로컬 타입 주석 한 곳뿐이다. 해당 파일의 타입 주석을 제거한 AST가 동일함을 검사했고, 나머지 9개 하네스 파일은 바이트가 동일하다. 타입 보완 후 정적 검사를 다시 통과했다.
- **Notion 가이드 관련성은 별도 제한으로 남는다.** 세 번 모두 같은 7695 화면의 저장/불러오기·롤백 관련 문서 본문을 읽었지만, #29186의 화살표 메모 기능을 직접 설명하는 가이드를 찾았다고 보지 않는다. 위 복합 통과 수치는 건수·조건·순서·후속 질문에 대한 것이다. 참고 자료의 상태 조건 미적용과 실제 조치를 증명하지 않는다는 표시는 유지했다.
- 지원 범위는 필수 조건을 유지하는 추가 조사와 기존 Notion 참고 검색이다. 독립적인 여러 모집단을 한 답변에서 비교하거나 조사 중 필수 조건을 해제하는 기능은 포함하지 않는다. 집계의 그룹·지표·기간·비교 명세는 요청에서 검증한 값을 유지한다.
- 운영 서버 재시작·배포·기본 활성화 설정 변경은 하지 않았다.

원시 비교 기록은 로컬 `assistant_web/runtime/agent-step-conditions-20261106/`에 있다. `summary.json`, `final-provenance.json`, `source/freshness.json`, 각 실행의 `result.json`·`tools.json`·`models.json`, `offline-checks.log`·`static-checks.log`로 재확인할 수 있다. 원문을 포함한 런타임 파일은 커밋 대상이 아니다.
