# 운영 Python 3.12 준비 및 배포 대기

후속 완료 기록: [운영 배포 결과](2026-11-02-production-deployment.md). 아래 내용은 AWS 로그인 전 준비 시점의 기록이다.

2026-11-02, 운영 서버 `43.202.45.113`. **신규 릴리스는 아직 배포하지 않았다.**

Python 3.12.16을 `/opt/content-ai-assistant/runtimes/cpython-3.12.16-20261026`에 분리 설치했다. [Astral 공식 배포](https://github.com/astral-sh/python-build-standalone/releases/tag/20261026)의 Linux x86-64 설치 전용 파일을 내려받고 GitHub 릴리스 API에 게시된 SHA256을 로컬과 서버 양쪽에서 대조했다. 기존 시스템 Python 3.14.4, 실행 중인 서비스 및 가상환경은 유지했다.

원본 작업 트리와 새 배포 후보 모두 결정형 테스트 2,796개, 커버리지 90%, 프런트 빌드 일치, Python 컴파일, 셸 문법, ruff 및 mypy 250개 파일 검사를 통과했다. 보안 검사는 네트워크 허용 후 통과했으며 기존 승인 예외 5건은 그대로다. Chroma 예외 4건의 재검토 기한은 11월 12일이다.

`REUSE_REMOTE_SNAPSHOT=1`을 배포 스크립트에 추가했다. 현재 검색 DB가 관리 경로 안에 있는지 검사하고, 활성화 전에 SQLite 무결성과 문서 수·구조화 인덱스·메타데이터 일치를 확인한다. 재사용 중 배포가 실패해도 기존 스냅샷을 삭제하지 않는 회귀 사례를 검증했다. 운영·로컬 검색 스냅샷은 모두 31,029건이다. 운영의 별도 전체 이슈 저장본 31,326건과는 다른 데이터다.

운영 `.env`와 Firebase 서비스 계정은 서버 안의 제한된 백업 디렉터리에 보존했다. 사용자·대화·감사 DB의 일관된 SQLite 백업과 무결성을 확인했으며 스키마 버전은 각각 3/5/3이다. 백업 시점 사용자 15명, 대화 13개, 대화 메시지 72개를 기록했다. 비밀값을 출력하거나 로컬로 반출하지 않았다. 로컬 비밀 아카이브 생성 시도는 자동 승인 검토에서 거절됐고 실행하지 않았다.

배포는 디스크 증설과 AWS 인증에 대기 중이다. 8GB EBS의 최초 여유는 약 589MiB여서 새 가상환경과 DB 검사·롤백용 사본·동기화를 함께 수행할 수 없다. 사용자는 20GB 증설을 승인했다. 배포용 AWS 계정에는 `ec2:DescribeVolumes`, `ec2:ModifyVolume` 권한이 없고 기본 CLI 및 콘솔 로그인도 만료돼, 사용자에게 열린 AWS 탭의 로그인을 요청했다. 인증과 증설이 끝나기 전에는 서비스 전환을 진행하지 않는다.

후속 절차는 20GB 볼륨·파일시스템 확장 확인, 보존 환경을 사용하는 원자 배포, 키·DB 보존 대조, HTTPS 및 보안 설정 확인, 전체 이슈 저장본 갱신, Luna·Gemini와 실제 질문 응답 검증이다. 배포 후 검증은 아직 수행하지 않았다.
