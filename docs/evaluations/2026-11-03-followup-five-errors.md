## 검증 방식과 재현

`assistant_web/scripts/accuracy/verify_followup_questions.py`가 실제 `chat_service.build_response`를 실행한다. 저장본과 개별 이슈 응답을 같은 고정 원본에 연결해 원천 변경을 통제한다. 설정된 회사 모델만 호출하고 외부 모델 fallback 및 다른 HTTP 목적지는 차단한다. 이전 응답의 서버 감사 ID를 다음 요청에 전달한다.

정답 계산은 제품 파서·필터 함수를 호출하지 않고 원본 프로젝트·매체·담당자·상태·날짜·제목 필드를 직접 비교한다. 경계 조합은 실제 원문에 우연히 없는 HTS/WEB, 타 팀 담당자, 해결·종료, 다른 기간까지 포함하므로 숫자가 우연히 같아도 잘못된 조건 해제를 검출한다. 원시 모델 제안과 실행 계획, 답변, 누락·초과 ID를 로컬 결과에 보관한다.

```bash
FOLLOWUP_QA_OUTPUT=followup_five_complete assistant_web/.venv/bin/python assistant_web/scripts/accuracy/verify_followup_questions.py
assistant_web/scripts/check.sh
```

선택 실행은 `FOLLOWUP_QA_CASE_NAMES=base,samsung-count`처럼 부모 시나리오를 함께 지정한다. 실패나 부모 실패로 인한 건너뜀이 있으면 명령은 0이 아닌 종료 코드를 반환한다. 이 결과는 기록한 저장본과 68개 시나리오의 검증 결과이며 운영 데이터의 이후 변경은 별도이다.

원시 결과: `output/followup_five_complete/results.json`. 시안·로컬 산출물은 Git 커밋과 운영 배포 패키지에 포함하지 않는다.
