# 문서 작성 반복 검증 확대

**실제 모델 36개 조합(42개 답변) 중 24개 조합이 기대 동작을 모두 만족했다.**
조회 조건·건수·범위·미완료 표시는 36개 모두 기대와 일치했지만,
사후 분석의 출력 길이 한도와 고객 안내의 보정 실패가 12개 조합에서 재현됐다.
문서 생성 실패를 조회 실패와 합산하거나, 부분 작성에 `complete=true`를 부여하지 않았다.

## 실제 모델 결과

각 셀은 **기대 동작을 모두 만족한 실행 / 2회**다. 부분 조회에서 `complete=false`는 정상이며,
확보한 범위의 요약 누락·미해결 거절·생성 오류가 없어야 성공으로 센다.

| 시나리오 | 인수인계 | 사후 분석 | 고객 안내 |
|---|---:|---:|---:|
| 전체 조회 0건 | 2/2 | 2/2 | 2/2 |
| 미완료 0건 | 2/2 | 2/2 | 2/2 |
| 부분 검색 3건 | 2/2 | 2/2 | 0/2 |
| 본문 미완료 | 2/2 | 0/2 | 0/2 |
| 합성 250건 중 20건 작성 | 2/2 | 0/2 | 2/2 |
| 실제 17건의 후속 질문 | 2/2 | 0/2 | 0/2 |
| 합계 | 12/12 | 6/12 | 6/12 |

- 0건은 전체 조회를 마친 경우에만 확정했다. 미완료 0건과 부분 검색에서는 총건수를 미확정으로 표시했다.
- 대량 결과는 250건 중 20건만 읽었다는 범위를 표시했다. 인수인계·고객 안내는 20건 모두 요약했고,
  사후 분석은 원문 20건을 확보한 뒤 초안 작성이 실패했다.
- 실제 후속은 세 종류 모두 화면번호·기간·팀 조건을 유지하고, 최초·후속 각각 17건 원문을 다시 읽었다.
  인수인계는 두 실행 모두 17건 요약을 완료했다. 사후 분석은 요약 0건, 고객 안내는 후속 요약 16건으로 남았다.
- #31699 본문 미완료 신호는 여섯 실행 모두 보존했다. 인수인계는 17건을 요약해도 전체 문서 완료로 승격하지 않았다.
- 게시된 **465개 문장**의 이슈·항목·문장·문단 ID를 같은 턴의 독립 검토 `supported=true` 기록과 대조했다.
  검토 기록 없는 게시 문장은 0개였다. 이 검사는 검증 절차의 준수 여부이며 모든 의미 판단이 무오류라는 뜻은 아니다.
- 모델은 모두 `gpt-6-luna`였다. 기록된 Mantis GET 324회, OpenAI POST 300회는 모두 HTTP 200이고 429는 없었다.
  도구 수준에서는 시간 초과 2회, 잘못된 인자 1회, 한 턴의 호출 한도 초과 1회가 기록됐다.

## 재현된 문제와 다음 수정 순서

1. **사후 분석 초안의 분할 생성.** 대량 20건, 실제 17건 후속, 본문 미완료의 6개 조합이 모두 실패했다.
   최초 질문까지 포함하면 답변 8개에서 초안과 축약 재시도가 모두 `finish_reason=length`로 끝났다.
   3개 항목을 이슈별 JSON으로 표현할 때 기존 4,096 출력 토큰 안에 들어가지 못했다.
   검색·원문 확보는 완료됐고, 잘린 초안을 채택하지 않아 요약은 0건이었다.
   다음 수정은 이슈를 나눠 작성·검토하고 합치는 방식이 우선이다. 전체 호출·시간 예산과 각 문장의 근거 검증은 유지해야 한다.
2. **고객 안내의 표현 보정과 JSON 형식 복구.** 부분 검색 2회는 #31716의 영문·코드 표현이 거절된 뒤
   보정 JSON의 닫는 괄호가 누락돼 실패했다. 실제 17건 후속과 본문 미완료에서는 내부 코드·허용되지 않은 영문,
   완료 수준·원문과의 의미 차이 때문에 미해결 거절이 남았다. 두 번째 본문 미완료 실행은 17건 모두 요약됐지만
   일부 항목의 거절이 남아 성공으로 세지 않았다. 고객용 허용 표현을 생성·보정에 구체적으로 전달하고
   JSON 형식을 강제·복구하되, 검증 기준과 독립 검토를 낮추지 않는 수정이 필요하다.
3. **미완료 본문의 반복 조사 종료.** 본문 미완료 인수인계 1회는 도구 시간 초과 뒤 이미 읽은 이슈들을 다시 열다가
   모델 16회·도구 15회, `stopReason=call_limit`에 도달했다. 최종 예약분으로 17건 요약과 미완료 표시는 지켰다.
   같은 시나리오의 다음 실행은 모델 9회·도구 6회로 끝났다. 새 근거를 얻을 수 없는 반복 호출을 구분할 필요가 있다.

이번 작업은 검증 확대와 문제 재현·기록까지다. 위 작성 로직의 수정은 적용하지 않았다.

## 범위와 판정

인수인계(`handoff`), 사후 분석(`postmortem`), 고객 안내(`notice`)를 같은 조회·근거 기준으로 검사한다.
문서 작성 로직과 모델·도구 한도, 전송 정책, 문장 검증 기준은 변경하지 않았다.

조회가 부분인 사례는 `complete=false`가 정답이다. 전체 건수, 후보 ID, 본문 확보 ID,
검증된 요약 ID, 본문 미완료와 문장 거절을 각각 확인한다. 조회 범위가 정확해도
초안 생성·보정 오류나 미해결 거절이 남으면 문서 작성 성공으로 세지 않는다.

## 재현 조건

- 기준일: 2026-11-05. 최근 8주는 2026-09-11~2026-11-05, 화면번호 0000, 기존 팀 범위.
- 원본 목록: 이전 평가의 `mantis_complete.sqlite3` 복제본. 저장 시각은
  `2026-11-05T09:13:26.928524+00:00`. 파일 해시가 실행 전후 같은지 검사한다.
- 과거 목록을 재생하기 위해 목록의 신선도 판단 시각만 저장 시각+60초로 고정한다.
  원본 메타·TTL·요청 마감 시계는 변경하지 않는다. 운영 데이터의 현재 최신성을 측정한 결과가 아니다.
- 실제 원문: 이전에 승인한 17건만 Mantis에서 읽는다. 외부 모델 전송은 기존 허용 목록과 마스킹을 적용한다.
  추가 실데이터를 전송하지 않도록 상세 번호와 HTTP 목적지·메서드를 실행 경계에서 검사한다.
- 각 실행에 별도 감사 DB와 런타임 복제본을 사용한다. 후속 질문만 같은 실행의 감사 ID로 연결한다.
- 세 유형 × 여섯 시나리오 × 2회, 총 36개 실제 모델 시나리오를 대상으로 한다.
  후속 시나리오는 최초·후속의 두 질문을 실행하므로 총 42개 답변이다.

| 시나리오 | 원천 | 정답 기준 |
|---|---|---|
| 전체 조회 0건 | 실제 저장본 + 존재하지 않는 제목 문자열 필터 | 총 0건·완전 조회, 문서 사실 생성 없음 |
| 미완료 0건 | 원천 경계에서 결과 없이 중단 주입 | 총건수 미확정, 0건으로 단정하지 않음 |
| 부분 검색 | 실제 목록의 첫 3건만 반환하고 중단 주입 | 3건 원문·요약, 총건수 미확정 |
| 본문 미완료 | 승인된 17건을 읽고 #31699의 본문 완료 표시를 미완료로 주입 | 전체 조회 17건, 본문 미완료와 부분 작성 표시 |
| 대량 결과 | 합성 자료 250건, 도구의 기존 표시 한도 20건 | 총 250건·원문/요약 20건, 전체 문서 완료 금지 |
| 후속 질문 | 승인된 17건의 최초 문서 → 같은 조건의 간결한 문서 | 조건·종류 유지, 원문 17건 재조회, 현재 근거로 재작성 |

질문은 `화면번호 0000 최근 8주 이슈를`에 다음 목적을 붙인다.

- 인수인계: `개발팀 인수인계용으로 증상과 재현 조건을 요약해줘`
- 사후 분석: `사후 분석 문서로 증상과 원인·조치를 요약해줘`
- 고객 안내: `고객 안내문 초안으로 증상과 조치를 정중하게 요약해줘`

0건은 `제목에 "문서검증없는항목20261106"이 포함된` 조건을 추가한다.
후속은 `같은 조건으로` 위 목적을 요청하고 `이슈별로 간결하게 작성해줘`를 덧붙인다.

## 자동 회귀

`assistant_web/tests/test_agent_document_matrix.py`에 6개 테스트 메서드,
72개 하위 시나리오를 추가했다. 모델 응답과 원천을 대체한 결정형 검사다.

- 세 종류의 0건·미완료 0건·부분 검색·본문 미완료·대량 결과를 각 3회 검사한다.
- 실제 `ChatService`와 감사 DB를 통해 조건 상속, 문서 종류 전환, 두 번째 이슈 선택을 확인한다.
  원문을 바꾼 뒤 후속 답변에 새 내용만 반영되는지도 확인한다.
- 직전 완전한 문서가 있어도 현재 조회가 중단되면 과거 사실을 현재 근거로 재사용하지 않는다.
- 근거 없는 수치·완료 표현, 독립 검토 거절, 잘못된 초안/검토 JSON, 두 번 잘린 초안을 차단한다.
- 고객 안내 본문에서 내부 번호·화면 코드·담당자·프로젝트 고객사와 내부 출처 표기가 노출되지 않는지 확인한다.

문서 관련 35개 테스트와 전체 **3,121개 테스트**가 통과했다. 전체 커버리지는 **90%**다.
`assistant_web/scripts/check.sh tests compile shell ruff mypy`를 실행했고 모든 단계가 통과했다.
정적 타입 검사는 286개 소스 파일을 검사했다. 의존성 변경이 없어 이번 작업에서 의존성 감사를 다시 실행하지 않았다.

최종 로그: `/private/tmp/document-matrix-final-check.log`.

## 실행 자료

원문을 포함한 상세 실행 결과는 Git에 포함하지 않는
`assistant_web/runtime/agent-document-fix-20261105/`에 보관한다.

- `run_matrix.py`: 격리 실행·승인 범위 검사·장애 주입.
- `score_matrix.py`, `matrix-summary.json`: 기대 범위와 실제 결과 대조.
- `matrix-review-provenance.json`: 게시 문장과 같은 턴의 독립 검토 통과 기록 대조 결과.
- `matrix-<시나리오>-<종류>-<회차>/result.json`: 답변·계획·도구·HTTP 상태·스냅샷 해시.
- 같은 디렉터리의 `model_responses.json`: 실제 초안·검토·보정 응답.

재실행은 저장소 루트에서 프로젝트 Python으로 수행한다. 기존 결과 이름은 덮어쓸 수 없다.

```bash
assistant_web/.venv/bin/python assistant_web/runtime/agent-document-fix-20261105/run_matrix.py matrix-large-postmortem-3 postmortem large
assistant_web/.venv/bin/python assistant_web/runtime/agent-document-fix-20261105/score_matrix.py
```

실제 모델 실행은 네트워크가 필요하다. 자동 회귀는 기존 `assistant_web/scripts/check.sh`를 사용한다.
