## 변경 내용

- 비교 종료: 모델의 검색 필드 해제와 과업 변경을 구분하고, 검증된 get/explain 작업이 원문의 “유사 사례·비교” 단어로 다시 비교 검색에 진입하지 않도록 했다. 기준 상태만 요청하면 상태 필드와 근거를 2줄로 표시한다.
- 회신: 날짜·To가 있는 실제 발신 노트와 수신·초안·예정을 구분한다. 설명·접수 회신과 수정본 전달·고객 적용은 별도 단계다. 회신 내용 질문에 최초 문의의 가설을 섞지 않고, 별도 안내가 빠지면 같은 출처의 발췌로 보완한다.
- 최신 고객 이력: 노트 기록일과 연락일을 구분하고, 재확인뿐 아니라 최신 고객의 논의·후속 개발 의견도 핵심과 다음 행동에 연결했다. 여러 플랫폼의 추가 증상이 마지막 두 문단 때문에 누락되지 않도록 했다.
- 문서: 기술 조치와 QC·전달을 분리한다. 증상만 반복한 원인 필드는 기술 원인 미확인으로, 미재현 종료 같은 행정 처리는 별도 업무 처리로 표시한다. 요청·예정을 수정 완료로 올리지 않는다. 표시용 최근 노트 제한 전에 전체 원문에서 추출한다.
- 문서 시간: LLM이 질문 전체를 읽고 표현만 변경한다고 판정한 경우 축약 JSON을 반환할 수 있다. 서버는 전체 문장의 제한된 표현 문법과 기존 단일 이슈 계획을 다시 검증한다. 새 번호·조건·기간·다른 문서 종류가 있으면 전체 계획 경로를 사용하며, LLM 호출 자체를 생략하지 않는다. 모델 해석 시도 횟수도 별도로 기록한다.
