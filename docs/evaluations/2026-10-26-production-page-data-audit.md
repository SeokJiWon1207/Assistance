표시된 범위의 계산과 DB 기반 화면은 대부분 일치한다. 그러나 **전체 원천 동기화가 디스크 부족으로 보류되고 있어 최신 전체 데이터와의 일치를 보장할 수 없다.** 실제 미종료 누락 2건과 원문 팝업 오류, 팀 브리핑 시각 표시 오류도 확인했다.

## 방법과 범위

- 사용자가 열어 둔 운영 탭을 읽고, 같은 로그인 세션의 별도 검증 탭에서 각 화면을 열었다. 원래 탭의 화면·필터·입력은 조작하지 않았다.
- 화면의 표시값 → 인증된 실제 API → 읽기 전용 SQL 또는 설정된 Mantis 원천의 GET 응답을 대조했다.
- 독립 계산은 제품의 집계·정규화 함수를 호출하지 않고 원본 JSON의 상태·담당자·등록일·수정일·날짜 사용자 정의 필드·우선순위를 별도로 해석했다. 대표 마감일과 위험 점수는 현재 제품의 정책을 독립 구현했으며 정책 자체의 업무 타당성을 평가한 것은 아니다.
- 전체 Mantis 저장본 31,293건을 서버에서 한 행씩 읽었다. DB 파일과 원문 본문은 반출하지 않았다. 만료된 저장본은 현재의 정답으로 취급하지 않고 과거 범위와 누락 후보를 찾는 데 사용했다.
- 현재 원천 100건 × 10페이지를 별도 조회했다. 중복 ID는 없었고, 그중 설정된 팀 담당자 13명에 해당하는 933건이 대시보드 API의 확인 범위와 일치했다. 범위 밖의 과거 미종료 후보 2건은 원천에서 개별 재조회했다.
- 업무 내용·권한·설정·대화 삭제·답변 생성·검증 실행은 변경하지 않았다. 팀 브리핑 열람에 따른 제품의 정상 읽음 처리는 발생했다. 배포와 공간 정리는 하지 않았다.
- 이번 검사는 운영 데이터 대조다. 코드 변경이나 전체 AI 답변 정확도 검사 실행은 아니다.

## 확인한 문제

### 1. 전체 동기화가 디스크 부족으로 보류됨

- Mantis 전체 저장본 수집 시각: **10/23 12:30 KST**, 전체 동기화 시각: **10/22 14:39 KST**. 유효 시간 1시간이 지나 업무 화면은 최근 페이지의 실시간 부분 조회로 동작한다.
- 디스크 여유: **507,035,648바이트(약 507MB)**.
- 동기화 안전 기준: **718,220,288바이트(약 718MB)**. 부족분은 약 211MB다. 현재 DB 크기의 125%와 128MiB 여유를 요구하는 기존 보호 기준이며 이번 검사에서 완화하지 않았다.
- 10분마다 `Mantis 동기화 보류: free=... required=718220288`가 서비스 로그에 반복된다.
- 따라서 `건 이상`, `비교 미확정`, `판단 보류` 표시는 현재 상태를 올바르게 설명하지만 데이터 누락 자체를 해결하지는 않는다.

| 이슈 | 원천 현재 상태 | 담당자 | 등록일 | 마지막 수정일 | 현재 규칙 점수 |
| --- | --- | --- | --- | --- | --- |
| #29765 | confirmed, 미종료 | 정희진 | 2025-08-01 | 2025-11-17 | 5, 고위험 |

두 건은 운영 API의 미종료 71개 ID에 없고, 별도 Mantis GET에서 현재 미종료로 확인됐다. 확인된 현재 미종료는 **최소 73건**, 같은 점수 규칙의 고위험은 **최소 11건**이다. 최신 전체 이슈를 모두 수집한 것은 아니므로 이 값을 확정 전체 건수라고 부르지 않는다.

### 3. 원문 팝업의 데이터 원천 불일치

`#31631`은 실시간 내 업무와 대시보드 상세 패널에 존재한다. 그러나 ‘저장된 원문 보기’는 **‘문서 조회 오류 / ChromaDB 문서를 찾지 못했습니다’**로 끝난다.

- Mantis 저장본의 #31631: 존재.
- Chroma 저장본의 #31631: 없음.
- Chroma 이슈 ID 메타데이터 31,029행, 최대 이슈 ID 31411.
- 원문 API는 Chroma만 조회하며, 해당 문서가 없을 때 실시간 Mantis로 이어지는 경로가 없다.

이는 숫자 집계 오류와 별개인 실제 원문 접근 실패다. 화면의 ‘저장된’이라는 이름은 원천 차이를 알리지만, 현재 업무에 표시되는 이슈의 원문을 열 수 없는 문제는 남는다.

### 4. 팀 브리핑 생성 시각이 9시간 어긋남

API·DB의 `generatedAt`은 `2026-10-26T00:00:31+00:00`, 즉 **한국 시간 09:00**이다. 화면은 **‘생성 2026-10-26 00:00’**으로 표시한다. ISO 문자열을 자르고 `T`만 공백으로 바꾸어 시간대 변환을 하지 않는 것이 원인이다. 다른 화면의 정상 날짜 변환과도 다르다.

### 5. 알림의 미확인 상태와 빈 결과 표현이 섞임

알림 화면은 ‘완전한 동일 세대의 원본이 없어 배정·노트 변경 수집을 보류했습니다’라고 설명하면서 ‘새 업무 알림이 없습니다’도 출력한다. 개요의 알림 미리보기는 ‘새 업무 알림이 없어요’만 보인다. **확인되지 않음**과 **실제로 없음**을 더 분명하게 구분할 필요가 있다. 실제 누락 알림의 수는 이번 상태에서 확인할 수 없다.

## 오류와 구분한 기준 차이

- 저장된 대화는 10/21 답변을 그대로 보여 준다. KB증권 MTS의 기간 무제한 미종료 답변은 #31608·#31542의 2건이다. 이후 10/22 생성된 #31666이 추가돼 현재 확인 범위에서는 3건이다. 과거 답변이 최신 조회로 자동 갱신되지 않는다는 뜻이며 당시 계산 오류로 단정하지 않는다.
- 8월의 대표 3건 #31423·#31412·#31369는 현재 원천에서도 모두 MTS·closed다. 8월 전체 3건, 해결·종료 제외 0건이라는 현재 열린 대화의 앞선 두 답변은 조건과 일치한다.
- ‘이번 주’ 내 보고는 10/20~10/26 최근 7일이고 팀 브리핑은 10/19~10/25 지난 달력 주간이다. 숫자 차이는 각각의 기간 기준으로 해석해야 한다.
- 관리자 품질 현황의 반복 실패 안내는 별도의 답변 정확도 검사 기록을 기준으로 한다. 그 기록이 없다는 상태와 감사 로그의 실패 8건은 다른 집계이므로 하나의 전체 품질 지표로 합치지 않았다.

## 조치 우선순위

1. 데이터와 기존 백업을 보존하면서 동기화에 필요한 디스크 여유를 확보하고 전체 동기화를 복구한다. 이후 현재 전체 이슈 기준으로 목록·알림·지표를 다시 비교한다.
