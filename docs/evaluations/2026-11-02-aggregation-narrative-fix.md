## 원인과 수정

원인은 두 경로에 있었다.

1. 비교 없는 집계는 고객사별 표를 계산해도 모델에 전체 합계 사실만 전달했다. 실제 서버 재현에서 고객사 행은 2개였지만 모델 입력의 그룹 사실은 0개였고, Luna는 근거가 부족해 `claims=[]`를 반환했다. 이는 경고를 낮출 문제가 아니라 설명에 필요한 계산 근거가 빠진 문제였다.
2. 같은 질문을 모델이 단순 `count`로 해석하면 설명 생성 자체를 거치지 않았다. 첫 수정의 운영 재검증에서 이 경로를 실제로 확인했다. 플래너 프롬프트의 explain 규칙에도 ‘요약’이 빠져 있었다.

비교 없는 집계의 각 표시 행에 값 사실을 추가했다. 입력 상한 64개와 문장별 사실 ID 연결을 유지한다. 기간은 실제 일자·기간·월 형식을 사용하고, 하루는 해당 일자로 표시한다. 한국어 전체 날짜는 같은 ISO 날짜로만 정규화한다. 부분 월의 값 사실에는 실제 조회 구간을 명시해 월 전체 건수로 설명하지 않도록 했다.

기간과 그룹이 확인된 명시적 Mantis 요약 요청이 설명 없는 건수 경로로 빠지면 계획 검증에서 거절하고 모델에 재해석을 요구한다. 집계 계획에서도 명시적 설명 요청이 explain=false로 누락되면 거절한다. 일반 건수·표만·설명 없이 요청과 인용된 제목/본문의 요약 문자열은 기존 경로를 유지한다. 조회 필터·상태·팀 명단·건수 계산은 변경하지 않았다.

숫자·부호·기간·그룹·사실 ID의 결정형 검증과 별도 모델 의미 검토를 유지했다. 잘못된 문장, 검토 거절, 타임아웃에서는 설명을 채택하지 않고 계산 표로 대체한다. 점수나 타임아웃을 완화하지 않았다.
