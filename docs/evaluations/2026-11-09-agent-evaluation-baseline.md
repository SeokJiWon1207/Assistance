# 하네스 평가 기준선 재측정

2026-11-09. 평가기의 확인 질문 오채점을 고치고 요청 항목별 완료·근거 관련성·실제 모델 사용량·지연을 추가했다. 제품 백엔드와 조건·권한·근거·수치 검증은 변경하지 않았다.

같은 한투 복합·후속·집계 질문을 각각 3회, 총 9응답 측정했다. **건수·목록·후속·집계는 모두 맞았지만, 직접 기능 가이드 확보는 0/3이다.** 새 기준으로 복합 3건은 부분 완료, 후속·집계 6건은 완료다. 응답이 전달됐다는 이유만으로 전체 요청을 통과시키지 않는다.

## 수정한 평가 기준

- `agent_plan_clarification`과 `unified_plan_clarification`을 모두 확인 질문으로 집계한다. 최소 재현은 이전 평가에서 delivered 통과·확인 질문 비율 0%, 수정 후 delivered 실패·확인 질문 비율 100%다. 확인 질문을 기대한 문항은 정상 통과한다.
- 정책 거절·취소·근거 없음·빈 답변·미실행을 전달 성공에서 제외한다. 실행하지 못한 후속 질문도 요청 완료율 분모에 남긴다.
- `requirements`로 건수·표시 목록·감사 기록의 후속 순서·본문 읽기·관련성·후속 제목·집계를 나눠 채점한다. 숫자가 맞아도 조건 검사가 실패하면 전체 완료로 세지 않는다. 집계는 전체 조회 완료와 서버 계산, 실제 표의 숫자를 함께 확인한다.
- 현재 본문 읽기와 질문을 직접 뒷받침하는 근거 확보를 분리한다. 제목/검색 점수/제품의 가이드 표시가 아니라 페이지 ID와 도구 반환 본문 해시에 결속한 독립 판정을 사용한다. 판정되지 않은 버전은 미확인이며 완료가 아니다.
- 실제 HTTP 시도를 계측하여 재시도·대체 모델·보고서 내부 호출·최종 검토도 집계한다. 사용량·단가 누락은 0원으로 만들지 않는다. 단가 파일을 받으면 동일 토큰 기록으로 금액을 계산할 수 있다.

설계·문항 형식·운영 기준은 [AGENT_EVALUATION.md](../../assistant_web/docs/AGENT_EVALUATION.md)에 있다.

## 실행 조건과 정답

질문은 기존 회귀와 동일하다.

1. `전사 범위에서 한투 미해결 이슈가 몇 건이야? 최근 3건을 보여주고, 두 번째 이슈와 관련된 Notion 가이드도 설명해줘.`
2. 각 복합 질문의 후속: `그중 두 번째 이슈 번호와 제목만 다시 알려줘.`
3. `전사 한투 미해결 이슈를 상태별로 몇 건인지 알려줘.`

- 실행 시각: **2026-11-09 08:32:13~08:38:10 KST**. 일반 에이전트 경로, Luna, query-shadow 비활성. 제품 변경 전후의 성능 개선 실험이 아니라 같은 제품의 평가 기준선이다.
- 반복마다 독립 프로세스·감사 DB와 같은 초기 저장본을 사용했다. Mantis 저장 시각은 **08:16:40 KST**, Notion 240 DB 중 가장 오래된 목록 갱신은 **07:50:34 KST**다. 요청 전후 목록 나이는 2,499~2,855초였고 기본 TTL **7,200초를 유지**했다. 모든 실행의 신선도·실행 중 코드/설정 및 Mantis 불변 검사가 유효였다.
- backend/config 파일 해시는 세 실행 모두 동일하다. 정렬한 파일 해시 목록의 SHA-256은 `2f48f34a741009481118231355a3f364215be8d75993756739ec83e5191854ac`이다. 초기 저장본·색인·도구 검증 기록의 해시도 모두 동일하다. Mantis SHA-256은 `f3a6b2eecf0043b18fda1d38b8898c30853b7b6c0e2590d812aec164121093b8`이다.
- 제품 조건 해석기와 별개로 SQLite에서 고객사 프로젝트 `117Hantu%`, 미해결 상태 `new/feedback/acknowledged/confirmed/assigned/developed`, 등록일 내림차순·ID 내림차순을 조회했다. 정답은 전체 **5건**, 최근 **#31659 → #29186 → #28764**, 상태별 **정보 부족 3건·할당된 이슈 2건**이다.
- 원문은 기존 승인 범위와 마스킹/모델 정책을 적용했다. 운영 서버 설정·트래픽·재시작·배포는 변경하지 않았다.

평가 파일의 변경 이력도 보존했다. 첫 실행의 정답표에 `정보부족`으로 띄어쓰기를 빠뜨려 집계를 실패로 채점했다. SQL의 `feedback=3`, 다른 그룹 2, 질문·조건·ID·관련성 기준을 유지하면서 라벨만 `정보 부족`으로 정정했다. 최초 문항·원시 응답·최초 실패 보고서를 그대로 남기고, 허용된 라벨 수정만 있었는지 검사한 후 별도 재채점했다.

실행 도중이 아닌 반복 사이에 평가기의 타입 보정과 빈 응답/정책 거절 판정을 수정했다. 실행 래퍼의 `scripts` 패키지가 현재 앱에서 로드되어 실행별 평가 코드 해시는 서로 다르다. **제품 코드·설정·저장본은 동일하며, 최종 통계는 9개 원시 응답 모두를 동일한 최종 평가기로 다시 채점한 값**이다. 실행별 전체 해시와 재채점 평가기 해시를 모두 남겼다. 이를 모든 평가 파일까지 동일했던 실행으로 표시하지 않는다.

**금액은 미산정**이다. 출처 있는 Luna/Gemini 정산 단가가 제공되지 않아 단가 미등록 46회로 기록했다. 토큰 사용량은 모두 확보했지만 0원 또는 추정 가격으로 대체하지 않았다. 가격표가 확보되면 입력 중 캐시 분량을 분리해 재계산할 수 있다. 따라서 운영 비용 기준은 아직 통과로 판정할 수 없다.

## 과거 기록 재채점

11월 6일 최종 복합 3묶음의 6응답도 같은 기준으로 다시 평가했다. 건수·순서·후속·현재 본문은 그대로 통과하지만 직접 가이드가 없어 복합 3건은 부분 완료다. 기존 보고서에도 이 관련성 한계가 기록되어 있었으며, 이번에는 정량 완료율에 반영했다.

과거 실패 실행 `verified-compound-2`, `final-compound-1`도 함께 검사했다. 각 후속의 `agent_no_evidence`를 미완료로 판정해 delivered 성공으로 집계하지 않는다. 과거에는 전체 HTTP 관측이 없었으므로 새로운 비용 수치를 소급 생성하지 않았다.

## 운영 적용 기준과 다음 순서

[운영 기준](../../assistant_web/docs/AGENT_EVALUATION.md)에 기능별 final 100개 이상·고객사 3곳·표현 3종·후속 20대화, 제한 적용 7일·실사용 100요청을 명시했다. 조건/숫자/ID/순서 100%, 완수·직접 관련성 95% 이상, 미완료·예상 밖 확인 질문 5% 이하를 요구한다. p95 목표는 건수/목록/집계 30초, 후속 15초, 복합 120초다. 금액과 사용량을 모두 확인한 뒤 평균·p95 비용이 채택 기준선 대비 120% 이하인지 확인한다.

이번 측정은 **운영 전환 미충족**이다. 개발 문항의 반복 표본이며 직접 근거 0/3, 금액 미산정이고 운영 관찰 기간도 없다. 기능별 적용·복귀 제어 및 온라인 수집은 이후 운영 단계의 구현 범위다. 현재의 평가 관측은 격리된 벤치마크에 적용된다.

다음 작업은 기존 합의대로 **호출별 상태 소유권, 원자적 예산 차감, 취소 이후 결과 반영 차단, 요청 정책/취소 문맥 전달**을 정비하는 단계다. 도구 확장과 제한 병렬화는 그 이후에 진행한다.
