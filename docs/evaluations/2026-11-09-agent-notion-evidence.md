# Notion 직접 근거 미확인의 원인 분리와 순차·병렬 재검증

직전 직접 근거 미확인 18응답을 조회 기록과 원문으로 다시 분류하고 검색·평가를 보완했다. 기존 12개 질문을 순차 1개/병렬 2개, 각각 3회, 총 72응답 실행했다. 이전 미판정 12건은 모두 직접성 부족으로 분류됐고, 본문 미조회 1건·미완료 1건은 별도 원인으로 남겼다. 새 실행은 현재 본문 읽기 18/18, 직접 기능 가이드 확보 0/18이었다. 전체 완료는 순차 26/36, 병렬 27/36이며 순차 고객사 변경 후속에서 표시 개수 오류 1건을 발견했다. 직접 가이드 검색과 운영 확대가 해결됐다는 결론은 내리지 않는다.

## 이전 18응답의 원인

| 분류 | 기존 평가 | 원문 대조 후 |
|---|---:|---:|
| 읽은 문서가 직접 근거 기준에 미달 | 4 | 16 |
| 읽은 본문 버전의 독립 판정 없음 | 12 | 0 |
| 본문 미조회·미완료 | 2 | 2 |

미판정 12건은 원문을 독립 검토한 결과 모두 직접 기능 근거 기준에 미달했다. 미판정을 해소했다고 직접 가이드 확보 성공으로 바꾸지 않았다. 최종 출처 14페이지 중 비어 있지 않고 수집이 완료된 10페이지를 검토했고, 과거 도구 발췌 28개 모두 감사 원문에서 시작 위치·길이·SHA가 일치함을 확인한 경우에만 전체 원문 버전 메타데이터를 복원했다. 답변이나 기록된 구간은 변경하지 않았다. 과거 기록은 최종 직렬화 이전 구간이므로 실제 모델 전달 구간을 소급 증명하지는 못한다. 위 표는 당시 읽은 문서의 직접성에 대한 분류다.

본문 미확보 2건은 순차 2회차 NH의 도구 호출 한도(`body_not_read`)와 순차 3회차 KB의 요청 마감(`body_incomplete`)이다. NH는 상세 조건 오류 2회와 중복 검색이 있었고, KB는 큰 문서를 읽은 뒤 추가 본문에 남은 시간이 부족했다. 두 큰 문서는 현재 API에서도 수집 미완료이며 저장된 실패 사유는 `request_limit,unsupported_block`이다. 60개 원천 요청 제한과 논리 도구 호출 제한을 구분한다.

**검색 누락 확정과 직접 문서 존재 미확정은 다르다.** 현재 확인 범위에서 실제 접근 가능한 직접 가이드가 존재하는데 이 18응답이 놓쳤다고 입증된 사례는 없다. 이는 가이드가 없다는 판정이 아니다. 목록에는 16,841페이지가 있고 이전 색인 기준 4,793페이지가 갱신 필요 상태였다. 일부 본문·첨부·연결의 미수집이 남아 전체 부재를 확정할 수 없다.

## 원문·연결 페이지 확인

- 한투 #29186과 같은 제목의 Notion 페이지는 현재 API에서도 빈 본문이며 연결 페이지가 없다. 같은 [7695] 화면의 저장/불러오기 문서는 `.dat`·`.mct` 분리와 호환 설명으로, 매수/매도 화살표 메모 기능의 직접 사용 가이드는 아니다.
- KB #31666의 실제 단서는 Android 일반설정의 더블클릭 확대/축소와 정밀도 설정이다. 조회된 HTS MACD 파일 로드 사례, MTS 디버깅 환경, 인수인계 프로세스는 이 기능의 직접 근거가 아니다.
- 이전 NH #31684와 같은 제목 페이지는 현재 API에서도 빈 본문이다. 실제 연결 3페이지도 읽었으며 모두 주간 이슈의 공수·목표일 관리 버튼 안내였다. 월주기 최근봉 저가 검증 가이드는 아니다.
- 현재 NH의 새 두 번째 이슈 #31620은 RealOpTuja 프로세스의 반복 기동 문의다. 실행 전에 관련 후보 4페이지를 현재 API로 확인했다. 같은 제목 페이지는 빈 본문이고 나머지는 선물옵션 콘텐츠 정보 부재, 장기 이슈, 인수인계 기록이었다. 프로세스 역할·기동·재기동 직접 가이드는 확인하지 못했다.
- 위 진단은 원천에 대한 읽기 전용 호출이며 별도 모델 호출은 하지 않았다. 다른 Mantis 이슈 원문을 새로 조회하지 않았다.

새 실행에서 읽은 「선옵특화 컨텐츠 정보 부재」 페이지에는 설계서·운영 매뉴얼 첨부파일 이름이 있지만, 본문은 자료 수집·역량 강화 계획이다. 첨부의 실제 내용은 이번 도구가 읽은 Notion 텍스트에 포함되지 않는다. 따라서 해당 페이지의 본문 수집 완료를 첨부까지 읽은 것으로 해석하거나, 첨부에 직접 가이드가 없다고 결론 내리지 않는다.

사후 독립 판정도 사전에 정한 주제를 유지한다. 다른 고객사의 체결 신호·복기차트 문서를 찾았다는 이유만으로 한투 `[7695]` 관련 근거로 넓히지 않는다. 초기에 넓게 판단했던 미래에셋 매매일지 1페이지는 정식 재채점 전에 사전 주제와 대조하여 근거 미달로 정정했고, 변경 이력도 `posthoc-judgments.json`에 보존했다.

## 수정 내용

1. 목록 응답에 선택 순번의 상세 조회 인자를 제공한다. 모델이 상세를 읽어 본문·노트의 설정명·재현 단서로 검색하도록 안내한다. 기존 필터·순번·모집단·비교 범위를 보존하고 실행 시 같은 조건 검증·승인 차단을 다시 거친다.
2. 검색 후보 선정에서 기존 주제어 추출을 재사용하여 ‘화면’, ‘데이터’ 같은 일반 표현만 일치하는 후보의 우선 노출을 줄인다. 명시된 화면번호 검색은 유지하며 고객사나 페이지 ID를 하드코딩하지 않는다.
3. Notion 본문에 `offset`/`next_offset` 이어 읽기를 추가한다. 앞부분이 생략된 경우도 잘림으로 표시한다. 원천 수집 완료와 모델이 전달받은 구간을 구분하고 원천 미완료 사유를 전달한다.
4. 평가 관측에 전체 현재 원문 해시·길이와 실제 발췌 구간의 일치 증명을 추가한다. 전체 원문을 심사한 판정은 필요한 근거 구간까지 실제로 전달했을 때만 통과한다. 같은 버전의 다른 발췌를 무조건 미판정으로 만들던 문제를 고쳤다.
5. 직접성 부족, 독립 판정 없음, 필요한 근거 구간 미열람, 빈/부분/미조회 본문, 최종 출처 제외를 별도 진단 코드로 기록한다. 제품의 관련 가이드 휴리스틱이나 모델의 자체 주장을 독립 직접성 판정으로 쓰지 않는다.
6. 최종 전송문 길이 조절 뒤 구간과 실제 성공한 모델 요청의 도구 메시지를 대조한다. 최종 직렬화에서 잘리거나 제거된 본문을 읽었다고 세지 않으며, 이어 읽기 위치도 실제 전달 끝에 맞춘다.

조건·수치·원장·인용·최종 전송 검증, 마스킹과 외부 모델 허용 목록, 27개 승인 ID 차단은 유지한다. 운영 플래그·서버·트래픽은 변경하지 않았다.

## 비교 조건과 최신성

- 기준선: [집계 기준 보존 비교](2026-11-09-agent-aggregation-repair.md). 동일한 질문 12개, 실행 순서 S1/P1/P2/S2/S3/P3, 동시 도구 수 1/2, 허용 모델·가격표·검증 기준을 유지한다.
- 직전 고정 코드에 이번 변경 11파일만 적용하여 별도 추천 기능 변경을 제외했다. 반복 간 동일한 코드·설정·초기 저장본을 사용한다.
- 운영 NH #31712가 confirmed→closed로 변경됐다. 현재 NH 미해결 건수는 14→13, 최근 3건은 `[31684,31620,31541]`, 두 번째는 #31684→#31620이다.
- 처음에는 이전 모집단을 고정하려 했으나 1시간 최신성 검사에서 모델 실행 전에 중단됐다. TTL이나 갱신 시각을 조작하지 않았다. 최신 저장본을 사용해 정답과 NH 관련성 주제를 모델 호출 전에 사전 등록했다. 승인 목록 27개는 동일하며 실제 조회 모집단은 그 안의 26개다.
- 이 변경 때문에 이전 NH 직접 근거 결과와 새 NH 결과는 같은 기능의 개선으로 해석할 수 없다. 이전 18건 재평가는 당시 질문 대상과 별도 정답 파일로 보존한다.
- 최종 비교의 초기 Mantis 갱신 시각은 2026-11-09 15:07:40 KST, Notion 목록의 가장 오래된 갱신은 13:58:28 KST다. 실제 본문은 요청마다 현재 API에서 검증한다.
- 사전 판정 점수와 새로 발견한 본문의 사후 독립 분류를 구분한다. 새 판정은 원래 manifest·응답·사전 점수를 덮어쓰지 않는다.

새 실행의 직접성 사전 미판정은 순차 3건·병렬 5건이었다. 신규 본문 5개를 고정된 주제로 원문만 독립 검토하여 별도 재채점한 결과, 두 방식 모두 직접성 부족 9건·미판정 0건이다. 원래 사전 점수와 manifest는 그대로 보존했다. 추가 판정으로 관련/직접 근거 성공 수나 전체 완료 수를 늘리지 않았다.

이전 NH와 새 NH는 두 번째 이슈가 다르다. **동일 대상이 유지된 한투·KB 복합 질문만 비교하면**, 본문 읽기는 이전 순차 5/6·병렬 6/6에서 새 실행 양쪽 모두 6/6이다. 관련 참고 근거는 이전/현재 모두 방식별 3/6, 직접 가이드는 0/6이다. 과거 관측은 최종 직렬화 전이므로 과거 실제 모델 전달 바이트까지 소급 증명한 비교는 아니다.

18개 복합 응답 모두 실제 두 번째 이슈 상세를 읽은 뒤 첫 Notion 검색을 실행했다. 다만 이 흐름과 본문 읽기 성공만으로 의미 검색이 해결됐다고 판단하지 않는다. 각 응답에 현재 수집 완료된 본문이 적어도 하나 있었지만, 함께 읽은 큰 페이지에는 부분 수집이 남았다. 실제 모델 전달 증명 45개 중 13개가 부분 수집 본문이며, 전체 45개 발췌의 해시·위치·원문 버전을 감사 원문과 다시 대조했다.

### 새로 확인한 표시 개수 실패

순차 1회차에서 NH 조회 뒤 “고객사만 한투로 바꿔서 전체 건수와 최근 3건을 다시 보여줘”라고 요청했을 때, 계획의 `limit=200`을 보정 기준으로 받아들였다. 건수 5와 고객사·미해결 조건은 맞았지만, 표시 목록과 후속 목록이 `[31659,29186,28764,26654,24182]`가 되어 기대한 최근 3건보다 2건 많았다.

제품의 기존 조건·수치 검사는 이 계획 값을 기준으로 통과했다. 독립 평가의 실제 표시 ID·후속 목록 검사는 실패를 잡았다. 따라서 “최종 자동 검증 통과”를 요청 전체 완료와 동일하게 보고하지 않는다. 이번 Notion 비교의 실행 중 코드·정답은 바꾸지 않았으며, 사용자 표현의 표시 개수를 계획 보정과 최종 목록 대조까지 결속하는 보완이 남는다.

Notion 429는 순차 5회·병렬 2회였고, 병렬 404가 1회 있었다. 모두 최종 응답까지 이어졌지만 순차 2회차 한투/KB 복합 질문은 각각 160.13초/162.00초가 걸렸다. 재시도·대기를 지연 및 원천 요청 수에 포함했다. 순차의 본문 도구 `retrieval_budget_exhausted` 1회도 유지했다. 모든 응답의 종료 표시는 `sufficient_evidence`였으나 직접 가이드 확보를 뜻하지 않으며 독립 평가에서는 미완료로 남았다.

병렬 실행의 평균 비용과 p95 비용은 직전 기준선보다 증가했다. 검색 경로·재시도·캐시 사용과 NH 대상 변경이 함께 있어 병렬화나 코드 변경만의 인과 효과로 단정하지 않는다. 본문 읽기 관측을 보완했지만 직접 근거, 전체 완료, 비용·지연의 전반적 개선은 입증되지 않았다.

최종 모델 호출 368회는 모두 Luna HTTP 200이며 Gemini 대체, 사용량·캐시 쓰기 미보고, 단가 미산정은 0회다. 최종 72응답의 토큰 추정 비용은 **$0.128110550**이다. 예비 36응답 비용 $0.077072295를 포함한 이번 작업의 모델 비용은 **$0.205182845**이며 청구서 실측은 아니다. 읽기 전용 원인 진단 HTTP 195회는 전부 200이고 모델 호출은 없었다.
