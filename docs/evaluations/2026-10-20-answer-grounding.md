# 인증·후속 조건 검증과 직접 답변 개선

## 변경 범위

인증 사용자와 서버 감사 기록에서 확인한 이전 조건을 현재 질문과 구분하여 개별 필터에 결속한다. 최신 질문에 담당자 이름이나 이전 이슈 ID가 반복되지 않았다는 이유만으로 경고하거나 조회를 거절하지 않는다. 검증 플래그만으로 모든 조건을 허용하지 않으며, 새로 끼어든 검색어·다른 담당자·실행 조건의 변경은 계속 검출한다. 클라이언트의 답변 텍스트는 상속 근거로 사용하지 않는다.

모델이 이전 확정 필터를 `equals` 대신 같은 값의 `in`으로 반복해도 같은 조건으로 처리한다. 값이 달라지면 현재 질문의 근거가 필요하다. 명시적인 ‘상태 구분 없이’는 전체 상태로 인정한다. ‘남은 이슈 모두’의 ‘모두’를 전체 상태로 바꾸는 동작은 추가하지 않았다. 원천 조회와 결정형 집계 계산식은 변경하지 않았다.

설명은 질문이 요구한 개발·내부 QC·전달·고객 적용·고객 검증·운영 반영 단계를 구분하고 각 단계의 근거를 붙인다. 요청·계획·실패·정정 기록을 완료로 승격하지 않는다. 제공된 근거에서 확인하지 못한 단계는 그 범위를 명시한다. 질문에 없는 운영 반영 경고를 일괄 덧붙이지 않는다. 기술 질문은 기존 근거 선택 호출에서 질문의 세부 항목과 근거 ID를 연결하고, 서버가 해당 이슈의 원문인지 검증한 뒤 항목별로 표시한다. 별도의 자유 요약 호출은 추가하지 않았다.

- 변경 전 결과 23개는 동일 질문·기준 코드·저장본의 실제 호출 결과를 유지했고, 개발에 사용한 마지막 후속 질문을 새 문항 E23으로 교체하여 추가 호출했다. 변경 후에는 최종 코드로 24개 모두 새로 호출했다. 반복 측정 평균이 아니라 문항당 1회 측정이다.
