# 설명 응답 지연의 원인과 중복 검토 출력 축소

## 원인 확인

이전 정확도 개선 평가의 설명 8개에서 평균 8.706초 중 모델 통신·생성이 8.675초였고, 그 외 처리는 0.031초였다. 전체 지연의 약 99.6%가 모델 호출이었다. 조회/집계 계산이나 원문 인용 검증을 생략하는 방식으로 줄일 병목은 아니었다.

정확도 개선 전후에 모델 출력 토큰 합계는 2,742→4,282로 늘었다. 질문의 세부 항목과 근거 ID를 연결하는 출력이 추가됐고, 독립 검토 단계가 거의 같은 전체 선택 JSON을 다시 생성했다. 검토 호출 평균도 1.80→2.98초로 늘었다. 이전에 조회를 거절하던 후속 질문이 정상 설명으로 진행된 효과도 있어, 전체 증가를 출력 중복 하나만의 영향이라고 해석하지 않는다.

이번 변경 전 코드를 별도로 보존하고 개발 질문 E09/E15/E21을 다시 실행했다. 검토 결과가 첫 선택과 동일해도 기존 방식은 전체 JSON을 반복했다. 출력 축소 후 해당 3개 최종 답변은 변경 전과 문자열까지 동일했고, 검토 단계는 각각 2.64/4.46/3.06초에서 0.46/0.58/0.60초로 줄었다. 이 질문들은 수정 확인에 사용했으므로 새 질문 평가에서는 제외했다.

## 변경과 보호 조건

독립 검토 호출은 계속 수행한다. 검토 모델은 보강된 원문과 연결 후보까지 대조하고, 선택·질문 항목·미확정 판정을 바꿀 필요가 없을 때만 `{"unchanged":true}`를 반환한다. 이 경우 서버가 이미 검증한 첫 선택을 그대로 유지한다. 추가 근거나 판정 변경이 필요하면 기존과 같은 전체 선택 형식을 반환하고 원문·대상 이슈·관계를 다시 검증한다.

인정하는 확인 형식은 정확히 해당 키 하나와 불리언 true뿐이다. false, 숫자 1, 다른 이슈 ID나 선택 필드를 함께 넣은 응답, 잘못된 JSON은 검증을 우회하지 못한다. 기존 제한된 재시도와 실패 처리를 따른다. 필수 질문 항목 검사·원문 보강·출처 검증·전체 이력 보존·QC/전달/고객 검증/운영 반영 구분을 유지했다. 집계·조건 해석·인증·상속 코드와 모델 해석 프롬프트는 이번 최적화에서 변경하지 않았다.

## 평가 방법

- 기준은 직전 정확도 개선을 포함한 작업 트리 사본이다. 이전 main 코드와 비교한 수치가 아니다.
- 동일 Mantis 31,243건 저장본, 수집 시각 2026-10-15T21:07:30.798467+00:00을 사용했다.
- 실제 회사 `company-qwen3.6-35b-a3b`, temperature 0, seed 42로 호출했다. 라이브 데이터 원천 조회는 차단했다.
- 최종 서비스 응답과 감사 저장까지 실행하고, 후속 질문은 실제 부모 감사 ID로 연결했다. HTTP/브라우저/운영 동시 부하는 포함하지 않는다.
- 수정에 사용하지 않은 질문 20개를 SHA-256과 함께 고정했다. 설명 12개는 새 이슈 6건의 단일/후속 질문 쌍이며, 집계 8개는 인증 본인과 명시 등록자 조건의 두 연속 대화다. 이 평가의 질문을 보고 제품 코드를 조정하지 않았다.
- 첫 측정은 변경 전→후 20개씩, 반복 측정은 변경 후→전 순서로 설명 12개씩 실행했다. 설명은 각 버전 24응답(고유 질문 12개), 집계는 각 버전 8응답이다. 모델에 동시에 다른 평가 요청을 보내지 않았다.
- 집계 정답은 제품 파서가 아닌 raw 원천 필드에서 독립 산출했고, 숫자·전체 대상 ID·실행 필터·상태 집합을 확인한다. 설명은 요구 사실과 완료 판정, 원문 인용, 실제 노트 번호를 대조한다. 제품 내부 점수를 정답률로 쓰지 않는다.

## 회귀와 재현 자료

`assistant_web/scripts/check.sh tests compile shell ruff mypy` 통과: 2,016개 테스트, 커버리지 88%, mypy 139개 파일. 새 테스트는 짧은 확인/전체 검토의 최종 답변 동등성, 보강된 나중 노트의 유지, 혼합·숫자·거짓 확인의 거부를 검증한다. 기존 보강 실패·다른 이슈 선택·필수 이력·근거 관련 회귀 검사도 유지한다.

로컬 `assistant_web/runtime/explanation_latency_20261020/`에 변경 전 사본, 질문/정답 manifest와 해시, 모델 단계별 시간·토큰·출력, 원문, 코드 불변 해시, 검사 로그를 보관한다. 회사 원문과 비밀값은 Git에 추가하지 않는다. 이번 작업은 로컬 수정이며 커밋·운영 배포는 수행하지 않았다.

## 집계·조건 해석의 유지와 발견한 기존 한계

새 집계는 전후 모두 7/8이었다. 담당자·등록자·등록 연도·매체·상태를 연속으로 바꾸는 7문항의 숫자와 조건이 유지됐다. N08은 양쪽 모두 ‘서로 다른 상태 계획 충돌’로 조회를 거절했다. 기대 정답은 1건이다. 모델이 ‘같은 등록자와 상태 조건으로 합쳐줘’를 상태별 집계로 해석하고, 상속 상태와 별도 상태 필터를 함께 출력한 기존 오류다. 성공 문항으로 바꾸거나 평가에서 제외하지 않았다. 이번 설명 출력 최적화는 조건 해석을 바꾸지 않았으며 이 오류는 남아 있다.
