# 후속 상태 계획 충돌·답변 표 줄바꿈 수정 검증

2026-10-23. 현재 작업 트리와 로컬 서버 기준. 이번 작업에서 운영 배포·커밋은 하지 않았다.

## 결과

- 요청한 두 문제를 수정했다. 기존 디자인을 기준으로 일반 답변 표의 폭과 줄바꿈만 보완했다.
- 수정 전에 고정한 새 질문 4개와 후속 질문 9개, 총 13개: 수정 전 11/13 → 최종 수정 후 13/13 통과. 자동 검증 배지에만 의존하지 않고 원본 JSON을 직접 집계하고 표시 내용·출처를 대조했다.
- 원래 실패한 `이번 달 등록된 미종료 이슈를 고객사별로 요약해줘` → `그중 미래에셋증권만 건수로 알려줘`: 38건 → 4건 정상 처리. 그 후 MTS 표 요청은 2건(#31668, #31636).
- 전체 회귀 2,362개, 커버리지 89%, compile·shell·ruff·mypy(157개 파일), `git diff --check` 통과.
- 브라우저 별도 탐색에서 발견한 기간 표현 누락 1건은 아래 제한에 명시했다. 따라서 모든 표현의 정확도가 보장된다는 결론은 아니다.

## 원인과 변경

1. 고객사별 집계를 단일 건수로 전환할 때 모델이 `group_by`를 `clear_fields`에 넣어 첫 검증에 실패했다. 재시도에서 이전 미종료 조건을 `open`과 여섯 상태의 `in`으로 동시에 출력해 서로 다른 계획으로 판정했다. 이전 작업이 aggregate이고 새 작업이 count이며 group_by=null인 경우에만 출력 그룹 해제를 정규화한다. 실제 검색 필드는 해제하지 않는다.
2. 명시한 상태 범위와 status 필터의 실제 포함·제외 범위가 같으면 하나로 정리한다. 같은 사용자에게 묶인 이전 확정 범위와도 같고, 현재 질문에 새 상태 요청이 없는 경우에만 상속으로 처리한다. 서로 다른 상태, 알 수 없는 값, 상태 변경·해제 요청은 계속 검증한다. 재시도 안내도 독립 질문과 후속 질문의 상태 규칙을 구분했다.
3. 일반 Markdown 표가 넓은 답변 레이아웃에서 빠져 있었다. 기존 표 레이아웃을 적용하고 번호·고객사·상태·담당자·날짜 등 짧은 열은 한 줄로 유지한다. 제목과 설명은 줄바꿈을 허용한다. 좁은 화면은 표 영역 안에서 가로 스크롤한다.

이번 제품 코드 변경은 `intent/unified_validation.py`, `intent/unified.py`, `static/modules/notion.js`, `static/modules/chat.js`, `static/styles.css` 5개다. 집계 계산·원천 필터 실행·대화 저장 코드는 변경하지 않았다. 기존 사용자 변경은 유지했다.

## 미사용 질문의 최종 답변 비교

같은 31,300건 저장본을 복사해 수정 전·후에 사용했다. 원천 SHA-256은 `789d5444d9b55b2a0c5bff73466854e41bcab52efc2311ceb66e06bad587be81`, 수집 시각은 2026-10-23 15:48 KST다. 전후 파일이 동일한지 확인했다. 질문은 수정 전에 고정했고 해당 결과로 제품 코드를 조정하지 않았다. 최종 안내 문구 점검 뒤 동일 질문으로 한 번 더 확인했다.

원문 오라클은 제품의 집계·필터 함수를 호출하지 않고 원본 payload의 담당자, 프로젝트, 상태, 등록일, 매체구분 필드를 직접 비교했다. 최종 답변의 총건수, 고객사/담당자 그룹별 합계, 표의 ID 전체, 표시한 출처의 제목·상태·고객사·담당자·등록일, 상속 상태·기간·대상 조건을 대조했다. 상태 해제 후 19건 중 5건을 보여준 답변은 실제 총 19건/표시 5건 안내와 최신 5개 ID까지 확인했다.

## 별도로 남은 확인 사항

브라우저 탐색 질문 `이번 달 우리 팀 미종료 이슈를 고객사별 건수로 정리해줘`에서는 ‘이번 달’이 등록 기간으로 반영되지 않아 전체 미종료 78건이 나왔다. 다음 고객사 후속도 이 기간 누락을 상속하여 미래에셋증권 7건을 답했다. 수정 전 소스와 고정 원문으로 같은 최초 질문을 추가 실행해 동일하게 기간 없이 78건을 답하는 것을 확인했다. 따라서 이번 변경으로 발생한 회귀가 아니라 상태 중복 충돌과 별개로 남아 있는 기간 해석 누락이다. ‘등록된’을 명시한 질문은 38건 → 4건으로 정상 처리했다. 이 최초 누락 1건과 그 영향을 받은 후속은 13개 사전 고정 평가에 합산하지 않았으며, 해당 표현까지 정확하다고 주장하지 않는다.
