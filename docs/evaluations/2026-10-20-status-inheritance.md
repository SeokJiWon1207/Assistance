# 등록 기간 해제 후속 질문의 상태 계획 충돌 수정

## 원인과 변경

같은 사용자·질문에 묶인 이전 계획에는 `status not_in [closed]`가 확정돼 있었다. 모델은 ‘등록 기간만 해제하고 같은 등록자와 상태 조건으로 합쳐줘’에 대해 등록 기간 해제와 상태 상속을 지정하면서, 필터에도 이전 `not_in [closed]`를 반복했다. 기존 검증기는 이전 조건을 읽기 전에 반복 필터를 새 상태 계획으로 변환하여 `inherit`와 충돌한다고 거절했다.

이전 계획의 존재와 원천 일치를 검증한 뒤 상태 필터를 정규화하도록 순서를 고쳤다. 모델이 상태 상속을 명시하고, 반복 필터의 실제 상태 범위가 이전 실행 조건과 정확히 같을 때만 중복 필터를 제거한다. 실제 실행에서는 이전의 포함·제외 조건과 표기를 그대로 보존한다. `미종료` 별칭은 실제 6개 상태로 펼쳐 비교하므로 `해결·종료 제외` 및 같은 상태들의 순서 변경도 동등하게 처리한다.

범위를 넓히거나 좁힌 반복 값, 범위가 달라지는 포함/제외 방향 변경, 알 수 없는 상태, 상속과 상태 해제의 동시 지시, 이전 기록 누락, 원천 변경은 계속 거절한다. 현재 질문이 명시적으로 새 상태를 지정한 경우에는 기존 상태 변경 검증 경로를 유지한다. 질문을 다시 규칙으로 해석하거나 추가 모델 호출을 넣지 않았다. 집계 계산·등록자/담당자 의미·설명 렌더링·근거 선택·짧은 독립 검토는 이번 수정에서 바꾸지 않았다.

## 개발 재현과 회귀 검사

원래 실패 문항 N08은 회사 모델 실제 호출로 1건을 답했다. 등록 기간은 제거되고 등록자 우동헌과 종료 제외는 유지됐다. 해당 이슈는 #24662이며 최종 검증 상태는 pass였다. 이 문항과 앞선 연결 문항 N05–N07은 수정 확인용으로 사용하여 새 질문 점수에 넣지 않았다.

테스트는 수정 전 실패를 확인한 뒤 작성한 수정으로 통과시켰다. 등록 기간 해제 시 등록자·상태·원문 근거 유지, 포함 상태의 순서 변경, 미종료의 동등 표현, 모순·미지원 값·잘못된 상속 거부, 명시적 상태 변경과 입력 원본 불변성을 검증한다. `routing_cases.jsonl`에 실제 반복 상태 계획과 이전 확정 계획을 함께 넣었다. 문맥 없는 이전 라우터의 기대값과 감사 기록을 전달한 새 경로의 기대값을 구분한다.

`assistant_web/scripts/check.sh tests compile shell ruff mypy` 통과: 2,021개 테스트, 커버리지 88%, mypy 139개 파일. 모델 해석 프롬프트·집계 계산 코드·설명 속도 개선 코드는 변경하지 않았다.

## 새 질문과 시간 비교 방법

- 기준은 직전 설명 속도 개선을 포함한 변경 전 작업 트리 사본이다.
- Mantis 31,243건의 동일 저장본(2026-10-15T21:07:30.798467+00:00)을 사용한다.
- 회사 `company-qwen3.6-35b-a3b`, temperature 0, seed 42의 실제 호출이다. 라이브 원천 조회는 차단한다.
- 최종 서비스 답변·검증·감사 저장까지 실행하며 후속 질문에는 실제 부모 감사 ID를 전달한다. HTTP/브라우저/운영 동시 부하는 포함하지 않는다.
- 수정에 사용하지 않은 새 질문 20개: 집계 12개(3개 단일과 9개 후속), 설명 8개(4개 단일과 4개 후속). 설명은 전후 순서를 바꿔 두 차례씩 측정하므로 버전별 16응답이다. 고유 질문 8개를 16개 새 질문으로 세지 않는다.
- 질문·정답은 실행 전에 SHA-256으로 고정했다. 집계 정답은 raw 원천의 담당자·등록자·상태·등록일에서 독립 산출하여 전체 대상 ID와 필터도 확인한다. 설명은 요구 사실과 완료 단계, 인용 원문·노트 번호를 대조한다. 제품 내부 검증 점수를 정답률로 사용하지 않는다.
- 개발 문항은 제외하고, 새 질문을 보고 제품 코드를 조정하지 않았다. 저장된 모델 출력의 재생은 실제 모델 정확도/시간과 구분한다.

로컬 `assistant_web/runtime/status_inheritance_20261020/`에 기준 코드 사본·manifest/해시·실제 모델 출력·최종 답변·단계별 시간/토큰·원문 검수·코드 불변 해시·회귀 로그를 보존한다. 실제 회사 원문과 비밀값은 Git에 추가하지 않는다. 이번 작업은 로컬 적용이며 커밋·운영 배포는 수행하지 않았다.
