## 변경 사항

- 유사 비교의 주제는 의미 검색어로 유지하고 명시적인 문자열 포함 조건만 강제 필터로 남긴다. 이전 계획의 과도한 키워드 조건도 후속 질문에서 구분한다. 고객사·매체·담당자·기간·상태·제목·제외 조건과 결정형 집계를 유지한다.
- 개발 서버 적용 시험, 효과 미비, 롤백 결정, 재오픈 예고를 이력으로 보존한다. 저장소 전달과 날짜가 붙은 수정 모듈 전달도 노트 번호와 함께 남긴다. 전달·QC를 운영 적용이나 기술 수정 완료로 바꾸지 않는다.
- CPU 직접 원인과 회선 처리량·다른 지표의 값 오류를 구분한다. ‘추측’도 불확실성으로 처리한다. 제목 단어가 원인 문장 중간에 있다는 이유로 삭제하던 정리도 수정했다.
- 메모리 증상 판단에 구조화된 원인·조치 필드도 사용한다. 일반적인 메모리 제목 때문에 좌표·작도 등 다른 작업이 섞이는 것을 줄였다. QC·전달 뒤 ‘아직도 증가’와 추가 확인 요청도 남긴다. 수정 이전 ‘계속 new 발생’을 수정 이후 미해결 상태로 오인하지 않도록 구분했다.
- 자연 요약의 이슈 귀속, 불확실성, 계획·완료 표현을 검증한다. 필수 롤백·재오픈 이력과 최신 미해결 단서가 빠진 요약은 채택하지 않는다. 검증을 통과하지 못하면 근거 비교표를 표시한다.
- 중복 제목뿐인 기록 등 추가로 분류할 사실이 없는 경우 모델 호출을 줄였다. 요약은 두 문장·출력 예산 360토큰, 생성 6초·검토 3초 제한이며 재시도하지 않는다.
