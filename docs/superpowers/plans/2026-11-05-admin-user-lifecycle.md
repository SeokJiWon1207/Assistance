# 관리자 사용자 삭제와 마지막 로그인 표시

**목표:** 관리자 사용자 목록에서 마지막 로그인 시각을 확인하고 계정과 소유 데이터를 삭제한다.

**구조:** 기존 Firebase 인증, SQLite 사용자·워크스페이스·감사 DB와 관리자 패널을 확장한다. 메인 에이전트가 직접 수행한다.

- [x] 임시 DB 기반 API 회귀 테스트: 관리자/CSRF/본인 삭제 제한, 대상 데이터 삭제와 타 사용자 데이터 보존, 외부 서비스 실패와 재시도.
- [x] 삭제 서비스와 DELETE API: 로컬 접근 차단 후 Firebase 계정 삭제, 소유 데이터를 정리하고 사용자 행을 마지막에 삭제. 로컬 DB 정리는 연결된 DB 트랜잭션으로 처리한다.
- [x] 사용자 소유 대화·메시지·휴지통·알림·브리핑 읽음·작성 플레이북·답변 감사 기록·피드백을 삭제한다. 공용 원천 DB와 팀 브리핑은 유지한다.
- [x] 성공한 로그인만 기존 last_login_at에 기록한다. 실패·일반 API 조회는 갱신하지 않는다.
- [x] 목록 및 상세에 한국 시간 마지막 로그인 표시, 이메일 확인을 포함한 삭제 화면, 중복 전송과 늦은 응답 처리.
- [x] 프런트엔드 동작 테스트와 저장소 check.sh 검증. 실사용 계정을 삭제하지 않고 기능만 구현한다.

**확인할 경계:** Firebase 계정이 이미 없는 경우, 로컬 정리 실패 후 재시도, 로그인 기록이 없는 사용자, 다른 사용자와 동일한 대화 ID, 삭제 중 패널을 닫거나 다른 사용자를 여는 경우.

## 검증 결과

- `assistant_web/scripts/check.sh tests compile shell ruff mypy`: 성공. 3,078개 테스트 통과, 전체 커버리지 90%.
- `assistant_web/scripts/check.sh audit`: 네트워크 재시도 후 성공. 저장소의 기존 예외 정책을 유지했다.
- 신규 백엔드 테스트 11개와 프런트엔드 테스트 5개로 삭제 권한, 데이터 격리, 실패·재시도, 로그인 시각, 중복 요청과 늦은 응답을 검증했다.
- 사용자별 공유/배타 파일 잠금으로 스트리밍을 포함한 진행 중 요청과 삭제의 충돌을 차단한다.
- 브라우저는 로그인 화면까지 확인했다. 실제 사용자 계정 삭제는 수행하지 않았다.
- 독립 커밋 검증: 기존 커밋에 이번 기능의 9개 파일만 적용한 임시 사본에서 `check.sh tests compile shell ruff mypy` 성공. 2,893개 테스트 통과, 커버리지 90%. 보안 검사도 다시 통과했다.
- 휴지통 테이블이 없는 기존 DB에서도 삭제가 성공하도록 처리해 다른 미커밋 기능에 대한 의존성을 제거했다.
