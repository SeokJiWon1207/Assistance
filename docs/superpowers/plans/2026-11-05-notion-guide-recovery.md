# Notion 가이드 탐색과 요청 제한 복구

사용자 승인 범위: 비교차트 가이드 누락·429·호출 상한을 보완하고 동일 한투 복합 질문을 반복 검증한다. 메인 에이전트가 직접 수행한다.

## 확인한 원인

- 의미 검색은 수집된 본문만 대상으로 한다. 제목 후보 5건을 현재 API로 확인했지만 비어 있거나 일정 기록이었다. 가이드 존재를 전제하지 않는다.
- 이슈의 고객사 조건이 모든 문서에 투영된다. 공통 가이드는 자동으로 조건을 해제하지 않고 명시적인 참고자료 검색으로 구분한다.
- 본문 GET과 제목 POST의 429 대기가 분리돼 있다. 프로세스 간 요청 간격도 공유하지 않는다.
- 모델·도구 8회 상한과 쓰지 않는 최종 답변 예약 시간이 복합 질문의 후속 읽기를 제한한다.

## 작업

- [x] 회귀: GET↔POST/다중 프로세스 대기, 시간 예산, 일시 실패 재시도, 조건 보존, 미수집 제목 후보, 탐색 호출 예산.
- [x] 요청 간격·Retry-After 공통화. 일시 실패를 접근 거부와 구별하고 남은 시간 안에서 재시도한다.
- [x] 본문 의미+제목/본문 키워드 후보 결합. 현재 원문 확인, 명시적인 공통 참고 범위, 요청 내 본문 재사용.
- [x] 기본 모델·도구 상한 16회. 결정형 최종 답변의 불필요한 예약 시간을 조사에 환원한다.
- [x] 동일한 최신 저장본으로 복합 질문 3회 이상, 후속 순번 확인, 조건검색 서버 보조 질문을 실제 승인 모델로 검증.
- [x] 관련 회귀·정적 검사·전체 검사, 관측 결과와 미확보 한계를 보고서에 기록.

읽기 권한·DB 범위·인자 검증·전송 정책·근거 등급은 유지한다. 180초 요청 한도 안에서 중단 이유와 조회 완전성을 표시한다. 운영 설정/서버 재시작/커밋은 이 작업에 포함하지 않는다.

## 관측 결과와 미해결 항목

복합 질문 3회는 53.451~76.049초에 종료했고 건수·목록·후속 순번은 모두 정확했다. 최종 실제 실행 6회에 429·호출 한도 중단은 없었다. 서버 접속 가이드 본문 읽기는 2/2회 성공했다.

**비교차트 가이드 확보는 0/3회로 미해결이다.** 페이지 탐색 보조 질문의 연결 후보 1개도 현재 본문을 읽지 못했다. 위 체크는 구현·검증 작업의 수행 여부이며 가이드 확보 목표 달성을 뜻하지 않는다. 상세 결과와 한계는 [검증 보고서](../../evaluations/2026-11-05-notion-guide-recovery.md)에 기록했다.
