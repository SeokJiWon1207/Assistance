# 남은 보고서 도구화 구현 계획

> 메인 에이전트가 직접 구현한다. 사용자가 승인한 1번 범위이며 서브에이전트·커밋·배포는 포함하지 않는다.

**목표:** 고객사 프로필·처리시간·공수/처리시간·유사 사례·초동 대응·특수 업무조회를 일반 에이전트 도구에 연결하고 내부 모델 호출을 공통 예산으로 계측한다.

**구조:** 기존 `build_issue_report`를 확장하고 보고서 종류·날짜 기준·결측·참고 범위 계약을 별도 모듈에 둔다. 계산기에는 검증된 조건을 명시 전달하며 유사 보고서의 사실 선택·초안·독립 검토에는 공통 실행기 콜백을 주입한다. 서버가 만든 보고서 원문과 기존 검증 모드를 유지한다.

**기술:** Python 3.12, 기존 Pydantic·ContextVar·보고서 계산기. 새 의존성 없음.

**기준:** 사용자가 요청한 남은 결정형 기능 도구화, `AGENT_HARNESS.md`, `AGENT_EVALUATION.md` 및 11월 9일 상태 소유권 비교 결과.

## 공통 제약

- 요청 180초·모델/도구 16회·최종 검증 예약·조건/근거/수치/인용/전송 검증을 유지한다.
- 이미 도구화한 공수·주간·월간은 같은 계산기와 계약을 유지한다. 실제 병렬화·공통 보정 확대는 후속 작업이다.
- 모델이 보고서 목적·조건을 명시하며 서버 계산 결과를 최종 응답으로 쓴다. 실패를 자유 생성으로 우회하지 않는다.
- 기준 이슈·참고 사례 범위를 구별한다. 기한은 목표일, 처리시간은 등록→최종수정 근사, 공수는 전달일이며 결측을 0일로 채우지 않는다.
- 허용 모델의 장애 시 대체/재시도도 예산·사용량에 포함한다. 취소·정책 거절·서빙 변경은 내부 보고서가 삼키지 않는다.

## 검토 초점

- 보고서 내부 재해석이 고객사·상태·등록 기간·전사 범위를 바꾸는 경우.
- 전체 0건과 부분 조회, 날짜 결측/역전, 목표일 부재를 같은 결과로 만드는 경우.
- 유사 후보가 기준 ID 조건을 공유하거나 초동 참고가 고객사 원인 근거로 승격되는 경우.
- 내부 모델 호출이 예산·전송 정책·취소를 우회하거나 검토 실패한 초안을 표시하는 경우.
- 보고서가 없는데 일반 검색 결과만으로 요청 완료 처리하는 경우.
