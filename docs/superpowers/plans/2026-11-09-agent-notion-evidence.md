# Notion 근거 누락·평가 미판정 구분과 보완 계획

> 메인 에이전트가 직접 실행한다. 서브에이전트는 사용하지 않는다.

**Goal:** 직전 부분 완료 18응답을 원문·조회 기록으로 분류하고, 검색 단서 손실과 본문 버전/발췌 해시 혼동을 보완한 뒤 동일 질문 72응답을 재측정한다.

**Architecture:** 모델이 상세 조회·검색·본문 탐색을 선택한다. 서버는 실제 표시 순번에 대한 검증 가능한 상세 도구 인자를 제공하고 기존 조건 검사로 다시 검증한다. 평가기는 원문 버전과 실제 전달 구간을 구별하고, 사전 독립 판정의 지원 구간을 읽었을 때만 직접/관련 근거를 인정한다.

**Tech Stack:** Python 3.12, unittest, SQLite 저장본, 기존 읽기 전용 도구·벤치마크.

**Spec:** 사용자 현재 요청과 `docs/evaluations/2026-11-09-agent-aggregation-repair.md`의 부분 완료 18응답.

## 유지할 계약

- 기존 조건·원장·수치·인용·취소 검증, 마스킹과 27개 이슈 승인 범위 차단을 유지한다.
- 같은 12개 질문을 순차1/병렬2 각각 3회 실행한다. Luna 및 장애 시 Gemini의 기존 승인 범위를 유지한다.
- 평가 기준을 완화하지 않는다. 미판정과 무관한 문서를 직접 가이드로 승격하지 않는다. 부분/빈 본문은 전체 읽기 성공으로 바꾸지 않는다.
- 관련 문서를 더 찾지 못해도 전체 수집·접근·검색을 증명하지 못하면 문서 부재로 결론 내리지 않는다.
- 미검증 저장본 문장은 검색 단서로만 쓰고 현재 접근·본문 확인을 거쳐야 근거로 사용한다.
- 운영 설정 변경·배포·커밋 및 무관한 추천 기능 수정은 하지 않는다.

## 작업

- [x] 직전 18응답과 14개 최종 근거 페이지, 검색 후보·빈 본문·연결 페이지를 검사한다. 미판정 12, 본문 미완료 2, 직접성 부족 판정 4를 구분하고 검색 누락은 확인된 직접 문서가 있을 때만 판정한다.
- [x] 본문 발췌 위치 변화, 미열람 근거, 변경된 버전, 빈/부분 본문에 대한 평가 회귀를 RED로 확인한다.
- [x] 관측에 전체 현재 원문 해시·길이와 실제 전달 구간을 추가한다. 사전 판정에 필요한 지원 구간을 결속하고 실패 원인을 구조화한다. 기존 정확 일치 판정은 호환한다.
- [x] 최종 직렬화에서 잘린 구간과 성공한 모델 요청의 실제 도구 메시지를 대조한다. 미전달 본문을 읽기 성공으로 세지 않고 이어 읽기 위치도 실제 끝에 결속한다.
- [x] 모델이 필요한 다음 본문 구간을 읽을 수 있도록 offset/next_offset을 제공하고 잘린 구간의 표기를 수정한다. 인용·현재 접근·원장 검증은 유지한다.
- [x] 표시 순번의 상세 조회 인자를 도구 결과에 제시하고 원문·노트에서 구체적인 검색어를 고르도록 안내한다. 인자를 변조하면 기존 검증이 거절하는 회귀를 추가한다.
- [x] 후보 검색에서 기존 주제어 추출을 재사용해 공통 표현에 의한 후보 승격을 줄인다. 특정 고객사/페이지를 하드코딩하지 않는다.
- [x] 응답을 보지 않고 원문을 심사한 관련성 판정을 동결한다. 이전 응답도 같은 새 판정으로 재채점해 평가 보완과 제품 변경 효과를 나눈다.
- [x] 전체 테스트·정적 검사 후 최신 저장본·정답·승인 ID를 확인하고 코드/설정/가격표를 고정한다. APFS 복제로 디스크 사용을 제한한다.
- [x] 72응답을 재실행하고 검색·본문·평가 상태, 완료율·비용·지연과 잔여 문제를 기록한다.

## 측정 중 확인한 원본 변화

- 최신 운영 저장본에서 NH #31712가 confirmed→closed로 바뀌어 NH 미해결 건수가 14→13, 두 번째 항목이 #31684→#31620으로 바뀌었다.
- 같은 대상을 비교하려던 이전 Mantis 저장본은 1시간 최신성 검사에서 모델 호출 전에 중단됐다. TTL이나 수집 시각을 변경하지 않았다.
- 최신 저장본의 정답과 #31620(RealOpTuja 프로세스) 관련성 주제를 실행 전에 다시 등록했다. 질문 12개·승인 ID 27개는 같다. 실제 미해결 모집단은 승인 범위의 부분집합 26개다.
- 이전 18응답의 원인 재평가는 이전 질문 대상 기준으로 별도 보존한다. 새 NH 결과를 같은 기능의 직접 근거 개선으로 해석하지 않는다.
- 이번 실행에서 새로 읽은 미판정 원문이 나타나면 고정 기준으로 원문만 독립 검토하고, 사전 판정 점수와 사후 분류를 따로 보존한다.

## 완료 결과와 제한

- 이전 18건은 직접성 부족 16건·본문 미완료 2건으로 분류했다. 이전 평가 미판정 12건은 해소했으며 직접 가이드로 승격하지 않았다. 실제 직접 문서를 놓쳤다는 검색 누락도, 문서 부재도 확정하지 않았다.
- 최종 72응답: 현재 본문 18/18, 직접 가이드 0/18, 전체 완료 순차 26/36·병렬 27/36. 기존 검증과 승인 범위 차단을 유지했다.
- 순차 고객사 변경 후속 1건은 최근 3건 대신 5건을 표시해 독립 평가에서 실패했다. 실행 중 코드·정답을 바꾸지 않고 잔여 문제로 보존했다.
- 3,433개 테스트·커버리지 91%, 컴파일·셸 검사, 수정 후 Ruff·mypy 및 대상 회귀가 통과했다. 운영 적용 기준은 미충족이다.
- [최종 보고서](../../evaluations/2026-11-09-agent-notion-evidence.md)에 사전/사후 판정, 예비 실행을 포함한 비용, 429와 지연, NH 대상 변경 및 첨부 미열람 한계를 기록했다.
