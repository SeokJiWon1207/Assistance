# 공통 응답 흐름과 라우팅 정리

사용자가 승인한 하네스 개선 3번을 현재 작업 공간에서 직접 구현한다. 별도 에이전트·배포·설정 변경·커밋은 포함하지 않는다.

## 설계

현재 `_finish`는 보고서, Notion 결과, 비교, 문서, 집계, 목록 중 먼저 맞는 분기로 종료한다. 그 결과 모델이 추가로 읽은 자료와 설명이 사라진다. 결과를 하나의 자유 초안으로 다시 쓰면 숫자 검증을 잃으므로 채택하지 않는다. 각 결과를 기존 렌더러·검증기로 처리하는 응답 부분으로 만들고 공통 조합기에서 합친다. 단일 결과의 기존 모드도 보존한다.

모델은 조건 준비의 `answer_sections`로 `results`와 `explanation`의 표시 순서를, `explanation_sources`로 설명할 원천을 정한다. 이는 출력 목적이며 조회 조건·권한을 바꾸지 않는다. 확보한 필수 계산 결과는 생략할 수 없다. 설명은 기존 원문 인용 검증 또는 Notion 인용 검증을 통과해야 한다. 설명 검증 실패는 수치 결과를 지우지 않고 확인한 범위 안내로 남긴다. 여러 부분을 합친 결과도 부분별 기존 수치·조건 검증과 최종 조합 일치 검사를 모두 통과해야 한다. 사후 접근 철회 시에는 앞서 만든 응답도 함께 보류한다.

라우팅은 지원하는 읽기 작업·보고서 종류를 한곳에서 판단한다. 일반 설명에도 같은 읽기 도구를 제공하고 Mantis 단건 읽기를 지원한다. 도구 사용 가능 여부는 검증된 계획과 사용자 설정으로 정한다. 인증된 순번 복원·출처 접근·쓰기 권한·지원하지 않는 보고서의 기존 경로는 유지한다.

- [x] `services/agent/response_parts.py`와 `evaluation/agent_response.py`를 추가한다. 공통 조합과 부분별 검증, 중복 출처 제거, 표시 순서 보존, 부분 실패 안내를 연결한다.
- [x] `planning.py`의 출력 목적 검증을 추가하고 `orchestrator.py`의 우선순위 종료를 결과 수집·설명·공통 마무리 흐름으로 바꾼다. 기존 전송·예산·문서 검증을 재사용한다.
- [x] `eligibility.py`로 지원 범위를 모으고 일반/비교 경로의 중복 판정과 도구 설정의 질문 정규식을 줄인다. 라우팅 fixture를 추가한다.
- [x] 의미 있는 관련 회귀와 `check.sh tests compile shell ruff mypy`를 실행한다. 최종 자체 리뷰와 문서를 갱신한다.
- [x] 같은 한투 복합·후속·집계 질문을 유효한 동일 저장본에서 변경 전후 비교한다. 보고서+설명과 Notion 속성+본문도 오프라인 실제 엔진으로 확인한다. 실제 실행의 실패·제한을 기록한다.

검증 경계: 전체 조회 0건/미완료, 원문 없는 설명, 참고 자료의 본문 근거 승격, 모델 수치 재작성, 후속 질문 순번 오염을 반드시 검사한다. 추가 원문 범위를 확장하지 않고 승인된 기존 사례·모델만 실제 재검증한다.

- 최종 코드와 동일한 복제본 `after-complete`에서 한투 복합·후속 질문 각 3회, 집계 1회, 기존 Notion 가이드 속성+본문 1회가 결과 기준을 통과했다.
- 실제 후속 조회 실패에서 발견한 불필요한 `query_scope_id=S1` 노출을 요청별 도구 스키마로 보완했다. 비교 범위가 없으면 숨기며, 임의로 보내도 실행 검증은 계속 거부한다.
