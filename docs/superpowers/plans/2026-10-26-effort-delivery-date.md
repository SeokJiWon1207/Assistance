# 고객사 전달일 기준 공수 집계 구현 계획

> 실행: superpowers:executing-plans. 저장소 지침에 따라 메인 에이전트가 직접 수행한다.

**Goal:** 전달일 기준 공수를 검증된 LLM 계획으로 조회하고 코드로 합산한다.
**Architecture:** 전달일과 공수 기입자 필터를 명시하고 공수 계산·검증·표시를 같은 계약으로 연결한다.
**Tech Stack:** 기존 Python 3.12/FastAPI 및 JavaScript.
**Spec:** ../specs/2026-10-26-effort-delivery-date-design.md

## 제약

기존 인증·보안 설정 유지. 관련 변경만 수행. 외부 데이터는 설정된 회사 서비스에만 조회한다.

## 검토 초점

등록일과 전달일이 다른 이슈, 전달일 없는 이슈, 타 담당자 이슈의 본인 공수, 생략형 후속, 불완전 수집을 확인한다.

## 작업

- [x] 전달일·기입자 필터 및 LLM 계획의 실패 회귀 작성 후 실행.
- [x] 필터 계약과 날짜 정규화, 인증·후속 조건, 계획 직접 실행 구현.
- [x] 공수 계산기의 전달일·전체 저장본·조회 완전성 적용 및 기존 회귀 갱신.
- [x] 추이·복합 보고서·원문 검증·화면 날짜 표시 정합성 확인.
- [x] `assistant_web/scripts/check.sh` 전체 검증, 실제 모델·데이터 확인, 변경 자체 리뷰.

## 실행 기록

- 기존 작업 디렉터리는 깨끗한 상태이며 현재 웹앱 체크아웃에서 작업한다. 추가 서브에이전트와 커밋은 생성하지 않는다.

- 검증: 전체 2,454개 테스트 통과. compile·shell·ruff·mypy 통과, 의존성 감사는 기존 승인 예외 5개 외 알려진 취약점 없음.
- 실제 회사 모델·전체 저장본: 2026년 10월 석지원 5건·6.50, 후속 9월 9건·9.45. 두 답변 모두 원문 검증 pass.
- 로컬 웹앱: 통합 LLM 플래너 활성화, /health 200, 전달일 기준 차트 파일 제공 확인.
