# 채팅 FIFO 대기열 구현 계획

**목표:** 동시 처리 한도를 넘긴 질문을 접수 순서대로 기다렸다가 실행하고, 대기 순서·취소를 지원한다.

**구조:** admission 컨트롤러가 작은 대기 티켓과 FIFO를 소유한다. API는 비동기로 대기하며 SSE 상태를 전송한다. 실행 예산과 작업 스레드는 슬롯을 얻은 뒤 생성한다. 동기 서비스 호출도 같은 대기열을 사용한다.

**제약:** 기존 동시 처리·메모리 기준·분당 제한 유지. 기본 대기열 32건, 사용자별 4건, 대기 120초. 대기는 실행 시간 제한과 구분한다. 진행 중인 작업은 실제 워커 종료까지 슬롯을 소유한다. 기존 작업 공간에서 직접 구현하고 사용자 변경을 보존한다. 사용자 지침에 따라 서브에이전트는 사용하지 않는다.

- [x] 컨트롤러: FIFO·끼어들기 방지·메모리 회복·취소·만료·대기열 상한의 실패 테스트를 먼저 작성하고 `enqueue`/`try_start`/`cancel`과 동기 대기를 구현한다.
- [x] API: 대기 SSE·취소·연결 종료·실행 예산 분리·비스트리밍 순차 완료 테스트를 먼저 작성한다. 기존 `chat_events`의 워커/lease 수명은 유지하고 앞에 비동기 대기를 연결한다. 스트림 미소비 종료도 background cleanup으로 처리한다.
- [x] 서비스·설정: 직접 서비스 호출을 동일 대기 방식으로 연결하고 환경변수 예시를 추가한다. 전체 검사 후 현재 운영 원본을 대조해 이번 변경만 배포한다. 4개 동시 요청의 순차 완료, 취소 후 진행, 메모리·재시작 여부를 검증한다.

**결과:** 전체 2,493개 테스트·빌드·정적 검사·의존성 검사 통과. `20261027T041234Z` 배포 후 운영 4탭 대기·자동 완료·대기 취소, 가상 사용자 4명 3분 반복 20건 전부 완료·429 0건을 확인했다. 상세 증거는 `docs/evaluations/2026-10-27-memory-stability.md`의 대기열 절에 기록했다.

**검토 초점:** 대기 중 모델 선실행 금지, 대기 중 연결 종료의 티켓 제거, 슬롯 부여 직후 취소 누수, HTTP 응답 전에 분당 제한 반환, 기존 워커가 끝나기 전 다음 작업 시작 금지. 각 항목은 컨트롤러·API 회귀로 검증한다.
