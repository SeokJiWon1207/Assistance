# 여러 조회 범위 비교 구현 계획

> 실행: 사용자가 승인한 1번 작업을 메인 에이전트가 직접 수행한다. AGENTS.md에 따라 위임하지 않는다.

**목표:** 한 질문에서 고객사 또는 등록 기간이 다른 Mantis 범위를 각각 검증·조회하고, 서버가 차이·합계·중복 제외 건수를 계산한다.

**구조:** `prepare_query`의 기존 제안에 `comparison={axis, cohorts}`를 추가한다. 공통 조건은 기존 제안으로, 변경 축(customer 또는 created_at)의 값과 실제 원문 근거는 2~4개 cohort로 지정한다. 서버가 S1~S4 조건 계약을 만들고 모델이 기존 조회 도구의 `query_scope_id` 또는 검증된 참조를 선택한다. 결과는 범위별 원장에 분리하고 최종 비교는 서버가 계산·대조한다.

**런타임:** Python 3.12, 기존 pydantic·SQLite·검증 엔진. 의존성 추가 없음.

## 제약과 검증 기준

- 상태·담당자·팀·화면·키워드 등 공통 조건은 모든 범위에 동일하게 유지한다. 비교 축만 바꾸며, 각 값과 기간을 실제 질문·기존 달력 검증기로 확인한다.
- 여러 고객사 비교는 명시된 고객사 집합과 일치해야 한다. 기간 비교는 각 원문 구절과 실제 날짜를 대조한다. 질문을 모델이 임의로 다시 써서 조건을 지우지 않는다.
- count/list 및 기존 건수 집계 지원. 기간 비교의 날짜 기준은 등록일이다. 공수 비교·원천 간 수치 합산·서로 다른 상태/권한 범위 비교는 이번 범위에서 실행하지 않는다.
- 하나라도 미조회·미완료면 해당 범위는 미확정으로 표시하고 전체 차이·합계는 확정하지 않는다. 완전한 0건과 구분한다.
- 전체 스캔의 일치 ID로 단순 합계·합집합 건수·중복을 계산한다. 목록에 표시한 몇 줄로 계산하지 않는다. 각 쌍의 차이는 왼쪽 범위 − 오른쪽 범위로 명시한다.
- 기존 단일 조건·단계 조건·숫자·인용·전송 정책 검증은 유지한다. 다중 조회의 검증 불일치는 전달 차단 검사에 추가한다.
- 서로 다른 비교 목록을 하나의 순번으로 복원하지 않는다. 선택 범위가 불분명한 후속 질문은 조회 전에 확인한다.
- 사용자 변경 파일을 보존하고 운영 배포·서버 재시작은 하지 않는다. 실제 반복 검증은 승인된 Luna와 별도 복제 저장본을 사용한다.

## 작업 순서

- [x] 조건 제안·근거 검증: `intent/query_comparison.py`, `intent/comparison_contract.py`, `services/agent/planning.py`. 고객사·기간 분리, 누락·중복·조작·잘못된 날짜·공통 조건 손실 회귀부터 실패를 확인한다.
- [x] 범위 선택·원장 연결: `tools/query_conditions.py`, `step_conditions.py`, `registry.py`, `ledger.py`. 조건 참조가 다른 범위로 옮겨가지 않고 캐시·부분 결과가 섞이지 않는 테스트를 추가한다.
- [x] 비교 계산·응답 검증: `services/agent/query_comparison.py`, `evaluation/agent_comparison.py`, `orchestrator.py`, `verification.py`, `delivery.py`. 겹치는 ID, 0건, 부분 조회, 한쪽 누락, 숫자·순서·범위 변조, 기존 질문 회귀를 검증한다.
- [x] 라우팅·프롬프트·후속 경계: `eligibility.py`, `unified_planning.py`, `fixtures/routing_cases.jsonl`, 문서. 모델이 비교 범위를 정하고 도구 호출 순서를 선택하도록 연결한다.
- [x] 전체 tests·compile·shell·ruff·mypy, 직접 코드 리뷰.
- [x] 같은 저장본의 이전/개선 코드로 고객사 비교·기간 비교를 각 3회, 기존 한투 복합·집계 회귀를 실행한다. 독립 SQL 정답·조건 유지·전달 검사·시간/호출 비용을 기록한다.

예산·보안·조회 완전성을 완화하지 않는다. 질문별 도구 순서는 고정하지 않으며 결과 중심으로 평가한다.

## 완료 근거

- 실제 최종 코드의 고객사·기간·상태별 비교 각 3회와 기존 한투 복합·집계·후속 회귀 통과. 변경 전과 같은 최신 복제 저장본·독립 SQL 정답을 사용했다.
- 전체 테스트 3,200건·커버리지 91%, compile·shell·ruff·mypy 297파일 통과.
- 기간 비교의 집계 형식 혼동과 일반 질문의 comparison=null 회귀를 실제 반복에서 발견해 별도 실패 테스트로 보완했다.
