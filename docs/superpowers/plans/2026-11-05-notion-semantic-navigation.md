# Notion 본문 의미 검색과 페이지 탐색

사용자가 승인한 다음 단계: 기존 로컬 임베딩으로 Notion 본문을 검색하고, 확인된 페이지에서 하위 페이지·링크·DB 관계를 따라 읽는다. 같은 한투 복합 질문을 다시 실행해 실제 가이드 본문 확보 여부를 검증한다. 기존 조건 계약·권한·근거 원장·부분 조회 표시를 유지한다.

## 설계

별도 SQLite 벡터 색인에 페이지별 본문 구간을 저장한다. 연결 지문·임베딩 모델·내용 해시로 분리하고 바뀐 구간만 다시 임베딩한다. 현재 설치된 loopback Ollama `bge-m3:latest`를 사용하며 외부 임베딩 전송이나 신규 모델 다운로드는 하지 않는다. 저장된 전체·부분 본문은 후보 발견 용도이고 결과 근거는 매번 현재 API로 검증한다. 의미 검색은 top-k이므로 빈 결과도 전체 부재로 판정하지 않는다.

`search_notion_body` 도구를 추가해 기존 조건 인자 계약을 적용한다. 현재 읽기 범위·소속·수정 시각·조건을 확인한 페이지의 실제 소유 블록만 근거 원장에 등록한다. 임베딩 장애/색인 미준비는 명시적인 부분 상태로 돌려주고 기존 제목 검색 도구를 계속 사용할 수 있다.

본문 수집기가 하위 페이지, page mention, Notion URL, link_to_page, 관계형 속성의 목적지를 구조화된 탐색 힌트로 제공한다. `list_notion_page_links(page_ref)`는 현재 요청 원장의 페이지에서만 출발하고, 목적지의 현재 소속·조건을 다시 확인한 뒤 새 ref를 발급한다. 임의 URL·ID나 외부 호스트는 열지 않는다. 자식/관계 문서의 본문을 부모 근거로 합치지 않는다. 루프·요청 수·시간·깊이 한도를 유지한다.

관련 가이드의 현재 본문에 확인 가능한 절차가 있어야 가이드로 표시한다. 의미 점수나 제목만으로 읽었다고 판정하지 않는다. 사실상 가이드가 없거나 API가 본문을 제공하지 않으면 이슈 조회 성공과 가이드 미확보를 구분해 보고한다. 이번 단계에서 기존 조건 범위를 자동으로 넓히지 않는다.

## 작업

- [x] 의미 색인·검색 실패 테스트: 표현이 다른 본문 발견, 증분 재사용, 모델/연결 분리, 삭제·변경·접근 거부, 미완료 0건, 유효하지 않은 벡터.
- [x] 로컬 본문 청킹·벡터 저장/검색 및 제한된 증분 갱신 CLI와 주기 갱신 연결.
- [x] 현재 본문 수집의 링크 힌트와 페이지 탐색 도구. 소속·관계·자식 근거 분리, 순환/범위 밖/외부 URL/폐기된 페이지 회귀.
- [x] 에이전트 도구·프롬프트·가이드 읽기 연결. 조건 검증·원장·본문 완전성·후속 이슈 순서 유지.
- [x] 동일한 신선한 저장본에서 한투 복합 질문을 반복하고 도구 선택·관련 경로·본문 발췌를 기록. 한투 조건검색 서버 문서를 보조 실측으로 확인.
- [x] 전체 검사 실행·작성자 리뷰·문서/리포트. 기존 사용자 변경을 보존하고 배포/서버 재시작/커밋은 하지 않는다.

## 검토 초점

벡터는 현재 사실이 아닌 후보이고 저장본이 바뀌면 현재 조회를 우회하지 않아야 한다. 부모/다른 고객사/범위 밖 페이지의 내용을 잘못 인용하지 않아야 한다. 링크 힌트는 읽기 권한이 아니다. 부분 본문·미구축 색인·외부 API 제한은 전체 부재가 아니며, 임베딩과 최종 원문 전송은 기존 허용 범위 안에 있어야 한다. 서브에이전트 없이 메인 에이전트가 수행한다.

## 실행 결과

[검증 리포트](../../evaluations/2026-11-05-notion-semantic-navigation.md)에 성공과 미확보를 분리했다. 복합 질문 3회 모두 건수·목록·후속 순번은 일치했고 관련 비교차트 가이드는 미확보였다. 조건검색 서버의 실제 접속 가이드 본문은 2/2회 읽었다. 별도 연결 탐색 질문은 제목 검색 뒤 429와 시간 제한으로 미완료였다.

관련 회귀 224개와 compile/shell/ruff/mypy/audit는 통과했다. 마지막 전체 테스트 3,047개 중 작업 중 별도로 변경된 개인 작업공간 UI 검사 1건은 실패했으며, 해당 변경은 이 작업에서 수정하지 않았다. 전체 검사 통과나 비교차트 가이드 탐색 해결을 주장하지 않는다.

검증에서 확인한 불필요한 조기 종료도 보완했다. 건수·목록 원장으로 서버가 최종 답변을 만드는 경우만 모델 합성용 예약 호출을 해제하며, 전체 모델/도구/시간 한도는 유지한다.
