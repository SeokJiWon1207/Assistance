# 하네스 평가 기준선 구현 계획

사용자가 승인한 평가 기준선 작업을 메인 에이전트가 직접 구현한다. 기존 조건·근거·수치 검증과 제품 응답 경로는 변경하지 않는다. 서브에이전트·운영 배포·커밋은 범위에 포함하지 않는다.

## 설계와 범위

- `benchmark.py`의 확인 질문 오채점을 회귀로 고친다. 확인 질문·차단·취소·오류·미완료를 전달 성공과 구분하고, 요청 항목별 평가를 기존 기대값 검사와 함께 제공한다.
- `benchmark_outcomes.py`는 실제 표시 ID/후속 ID, 현재 본문 읽기 증명, 사전에 고정한 근거 관련성 판정을 평가한다. 본문 읽기 성공을 직접 답변 근거 확보로 승격하지 않는다. 판정 자료가 없으면 미확인으로 남긴다.
- `benchmark_observation.py`는 평가 실행 동안 모델의 실제 HTTP 시도·사용량·원천 HTTP 요청을 기록한다. 재시도·대체 모델·최종 검토도 포함한다. 원문·키·전체 URL은 기록하지 않는다. 단가·사용량이 없으면 금액은 미산정이다.
- 평가 문항은 같은 한투 복합·후속·집계를 각각 3회 실행한다. 고정한 최신 복제 저장본의 독립 SQL 정답을 사용한다. 이번 문항은 이미 개발에 사용한 `dev`이며 운영 전환 근거로 과대해석하지 않는다.
- 코드·설정·저장본·평가 명세를 해시로 고정한다. Notion TTL을 늘리지 않으며 측정 전후 최신성을 검사한다. 현재 원문 읽기의 수정 시각·증명도 기록한다.
- 운영 기준은 문서로 수치화한다. 정확성·보안 검증은 완화하지 않으며 기능별 최소 표본·관찰 기간·완료율·관련성·p95·비용·미보고 사용량과 복귀 조건을 명시한다.

## 실행 순서

- [x] 확인 질문 오채점, 목록/후속 순번 불일치, 본문 성공/관련성 분리, 항목별 실패·누락, 비용 미산정·재시도 집계의 실패 테스트를 작성한다.
- [x] 평가 모듈과 기존 benchmark 실행·채점·Markdown 보고서를 연결한다. 오류·누락 표본을 분모에서 제외하지 않는다.
- [x] 코드·설정·데이터 해시와 최신성 검사, 실행별 관측을 연결한다. 실제 금액에는 출처와 버전이 있는 단가만 사용한다.
- [x] 기존 사례 재채점과 동일 한투 질문 3회씩 실제 측정을 수행한다. 결과 정확성·요청 완수·본문 읽기·관련성·시간·토큰·비용을 분리해 보고한다.
- [x] `check.sh tests compile shell ruff mypy`와 자체 리뷰를 완료하고 운영 적용 기준·기준선 리포트를 작성한다.

검토 경계: 정상 확인 질문도 결과 완료로 세지 않기, 자료 부재/미확인과 검색 부재 구분, 참고 문서를 직접 가이드로 오인하지 않기, 표시 출처와 실제 번호 목록 구분, 실패·미보고 사용량을 비용 0으로 처리하지 않기, 후속 질문 미실행도 분모에 포함하기.

완료 기록: 제품 코드·초기 저장본이 동일한 9응답, 항목 21/24·전체 완료 6/9, 직접 가이드 0/3. 모델 46호출의 토큰은 모두 보고됐으나 정산 단가가 없어 금액은 미산정이다. 첫 정답표의 상태 라벨 띄어쓰기 정정과 반복 사이 평가기 수정은 원시 기록을 보존한 별도 재채점 이력에 남겼다. 전체 3,250테스트와 정적 검사 통과. 상세는 `docs/evaluations/2026-11-09-agent-evaluation-baseline.md`에 정리했다.
