# 독립 도구 최대 2개 병렬 실행

목표: 모델이 한 턴에서 제안한 읽기 도구 중 서버가 독립성을 확인한 인접 호출만 최대 2개 실행한다. 조건·근거·수치·전송 정책과 최종 검증 예약은 유지한다.

1. 호출 시작 시 작업 사본과 기준 상태를 고정한다. 작업자는 확정 원장을 직접 쓰지 않는다. 조정자가 원래 호출 순서대로 변경분을 병합하고 단계 인덱스를 재계산한다. 충돌·취소·외부 상태 변경은 결과 반영을 차단한다.
2. 저장본 건수·목록·집계, 이미 확인한 서로 다른 이슈 상세를 우선 허용한다. 새로운 참조, 모집단 API 조회, 계획 변경, 내부 모델 호출이 있는 보고서는 순차 처리한다. Notion 호출끼리는 참조 번호·본문 무효화·대체 가이드 탐색의 공유 상태 때문에 순차 처리한다. 순번 의존이 없는 Notion과 Mantis 독립 조회만 함께 실행한다.
3. 공통 요청 문맥을 작업자에 전달하고 원자적 예산 차감·공통 마감·협력 취소·연결별 429 대기를 재사용한다. 모든 결과는 모델 요청 순서대로 돌려준다. 병렬 묶음·실제 실행 시간·논리 호출·원천 HTTP 요청을 각각 기록한다.
4. `AGENT_MAX_CONCURRENT_TOOLS=1`을 기본값으로 두고 2에서만 활성화한다. 2를 넘지 않는다. 독립성 판정과 병합의 실패·취소·역순 완료·조건 혼합 방지 회귀를 먼저 작성하고 구현한다.
5. 전체 결정형 검사 후 동일 코드·설정·저장본에서 순차 1/병렬 2를 교차 실행한다. 기존 한투 복합·후속·집계 질문을 각 3회 측정한다. 정답·완료·관련성·비용·지연과 실제 병렬 실행 여부를 보고한다. 서버 재시작과 운영 활성화는 이 작업 범위에 포함하지 않는다.
