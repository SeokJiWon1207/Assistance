# UI 후속 기능과 실제 검증 실행 계획

사용자의 “순서대로해줘” 요청에 따라 메인 에이전트가 직접 수행한다. 기존 미커밋 변경은 유지하며, 시작 시점 파일 사본은 `assistant_web/runtime/ui_followthrough_20261023/baseline`에 보관한다.

**목표:** PDF UI 적용 후 남은 답변 정확성, 계정 검증, B 문맥, 알림, 실제 진행 정보, 전체 검증을 순서대로 처리한다.
**구조:** 기존 FastAPI·SQLite·브라우저 JS와 인증 계약을 확장한다. 거짓 진행률이나 시계열은 생성하지 않는다. 권한 정책은 유지한다.

1. [x] #31631 차단: 실제 원인은 상태 뒤의 출처 표기를 상태값으로 함께 비교한 검증 오류였다. 올바른 `confirmed`를 유지하고 같은 이슈의 정해진 인용 형식만 분리했다. 현재 상태는 원본 필드로 표시하며 잘못된 상태는 계속 차단한다. 실제 회사 모델 재검증에서 전달 허용을 확인했다.
2. [x] 가능한 계정 검증: 실제 세션·CSRF·사용자 저장소·역할 검사를 격리 DB로 검증하고 브라우저에서 로그인·로그아웃·재로그인을 실행했다. 외부 Firebase 토큰 교환만 대체했다. 운영 사용자 권한은 바꾸지 않았다.
   - [ ] 실제 Firebase 신규 로그인과 실기기 한글 IME·소프트 키보드 확인은 테스트 계정/실기기가 없어 남아 있다.
3. [x] B 후속 질문: 사용자·질문에 묶인 서버 감사 기록의 B 본문·출처를 복원한다. 선택 저장/복원, 중지 후 재질문, 잘못된 ID·다른 사용자·차단 답변·크기 제한을 검증했다. 실제 회사 모델에서 B의 첫 번째 이슈 참조도 통과했다.
4. [x] 알림: 완전한 동일 세대 원본 사이의 새 배정·노트 식별자를 사용자별로 저장한다. 최초 관찰, 중복, 부분·오래된 조회, 계정/연결 변경, 배정 해제, 읽음 상태를 검증했다. 업무 조회·새로고침 시 수집하며 실시간 푸시가 아니다.
5. [x] 진행·차트: 실제 수신 단계와 확보한 답변 근거 건수를 연결했다. 분모 없는 백분율과 과거 상태를 추정한 차트는 추가하지 않았다. 기존 실제 집계 차트는 유지했다.
6. [x] 검증·정리: `check.sh` 전체 통과(2,395개, 커버리지 89%), Chrome의 데스크톱·태블릿·모바일 검증, 변경분 자체 검토, 이번 작업만의 패치/파일 해시 작성. 모바일 포커스 이동 시 전송 버튼이 60px 움직이던 문제도 수정·재검증했다. 커밋·운영 배포는 실행하지 않았다.

회귀 중점: 실제 상태와 업무 완료 의미 혼동, B 근거의 소유권/변조, 최초 알림 폭주, 부분 조회에 따른 거짓 변경, 중지·로그아웃 이후 남는 요청 상태.

결과: `docs/evaluations/2026-10-24-ui-followthrough.md`.
