# 대화 맥락 전달 구현 계획

> 이 세션의 메인 에이전트가 `superpowers:executing-plans` 절차로 직접 구현한다. 사용자 지침에 따라 위임하지 않는다.

**Goal:** 모델에 이전 질문·적용 조건·표시 순서·근거 요약을 제공하면서 조건 검증과 현재 근거 재조회를 유지한다.

**Architecture:** 동일 사용자·질문·선택 답변에 묶인 감사 기록에서 최근 3턴, 최대 8,000자의 요약을 만든다. 승인된 에이전트 전송 정책 안에서 플래너와 도구 실행 모델에 전달한다. 서버의 순번 결속, 조건 근거 검증, 새 요청의 근거 원장을 계속 사용한다.

**Tech Stack:** 기존 Python 3.12, SQLite 감사 DB, 통합 플래너, 에이전트 도구.

**Spec:** 사용자가 승인한 개선 순서의 3단계(대화 맥락 전달). 다음 단계 진행 요청에 따라 구현하며 추가 승인 절차는 만들지 않는다.

## 설계 선택

클라이언트 대화 원문 전체 전달은 근거 조작과 크기 증가를 막기 어렵다. 서버 답변 전문 전달은 검증 범위와 과거 사실의 구분이 불명확하다. 따라서 서버 기록에서 필요한 필드만 추려 과거 맥락으로 명시한다. 이전 수치와 발췌는 현재 답변의 근거로 등록하지 않고 도구로 다시 확인한다.

## 제약과 검토 초점

- 같은 사용자라도 질문이 다르거나 선택 B가 유효하지 않으면 문맥을 읽지 않는다.
- 차단된 답변, 참고용 문서, 화면 출처 숨김이 순번을 오염시키지 않게 한다.
- 미완료 0건을 완전 조회 0건으로 요약하지 않는다.
- 최근 3턴·8,000자 제한, 마스킹, 도구 사용 설정과 기존 전송 허용 목록을 적용한다.
- 독립 질문의 조건 누출과 여러 턴에 걸친 고객사만 변경을 검증한다.
- 기존 변경 파일은 보존하며 커밋·서버 재시작·운영 전환은 수행 범위에 포함하지 않는다.

## 실행 결과와 판단 기록

- 사용자 지침대로 메인 에이전트가 구현·직접 리뷰했다. 서브에이전트, 커밋, 운영 재시작은 사용하지 않았다.
- 공통 프롬프트 계약은 `backend/intent/conversation_contract.py`에 두었다. 의도 계층이 서비스 계층에 의존하지 않도록 하는 저장소 검사를 따른 결정이다.
- 실제 모델의 표시 결과가 맞아도 내부 표시 개수는 200으로 달라지는 예비 실행을 발견했다. 현재 질문에 변경 근거가 없는 후속 목록의 limit는 이전 확정 값을 유지하도록 검증했다. 명시적인 개수·전체 표시 요청은 기존 표시 계약을 따른다.
- 회귀 테스트에서 기존 실패를 확인하고 수정 후 통과했다. 최종 `check.sh tests compile shell ruff mypy`: 3,011개 테스트, 커버리지 91%, 정적 검사 통과. `check.sh audit`: 기존 예외 5개 외 신규 취약점 없음.
- 동일한 신선한 원천 DB에서 최종 23개 답변이 SQL 기준 수치·번호·제목·순서·조건과 일치했다. 실제 전송 맥락은 최대 4,208자였다. 한투 복합 질문의 가이드 본문은 미확인이며, 후속 순번은 #31659로 정확했다.
- 최종 리뷰: 작성자가 사용자/질문/선택 답변 결속, 전송 정책, 조회 완전성, 참고 자료 분리, 원장 인용 차단, 독립 질문 초기화, 표시 개수 유지와 후속 기록의 호환성을 직접 확인했다. 남긴 중요 결함은 없다.
- 리포트: `assistant_web/runtime/two-week-regression-20261104-155759/conversation-context-20261105/report.md`. 예비 실행과 최종 코호트를 구분하고 재현 스크립트·원천/코드 지문·검사 로그를 함께 보존했다.
