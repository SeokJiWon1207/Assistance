# 여러 고객사 순차·병렬 평가 확대 계획

> 메인 에이전트가 직접 실행한다. 저장소 지침에 따라 서브에이전트는 사용하지 않는다.

**목표:** 한투·KB·NH의 복합·순번 후속·고객사 변경 후속·집계 12개 질문을 두 실행 설정에서 각 3회, 총 72응답 비교한다.

**구조:** 제품의 조건·근거·수치·권한 검증은 그대로 사용한다. 평가의 정답은 고정 Mantis SQLite 원본에서 독립 SQL로 만들고 Notion 현재 본문 읽기와 사전 관련성 판정을 분리한다. 응답을 본 뒤 기대값을 바꾸지 않는다. 공식 단가와 실제 사용량으로 비용을 계산하며 누락된 과금 정보는 미확인으로 남긴다.

**기술:** Python 3.12, unittest, SQLite backup, 기존 benchmark/ChatService와 감사 원장.

**기준:** `assistant_web/docs/AGENT_EVALUATION.md`, 사용자의 검증 범위 확대 요청.

- [x] `benchmark_observation.py`의 캐시 쓰기·처리 등급 관측 및 `benchmark_pricing.py` 비용 계산을 회귀로 검증한다. 일반 입력/캐시 읽기/캐시 쓰기를 중복 과금하지 않으며 미보고·비표준 등급을 0원 처리하지 않는다. 평균·p95 요청 비용을 기록한다.
- [x] `benchmark_matrix.py`로 고객사별 독립 정답과 고정 문항을 만든다. 타 고객사 혼입·해결/종료 제외·동일 시각 ID 정렬·미지 상태를 테스트한다. 문항은 runtime에 보존한다.
- [x] 답변 생성 전에 읽을 수 있는 Notion 후보 본문에 관련성 판정을 남긴다. 새 본문 버전은 기존 기준대로 미확인 처리한다. 요청 항목과 고객사별 결과를 따로 보고한다.
- [x] 코드·문항·공개 설정·가격표·저장본을 고정하고 1/2 설정만 바꿔 교차 반복한다. 기존 허용된 Luna와 장애 시 Gemini, 읽기 전용 원천만 사용한다. 최신성이 만료되면 중단하며 TTL을 늘리지 않는다.
- [x] 완료율·조건/숫자/순서 정답·관련성·비용·지연·실제 병렬 묶음·429/재시도·최종 경고를 비교한다. 예비 실행 사용량은 별도 보존한다. 표본·관찰 기간이 부족하면 운영 통과를 선언하지 않는다.
- [x] 변경 범위 검사와 결과 리포트를 완료한다. 운영 설정·라우팅·검증 기준은 바꾸지 않는다.

최종 결과: `docs/evaluations/2026-11-09-agent-matrix.md`. 예정 72요청 중 70실행, 미실행 2개도 완료율 분모에 포함했다. 예비 실행에서 KB 정규 키 오채점과 NH 순번 해석의 승인 범위 이탈을 발견해 예비 결과를 분리하고, 원장 게시 전 승인 ID 차단을 양쪽에 동일하게 적용한 새 버전으로 재측정했다. 운영 확대는 보류하며 제품의 후속 조건/순번 해석 문제는 후속 수정 대상으로 남긴다.
