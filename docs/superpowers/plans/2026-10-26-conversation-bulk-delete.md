# 대화 목록 일괄 삭제 구현 계획

> 메인 에이전트가 직접 수행한다. 사용자의 일반 구현 선택 위임에 따라 기존 스택과 삭제 의미를 유지한다.

**목표:** 대화 관리 모드에서 개별 선택·불러온 목록 선택·선택 삭제·전체 삭제를 제공한다. 전체 삭제는 서버에 아직 불러오지 않은 로그인 사용자 대화와 기기의 대기를 포함한다.
**구조:** SQLite 단일 트랜잭션의 사용자별 일괄 삭제 API, 기존 작업 큐와 저장 캐시, 공통 모달·토큰을 사용한다. 새로운 서버 스키마나 보관 정책을 만들지 않는다.
**기술:** FastAPI, SQLite, Vanilla JS/CSS, 기존 Python·Node 테스트.

## 결정

- 선택 삭제만 제공하면 100개 이후의 서버 기록을 지우기 어렵고, 전체 삭제만 제공하면 필요한 대화를 남기기 어렵다. 두 경로를 하나의 관리 모드로 제공한다.
- 즐겨찾기도 선택/전체 삭제 대상이다. 삭제는 기존 단건 API와 같이 영구 삭제이며 확인 창에서 명시한다. 실제 운영 사용자의 기록은 검증 중 삭제하지 않는다.
- 삭제 요청 중 신규 전송·대화 조작을 막고, 해당 대화의 대기 저장을 취소하고 실행 중 저장을 기다린 뒤 삭제한다. 삭제 실패 시 기기의 기록을 복원한다.
- 저장 캐시 쓰기는 순서를 유지하고 삭제 완료를 반영해 새로고침 시 재등장하지 않게 한다.

## 순서

- [x] Python 회귀: 사용자 경계, 전체 100개 초과, 메시지 정리, 빈 입력 검증, 트랜잭션 실패 원복, 인증·CSRF.
- [x] Backend: conversation_history.py / workspace.py / api/workspace.py에 원자 일괄 삭제 추가.
- [x] Node 회귀: 대기·실행 중 저장과 삭제 경합, 실패 원복, 계정 전환, 전체 삭제 후 빈 대화, 선택 삭제 후 나머지 유지.
- [x] UI: index.html / runtime.js / workspace.js / conversation_bulk.js / events.js / conversation_list.css에 관리 모드·확인 모달·상태 추가.
- [x] check.sh 관련 검사, 실제 브라우저의 격리 데이터로 데스크톱·모바일 선택 및 확인/취소 시각 검증.
- [x] 전체 검증 후 결과 기록. 운영 데이터 삭제는 수행하지 않는다.
