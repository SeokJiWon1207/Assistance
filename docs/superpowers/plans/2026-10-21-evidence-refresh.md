# 비교 근거 보존과 원문 갱신 지연 보완 계획

사용자 요청을 구현 사양으로 삼아 메인 에이전트가 직접 실행한다. 서브에이전트는 사용하지 않는다.

목표: 긴 노트의 원인·실제 조치를 보존하고 모델 분류 실패에도 본문 진단을 유지하며 원문 갱신의 대기 시간을 제한한다.

구조: 원문 구역과 문장의 경계를 먼저 보존한다. 확정 원인·추정·실제 조치는 출처와 함께 구분하고 실패한 추가 분류는 이미 확인한 근거를 지우지 않는다. 유사 비교의 읽기 전용 갱신에 한해 요청 내 재사용과 짧은 대기 예산을 적용하며 저장본 대체 여부를 표시한다.

제약: Python 3.12, 회사 모델만 사용, 인증·쿠키·CORS·보안 설정 유지. 집계와 질의 조건 해석은 변경하지 않는다. 이전 D 질문은 회귀용이며 새 E12문항은 수정에 사용하지 않는다. 커밋·푸시는 별도 요청 전 수행하지 않는다.

- [x] 실패 재현: 다중 서버 원인/미확정, 여러 실제 조치, 분류 시간 초과 시 본문 진단, 갱신 요청 수·예산·접근 거부·저장본 대체의 회귀 테스트.
- [x] 구역·문장 단위 근거 추출 보완. 원인 ‘파악’과 제거 ‘요청’을 완료로 혼동하지 않으며, 빈 조치 제목은 버린다.
- [x] 비교 검색의 원문 갱신 예산·요청 내 재사용. 접근 거부·삭제는 저장본으로 되살리지 않고 취소 신호도 보존한다.
- [x] 전체 검사 후 운영 반영. 기존 D3/D4/D6와 E12문항을 실제 전송하고 원문·독립 집계·시간을 대조한다.
- [x] 코드와 운영 해시, 자원·데이터 세대, 최종 답변과 요약 대체 여부를 기록한다. E 결과로 코드를 수정하면 해당 질문을 개발용으로 전환하고 최종 미사용 점수에 넣지 않는다.

검토 초점: 한 노트의 서로 다른 서버, 부정 원인과 긍정 조치, 본문의 문의/추정과 진단, 403/404/429와 취소, 느린 연결 및 오래된 저장본을 각각 구분한다.

실행 검증: E는 추가 보완에 사용하여 개발 평가로 전환했고, 별도 F9는 코드 수정에 쓰지 않았다. F 최종7/9 충족, 일부 이력·원인 분류 오류와 전체 시간 개선 미달은 평가 보고서에 별도로 남겼다.
