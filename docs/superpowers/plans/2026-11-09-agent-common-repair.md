# 공통 보정 흐름 통합 구현 계획

> 메인 에이전트가 직접 수행한다. 사용자 요청 없이 위임하지 않는다.

**목표:** 검증된 문장·수치 결과를 보존하면서 실패 유형별로 제한 보정하고, 기존 검증과 최종 조합 검증을 유지한다.

**설계 근거:** 사용자가 승인한 공통 보정 단계. 표현·인용은 확보한 원문으로 실패 항목만 보정, 수치는 서버 계산과 재대조, 원문 부족은 미완료, 권한·취소는 보정 제외. 이미 검증된 부분을 전체 재생성에 맡기지 않는다.

**구조:** 모델과 무관한 공통 보정 거래를 `backend/evidence/repair.py`에 둔다. 키로 지정한 실패 항목만 받을 수 있고, 검증된 값은 복사해 고정한다. 기존 경로별 검증 함수를 어댑터로 연결한다. 최대 한 번 보정하며 같은 공통 요청 예산·정책·취소를 사용한다.

**런타임:** Python 3.12, 기존 unittest·check.sh. 운영 플래그·보안·허용 모델·검증 문턱·180초/16회 예산은 변경하지 않는다.

## 검토 초점

- 정상 문장과 실패 문장이 같은 문서 slot에 있어도 정상 문장은 원문 그대로 보존한다.
- 모델이 보정 대상 밖의 ID·수치·조건을 바꾸려 하면 채택하지 않는다.
- 수치가 원문/서버 사실에 없거나 단위·기간·그룹이 다르면 보정 후에도 거부한다.
- 본문 미확보와 전체 0건을 혼동하지 않으며 권한 거절·취소 이후 호출·병합을 하지 않는다.
- 수정 문장의 재검증 및 최종 조합 검증 실패 시 기존 정상 부분만 남긴다.
