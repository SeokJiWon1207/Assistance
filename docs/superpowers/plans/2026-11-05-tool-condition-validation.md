# 도구 인자 조건 검증 구현 계획

**Goal:** 모델이 필터·범위·정렬을 도구 인자로 전달하고 서버가 원문·이전 확정 조건과 일치하는지 조회 전에 검사한다.

**Architecture:** 현재 요청의 검증된 계획을 원천별 조건 계약으로 만든다. 모델은 전체 조건을 인자로 제안하거나 같은 요청에서 서버가 발급한 조건 참조를 재사용한다. 누락·추가·부정 연산 변경·범위 확대·정렬 변경을 거절하며 기존 수치 계산과 근거 원장을 유지한다. 이번 단계는 계약 이동이며 한 질문에서 서로 다른 조회 범위를 새로 만드는 기능은 포함하지 않는다.

**Tech Stack:** Python 3.12, Pydantic, 통합 계획·근거 검증기, 기존 읽기 도구.

**Spec:** 사용자가 요청한 도구 인자 기반 조건 검증과 정규식 의존 축소. 메인 에이전트가 직접 구현·리뷰한다.

## 작업과 검증

- [x] `backend/tools/query_conditions.py`: 구조화된 필터 스키마, 원천별 계약, 질문/이전 감사/인증 사용자 조건의 근거 확인, 조건 참조 재사용. 부정 조건·날짜·고객사 별칭·정렬·범위·명시적 빈 필터를 검사한다.
- [x] `tools/registry.py`, Mantis·Notion 검색 도구, 건수·목록 도구를 연결한다. 모델 조건이 검증되기 전에는 원천과 기존 캐시에 접근하지 않는다. 허용되지 않은 원천과 참고 등급은 기존 정책을 유지한다.
- [x] `services/agent/orchestrator.py`에서 조건 계약과 적용 근거를 모델·감사에 전달한다. 건수·목록의 첫 호출은 명시적인 조건 인자를, 이후 호출은 검증된 조건 참조를 사용할 수 있다.
- [x] query-shadow의 통합 계획은 리터럴 정규식 지름길을 거치지 않고 모델로 해석한다. 목록 도구의 질문 정규식에 의한 표시 개수 덮어쓰기를 제거하고 검증된 인자를 따른다. 날짜·상태·권한·조건 근거 검사는 유지한다.
- [x] 결정형 실패 테스트를 먼저 확인하고 구현한다. 라우팅 사례와 조건 누락/확대/근거 문구 주입/다른 요청의 참조/불완전 조회 회귀를 추가한다.
- [x] 신선한 동일 저장본으로 기존 경로와 shadow의 조건 변경·순번 후속·다양한 표현을 비교하고 한투 복합 질문을 shadow에서 재검증한다. 실제 도구 인자와 서버 검증 결과를 기록한다.
- [x] `check.sh` 검사, 직접 리뷰와 결과 리포트를 마친다. 운영 경로 전환과 서버 재시작은 이번 범위에 포함하지 않는다.

## 검토 초점

조건을 생략한 호출이 전체 조회로 넓어지지 않아야 한다. 근거는 모델의 설명 문구가 아니라 서버가 확인한 질문·감사 기록에 결속돼야 한다. count/list는 같은 조건과 저장본을 사용해야 하며 참고 문서에 Mantis 상태를 적용하거나 직접 근거로 승격하지 않아야 한다. 기존 경로와 가짜 원천 테스트의 내부 호출 호환성은 유지하되 새 조건 인자가 검증 없이 실행되는 우회는 허용하지 않는다.
