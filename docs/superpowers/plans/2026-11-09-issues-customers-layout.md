# 이슈·분포와 고객사 화면 개선 계획

> **For agentic workers:** `superpowers:executing-plans`로 직접 구현한다. AGENTS.md에 따라 서브에이전트를 사용하지 않는다.

**Goal:** 앞서 승인·적용한 중립 카드와 정보 위계를 이슈·분포와 고객사 화면에 확장한다.

**Architecture:** 기존 ES 모듈 문자열 렌더러, 이벤트 위임과 차트를 재사용한다. 이슈 목록을 분석보다 먼저 배치하고, 고객사 카드는 현재 데이터로 읽기 순서를 정리한다.

**Tech Stack:** 기존 JavaScript·CSS·Bklit, Node 테스트, Ego Lite. 새 의존성이나 TDS를 추가하지 않는다.

**Spec:** 사용자가 승인한 팀 현황·빈 업무·공통 카드 개선 기준과 이번 두 화면으로 확장하라는 지시.

## 범위와 제약

- 이슈·분포: 핵심 지표 → 우선 확인 목록 → 미종료 분포 → 신규 현황·주간 집계·추이.
- 고객사: 여유 있는 3열 카드, 이름·미종료 수 강조, 지연과 급증을 함께 표시, 과거 신규 추이 유지.
- 검색·필터 결과 건수와 초기화 동작을 제공한다. 0건·부분 조회·오류를 구분한다.
- 기존 위험 산정·API·필터 조건·정렬·상세 동작과 저장된 보기를 유지한다.
- 라이트·다크와 모바일을 확인한다. 기존 미커밋 변경을 기준으로 작업하며 이번 범위만 수정한다.

## 검토 조건

- 이슈 KPI가 두 탭에 있어도 필터 해제 후 현재 보이는 컨트롤로 포커스가 돌아간다.
- 지연·급증이 동시에 있는 고객사의 두 상태가 모두 보인다.
- 부분 조회 0건을 업무 없음으로 단정하지 않고 급증 판단을 표시하지 않는다.
- 고객사 검색 결과 0건에서 초기화하면 검색과 상태 필터만 해제하고 정렬·데이터를 유지한다.
- 상세 패널과 좁은 화면에서도 표·차트·검색이 카드 바깥으로 넘치지 않는다.
