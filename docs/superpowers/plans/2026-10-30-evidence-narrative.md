# 근거 기반 설명 확대 실행 계획

목표: 근거 검증을 유지하면서 검증 실패한 LLM 설명을 한 번 보정하고, 사례별 초기 문의 문장 치환 네 가지를 원문 인용과 검증된 LLM 설명으로 대체한다.

사용자가 선택한 2번 개선을 실행한다. Python 3.12와 기존 모델 호출·취소·Luna→Gemini 정책을 사용한다. 메인 에이전트가 직접 수행하며 기존 사용자 변경과 이전 측정은 보존한다.

## 설계

- 기존 선택·독립 검토를 통과한 근거를 대상으로 한다. 짧은 설명의 서버 검증이 실패한 경우에만 보정 1회와 의미 재검토 1회를 허용한다.
- 보정 모델은 항목별 문장만 출력한다. 이슈·질문 항목·근거·미확정 상태는 서버가 고정하고, 새 근거나 수치·식별자를 만들어 붙이지 못한다.
- 보정 결과는 기존 `summary_items`의 수치·식별자·완료 범위 검사를 통과하고, 별도 모델이 연결 근거와 후속 이력을 대조해 모두 승인해야 표시한다. 승인 결과의 자료형·개수도 검사한다.
- 오류·잘못된 JSON·보정 거부는 확인된 원문 답변으로 복귀한다. 사용자 취소는 전파한다. 성공한 기존 설명에는 추가 호출하지 않는다.
- 엑셀 1800년 날짜 문의, 날짜 기본값, CMF 추세, 창 크기 저장의 사례별 고정 설명을 제거한다. 원문 출력과 일반 검증 규칙은 보존한다.

## 실행·검증

- [x] 보정 성공·새 수치·완료 과장·잘못된 승인·다른 이슈·취소·장애의 실패 테스트를 작성하고 확인한다.
- [x] 보정 책임을 `services/explanation_narrative.py`에 구현하고 기존 설명 흐름에 연결한다.
- [x] 고정 문장 네 분기와 연결된 식별자를 제거하고, 관련 테스트는 원문 사실·근거 보존을 검증한다.
- [x] 집중 검사와 전체 `scripts/check.sh`의 여섯 단계를 통과한다.
- [x] 변경 전후 같은 Luna와 원천 복사본으로 고정 문항을 실행해 비교한다.

기존 11문항은 변경하지 않는다. 실제 저장본 원문으로 확정한 설명 문항 4개를 추가한 15문항·17턴을 제품 수정 전에 `runtime/evidence-narrative-20261030/cases.jsonl`에 봉인했다. 추가 문항은 개발 2개, 확인 2개이며 기대값은 측정 결과에 맞춰 수정하지 않는다. 모델 요약 채택 여부·새 실패·출처·토큰·응답 시간도 기록한다. 실시간 원천과 모델 출력의 변동은 코드 회귀와 구분한다.

## 구현과 검증 기록

고정 문장의 생성·분류 분기 네 개를 제거하고, 짧은 본문은 원문 그대로 출처와 함께 인용하는 공통 처리를 사용한다. 다른 사례의 기존 결론·완료 여부·근거 검증은 유지한다. 기존 요약이 통과하면 보정 호출은 없다. 초안과 연결 근거가 있지만 요약 검증에 실패한 경우에만 보정·의미 검토를 합쳐 최대 두 번 호출한다. 이 횟수는 서비스 호출 기준이며 공급자의 재시도·대체 모델 요청은 기존 정책을 따른다. 요청 전체의 시간 제한과 취소 정책을 그대로 사용한다.

보정 모델은 문장 배열만 반환하며, 서버가 기존 항목 순서·근거·미확정 상태에 결속한다. 전체 후속 근거가 80,000자를 넘으면 임의로 잘라 승인하지 않고 보정을 생략한다. 보정 실패나 모델 오류는 검증된 원문 답변으로 복귀한다. 승인 값은 정확한 개수의 `true` 불리언만 인정한다. 모델 검토가 통과해도 수치·식별자·완료 범위 검사가 거부하면 표시하지 않는다. 이는 의미 오류가 절대 발생하지 않는다는 보증은 아니다.

신규 테스트는 13개다. 최종 코드로 `assistant_web/scripts/check.sh` 전체를 실행해 종료 코드 0을 확인했다. 전체 테스트 2,692개, 커버리지 90%이며 compile·shell·ruff·mypy·audit도 모두 통과했다. mypy 검사 대상은 174개 소스이며 audit의 기존 예외 5개는 변경하지 않았다.

실제 Luna의 별도 보정 점검에서도 성공했다. 합성 원문은 `ReadValue 함수의 기본값은 7`이고, 잘못된 초안은 `99`였다. 기존 요약 검증은 초안을 거부했고, 새 보정 경로는 `조회 함수는 ReadValue이며 기본값은 7입니다.`로 고친 뒤 별도 의미 검토를 통과했다. 두 번의 실제 호출이 사용됐으며, 산출물은 `runtime/evidence-narrative-20261030/live-repair-probe.json`에 있다.

관련 로그: `red.log`, `green.log`, `temporal-red.log`, `temporal-green.log`, `full-check-verified.log`. 원문과 모델 응답은 Git에 포함하지 않는다.

## 초기 요청과 후속 변경의 구분

중간 실측의 자동 채점은 12/15로 변경 전과 같았지만, 핵심 설명을 원문과 대조하니 개발 문항 하나에서 후속 변경 값을 최초 요청으로 합친 오류가 있었다. 전체 답변에는 원문도 포함되므로 키워드 채점만으로 이 오류를 잡지 못했다. 문항과 기존 기대값을 바꾸지 않고 일반적인 질문 범위 검증을 보완했다.

최초·초기 요청이나 문의만 묻는 경우, 설명에 사용할 근거를 선택된 본문으로 제한한다. 이후·후속·최종 상태도 묻는 질문은 기존 전체 근거를 유지한다. 근거 범위를 좁혔으면 기존 의미 검토 결과를 재사용하지 않고 보정·재검토를 거친다. 본문 근거가 없거나 보정이 실패하면 원문 답변을 유지한다. 후속 노트는 정정·모순·완료 여부를 확인하는 데 계속 사용하며 전체 이력에도 남긴다.

중간 오류와 최종 설명 4개에 대한 의미 대조는 `runtime/evidence-narrative-20261030/narrative-manual-review.json`에 별도로 기록한다. 이 수동 점검도 제한된 표본이며 모든 문장의 의미 정확성을 보장하지 않는다.

## 최종 실제 모델 비교

동일한 15문항·17턴, 모델 `gpt-6-luna`, 모델·설정·실행 스크립트 해시, 고정 원천 복사본을 사용했다. 현재 코드 해시도 최종 측정의 코드 해시와 일치한다. 변경 전은 `before`, 최종 변경 후는 `after-verified`다. 최초 변경 후 실행 `after`와 중단한 `after-final`은 별도로 보존하며 최종 결과로 섞지 않는다.

| 구분 | 변경 전 | 최종 변경 후 |
| --- | ---: | ---: |
| 기존 고정 문항 | 8/11 | 11/11 |
| 추가 설명 문항 | 4/4 | 4/4 |
| 전체 자동 채점 | 12/15 | 15/15 |
| 성공한 모델 HTTP 요청 | 32 | 33 |
| 비교 실행 토큰 합계 | 164,481 | 168,434 |

새로 실패한 문항은 없다. 모든 모델 응답은 Luna였으며 실행 오류·미등록 요청도 없다. 토큰은 표의 두 실행만 집계한 값으로, 중간 실행·연결 확인·별도 보정 점검은 제외한다.

다만 **세 문항의 점수 상승을 모두 이번 코드의 효과로 볼 수 없다.** 변경 전 Notion 읽기에서 429가 40회 있었지만 최종 실행에는 없었고, 본문 검색 문서도 복구됐다. Mantis 후속 담당자 질문은 모델 계획이 `explain`에서 `get`으로 달라졌다. 직접 이슈 조회의 조건에는 숫자와 문자열 표현 차이도 있었다. 원천 응답의 공통 요청 588종 중 47종이 달랐다. 관찰한 목표 Notion 페이지 3개의 원문 자체는 동일했다. 따라서 이 결과는 제한된 회귀 표본이며 통제된 전체 정확도 향상 수치가 아니다.

추가 설명은 자동 키워드 채점과 별도로 핵심 답변을 원문에 대조했다.

- 엑셀 문의: 본문으로 근거를 좁혀 보정·별도 의미 검토에 실제 Luna 호출 두 번을 사용했다. 두 가지 최초 문의를 모두 설명했다.
- 날짜 기본값: 보정 응답은 올바른 최초 요청을 설명했으나 JSON 대신 일반 문장으로 반환됐다. 형식 검증에서 거부하고 초기 본문과 후속 정정 노트를 인용하는 답변으로 복귀했다. **LLM 설명 성공으로 계산하지 않는다.**
- 창 크기 요청과 CMF 기능 검토: 기존 설명 검증을 통과해 보정 호출 없이 LLM 설명을 사용했다. 요청을 구현 완료로 바꾸지 않았는지도 확인했다.

따라서 최종 추가 설명 4개 중 3개는 검증된 LLM 설명, 1개는 검증된 원문 복귀다. 원문이 함께 실리는 전체 답변의 4/4 점수와 LLM 설명의 채택률은 구분한다. 보정 모델의 출력 형식 오류가 원문 복귀로 처리되는 것도 이번 실측에서 확인했다.

산출물은 `runtime/evidence-narrative-20261030/comparison.json`, `narrative-manual-review.json`, `completion.json`에 있다. 최종 코드를 표준 재시작 스크립트로 로컬 서버에 적용했고 `/health`의 HTTP 200을 확인했다. 커밋은 만들지 않았다.
