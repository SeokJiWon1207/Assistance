# 목록 조건과 상세 대상 분리 구현 계획

> 실행: `superpowers:executing-plans` 절차로 메인 에이전트가 직접 수행한다. 사용자 지침에 따라 서브에이전트와 별도 승인 단계는 사용하지 않는다.

**Goal:** 상세 조회 후 고객사 변경에서도 원래 목록 조건을 유지하고 실제 표시 순번으로 대상을 찾는다.

**Architecture:** 서버 감사 기록에 목록의 조건과 상세 대상을 구분해 보존한다. 모델은 후속 조회의 맥락을 구조화된 인자로 지정하고, 서버는 선택한 기준의 조건 상속·변경 근거를 기존 검증기로 확인한다. 목록의 조건과 순서는 현재 사실 근거로 재사용하지 않고 원천을 다시 읽는다.

**Tech Stack:** Python 3.12, 기존 감사 DB·PlanningSession·검증기·순차/병렬 도구 실행기.

**Spec:** 현재 사용자 요청 및 `docs/evaluations/2026-11-09-agent-matrix.md`의 고객사 변경/순번 실패.

## 제약과 검토 대상

- 기존 조건·근거·수치·전송 정책과 승인된 27건 차단기를 유지한다.
- 다른 사용자, 질문, A/B 변형, 전달 차단된 기록은 상속하지 않는다.
- 독립 질문은 이전 목록을 끊고, 명시적 상태 변경은 기존 검증으로 처리한다.
- 순번 부재·범위 초과는 전체 검색으로 확장하지 않는다. 화면번호·반복 횟수와 구분한다.
- 목록 조건의 명시적 이슈 ID 제한은 보존한다. 상세 확인용 ID만 목록 조건과 구분한다.
- 과거 표시 순서와 현재 상세 사실을 구별하고, 여러 상세 턴 이후에도 목록 기준을 잃지 않는다.

## 1. 회귀 고정과 구현

대상: `backend/intent/conversation_scope.py`(신규), `context.py`, `unified_validation.py`, `conversation_contract.py`, `services/unified_planning.py`, `services/agent/planning.py`, 관련 테스트·라우팅 fixture.

- [x] 목록→순번 상세→고객사 교체 회귀를 실패 상태로 실행한다.
- [x] 서버 소유 목록 기준을 보존하고 모델의 후속 맥락 선택을 기존 조건 검증에 연결한다.
- [x] 표시 목록의 `2번` 참조 및 잘못된 참조의 조회 차단 회귀를 고정한다.
- [x] 권한·독립 질문·명시적 상태 변경·표시 개수·수치·근거·승인 차단 회귀를 실행한다.

시험 실행에서 count 계획의 limit=null 때문에 목록 3건 요청을 기본 5건으로 덮어쓰는 추가 오류가 확인됐다. 건수 계산과 표시 개수를 도구 계약에서 분리하고, 3건은 허용·5건은 거부하는 실패→통과 회귀를 추가했다. 시험 12응답은 최종 비교에서 제외하고 사용량·결과를 별도 보존한다.
