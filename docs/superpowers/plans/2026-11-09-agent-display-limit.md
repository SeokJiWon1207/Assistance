# 고객사 변경 후속의 표시 개수 보존

> 메인 에이전트가 직접 실행한다. 사용자 승인 범위와 기존 검증을 유지한다.

**Goal:** 최근 3건 요청이 계획의 200건으로 대체되는 실패를 수정하고 동일 한투·KB·NH 72응답을 재검증한다.

**Architecture:** 모델은 계획과 도구 인자를 결정한다. 서버는 현재 질문의 명시된 표시 개수를 계획 확정·실행·최종 표시에서 공통 검사한다. 전체 집계와 최근 N건 모집단은 표시 개수와 분리한다. 잘못된 값은 자동 덮어쓰기 대신 부분 보정 대상으로 돌려준다.

**Tech Stack:** Python 3.12, unittest, SQLite, 기존 ChatService 및 비교 평가기.

**Spec:** 사용자 현재 요청, `docs/evaluations/2026-11-09-agent-notion-evidence.md`의 순차 고객사 변경 실패 1건.

## 계약

- 미해결·고객사·범위·순서·근거·수치·전송 검증과 승인 27개 ID 차단을 유지한다.
- 사용자가 새 표시 개수나 전체 목록을 요청하면 허용한다. 총건수는 표시 개수로 자르지 않는다.
- 50건 요청을 과거 검색 기본 상한 20건으로 오인하지 않고, 최근 150건 기준 모집단을 표시 개수로 쓰지 않는다.
- 인용된 검색어의 숫자, 기간, 순번, 뒤쪽 Notion 문서의 개수를 Mantis 표시 개수로 적용하지 않는다.
- 저장본이 만료되면 갱신하거나 실행을 중단한다. TTL/갱신 시각을 조작하지 않는다.
- 공유 작업 공간의 무관한 변경·운영 설정·배포·커밋은 건드리지 않는다.
