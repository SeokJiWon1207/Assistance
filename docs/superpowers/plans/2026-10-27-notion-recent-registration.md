# 노션 최근 등록 목록 수정 계획

**목표:** 최근 등록 문서를 본문 수집 상태와 독립적으로 조회하고 등록일로 정렬한다.

**설계:** 사용자가 승인한 문서 속성 조회 분리를 적용한다. 최신·완전한 목록 저장본의 속성으로 상위 문서를 선택하고 반환 대상의 현재 접근 권한과 속성을 재확인한다. 본문 상태 검사와 본문 API는 사용하지 않는다. 저장본을 사용할 수 없으면 기존 API 경로에서 등록일 정렬과 목록 개수 제한을 적용한다.

**환경:** Python 3.12, 기존 SQLite 목록 저장본, Notion API.

**제약:** 설정된 읽기 범위·목록 최신성·현재 문서 접근 검증을 유지한다. 등록일 속성이 없으면 페이지 생성 시각을 사용한다. 인용한 제목과 실제 주제 키워드는 보존한다. 사용자 변경 파일은 보존하고 서브에이전트는 사용하지 않는다.

## 검증 중점

- 본문이 미수집된 240개 DB에서도 문서 목록을 이용하고 표시할 문서만 재확인한다.
- 오래된/불완전한 목록과 접근 철회 문서를 최신·완전한 결과로 반환하지 않는다.
- ‘등록된’은 정렬 요청에서만 제거하고 제목·본문 리터럴은 보존한다.
- 같은 날의 시각, 등록일 속성, 생성일 대체, 기간 필터를 함께 검사한다.
- 요약·본문 검색·건수 질문과 수정순 조회의 기존 의미를 보존한다.

## 작업

- [x] 최근 등록 목록·키워드·정렬·저장본 실패 경계의 회귀 테스트와 routing_cases.jsonl 사례를 추가하고 실패를 확인한다.
- [x] 최근 등록 의도 해석, 속성 전용 목록 검색, API 대체 경로의 등록순 정렬을 구현한다.
- [x] 관련 테스트와 `assistant_web/scripts/check.sh tests ruff mypy`를 실행한다.
- [x] 실제 로컬 목록 저장본으로 본문 없이 조회하는 경로와 처리 시간을 검증하고 변경 사항을 직접 리뷰한다.

## 실행 기록

사용자 요청으로 구현 범위가 확정되어 이 세션에서 직접 진행한다. 후속 사용자 요청에 따라 작업 내역 전체 커밋, 운영 배포, 실제 웹페이지 검증까지 진행한다.

- 회귀 테스트 18개를 추가했다. 키워드 오해석, 정렬, 본문 완전성 의존, 날짜 자정 처리, 검색 기준 표시의 실패를 확인한 뒤 수정했다.
- 최종 `assistant_web/scripts/check.sh tests ruff mypy`: 2,516개 테스트 통과, 커버리지 89%, Ruff 및 mypy 통과.
- 로컬 실제 목록 16,705건: 전체 표시 속성 변환 34.972초 → 날짜 속성만으로 후보 선정 2.478초.
- 실제 Notion API를 포함한 목록 조회: 최근 5건을 4.756초에 반환, 페이지 속성 재확인 5회, 본문 조회 0회. 모델 질문 해석과 브라우저 표시 시간은 이 측정에서 제외했다.
- 요청된 범위의 권한·기간·정렬·본문 리터럴 보존과 실패 시 기존 API 조회 경로를 직접 리뷰했다. 서브에이전트 없이 수행했다.
- 기존 목록 최신성 기준을 유지하며 목록 기준 시각을 답변에 표시한다. DB 등록일 속성이 비어 있을 수 있는 API 대체 경로는 생성일 대체 결과를 누락하지 않도록 전체 후보 검사를 유지한다.

- 배포 전 전체 검사: 2,525개 테스트, 커버리지 89%, compile·shell·Ruff·mypy 통과. 네트워크 제한으로 audit 단계만 재실행하여 기존 승인 예외 외 취약점 없음 확인.
