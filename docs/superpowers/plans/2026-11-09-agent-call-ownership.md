# 호출별 상태·예산·취소 정비 구현 계획

> 메인 에이전트가 직접 구현한다. 사용자 승인 범위에 따라 기존 검증과 순차 실행을 유지한다. 서브에이전트·운영 배포·커밋은 포함하지 않는다.

**목표:** 도구가 호출별 사본에서 실행되고 요청 소유자가 유효한 결과만 반영하도록 한다. 공통 호출 예산의 차감과 예약 검사, 작업자 문맥 전달, 취소/마감 이후 결과 차단을 보장한다.

**구조:** `ToolContext.for_call`로 호출 ID를 분리하고 `tools/call_state.py`가 원장·조건 참조·재사용 캐시·계획 상태의 스냅샷과 단일 반영 지점을 소유한다. 요청 원장 버전이 달라졌으면 덮어쓰지 않고 충돌을 반환한다. `ExecutionBudget`은 취소와 결과 반영을 직렬화하고 작업자 제출 시 ContextVar와 공통 마감/정책을 전달한다. 실제 도구 병렬화와 독립 호출의 병합 최적화는 후속 단계다.

**기술:** Python 3.12, dataclasses, threading, concurrent.futures, contextvars. 새 의존성 없음.

**기준:** `assistant_web/docs/AGENT_EVALUATION.md`, `docs/evaluations/2026-11-09-agent-evaluation-baseline.md`와 사용자의 2번 단계 요청.

## 제약과 검토 초점

- 조건·순번·원문 권한·근거 등급·전체 조회·최종 수치/인용 검증 및 전송 허용 목록을 유지한다.
- 호출 수·시간 상한과 최종 검증 예약의 현재 정책을 유지하며 원자적으로 검사/차감한다.
- 실패·취소 호출이 남긴 완전 조회 표시, 조건 참조, 캐시, 원문 수정, 준비 계획을 성공 결과로 반영하지 않는다.
- 재시도 가능한 Notion 읽기 실패는 이전 본문을 철회하고 미완료로 표시하는 기존 계약을 유지한다.
- 호출별 단계 인덱스와 호출 ID가 일치해야 한다. 오래된 결과는 다른 호출이 갱신한 원장을 덮어쓰지 못한다.
- 작업자가 요청 취소·마감·모델 전송 정책을 상속하고, 대기 중 취소되면 작업을 시작하거나 늦은 결과를 게시하지 않는다.
- Notion의 연결별 429 공유 대기는 기존 구현과 회귀를 재사용한다. 논리 도구 수·실제 HTTP 요청 수는 앞 단계 평가기로 각각 측정한다.
