# 팀 대시보드·공수 답변 스파크라인 적용 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 사용자 지침에 따라 메인 에이전트가 직접 구현·검증한다.

**Goal:** 승인한 시안의 신규 이슈 추이선과 일별 공수 막대를 실제 집계에 연결한다.

**Architecture:** 대시보드는 기존 intakeTrend를 재사용한다. 개인·조건별 공수는 합계에 반영한 동일한 이슈의 고객사전달일과 해당 기입자의 공수로 일별 자료를 생성한다. 기존 Bklit 차트 영역에 LineSparkline/BarSparkline을 연결하고 표 대체 표시를 제공한다.

**Tech Stack:** Python 3.12, FastAPI, 기존 JS/CSS 모듈, React 19, Bklit.

**Spec:** 이 대화에서 승인한 팀 대시보드 / 공수 답변 시안. 원본: `/Users/seokjiwon/.codex/visualizations/2026/10/27/01a17b80-b17d-7912-8a5c-bdf1a237b1e2/sparkline-preview.html`.

## 공통 제약
- 등록일·공수 기입자·고객사전달일의 기존 조회 의미를 유지한다.
- 불완전 조회는 확인 범위로 표시한다. 미래 빈 날짜를 실적 0으로 표시하지 않는다.
- 1년을 넘는 범위는 일별 차트를 생략해 무한 범위·과도한 응답 크기를 막는다.
- 기존 저장 답변에 일별 자료가 없으면 추이를 만들어 내지 않는다.
- 기존 사용자 수정 파일과 무관한 파일을 변경하지 않는다. 이번 요청은 구현·검증까지이며 커밋은 별도 요청 시 수행한다.

## 중점 검토
- 같은 날 여러 이슈·유형·기입자가 있어도 개인/조건별 합계와 차트 합계가 일치한다.
- 한국 시간 월 경계, 전달일 누락, 조회 범위 밖 이슈가 정확히 처리된다.
- 현재 월의 미래 빈 날짜는 생략하되 실제 미래 전달일로 기록된 집계값은 누락하지 않는다.
- 일부 조회·빈 자료·기존 저장 답변·차트 번들 실패에서 의미 있는 수치와 안내를 제공한다.
- 좁은 카드·모바일·키보드·동작 감소 설정에서 차트를 이용할 수 있다.
