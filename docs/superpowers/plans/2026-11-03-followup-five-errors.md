# 후속 질의 5개 오류 수정 계획

> 실행: 메인 에이전트가 executing-plans 절차로 직접 수행한다. 서브에이전트는 사용하지 않는다.

**목표:** 기존 확정 조건을 유지하는 후속 질의를 수정하고 main 병합 및 운영 배포까지 검증한다.

**구조:** LLM이 이전 계획과 현재 질문을 해석한다. 서버는 상태 변경의 집합 연산, 조건 해제의 원문 근거, 정렬 후 제한을 검증·실행한다. 문장별 목록 조회 우회 규칙은 추가하지 않는다.

**환경:** Python 3.12, unittest, FastAPI, 설정된 회사 모델.

**요구:** 사용자 요청의 남은 5개 오류 수정, 다양한 후속 질의 재검증, main 병합, 운영 배포.

## 제약과 검토 기준

- AGENTS.md의 검증·커밋·보안·위임 규칙을 따른다.
- 상태 제외는 기존 범위를 넓히지 않고, 추가·교체·전체 해제를 구분한다.
- 중복 상태 표현의 모순은 거부하며 현재 원문이 명시한 단일 상태는 정규화한다.
- 고객사만 바꾸는 요청으로 매체를 지우지 않는다. 실제 조건 해제와 비교 종료는 지원한다.
- 이름 끝의 실제 음절과 조사 '만'을 구분한다.
- 날짜와 이슈 번호 순서가 다른 자료에서도 전체 정렬 후 제한하며 라이브 보충 순서를 보존한다.
