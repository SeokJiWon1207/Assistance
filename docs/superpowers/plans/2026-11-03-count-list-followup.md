# 건수 조회 뒤 전체 목록 전환 수정

**Goal:** `MTS 안끝난 이슈 몇개야` 뒤 `리스트 전부 보여줘`를 기존 조건을 유지한 목록 조회로 실행한다.

**Architecture:** LLM이 서버에 저장된 이전 질문·확정 계획과 현재 질문을 함께 보고 작업 전환 및 조건 변경을 해석한다. 서버는 해석된 계획을 검증하고 확정 필터를 상속한 뒤 조회·출력한다. 이 작업에서 추가했던 전체 목록 정규식은 제거한다. count와 표시 개수의 충돌은 LLM 재해석으로 수정하며 검증에 실패하면 실행하지 않는다.

**Tech Stack:** Python 3.12, unittest, 기존 통합 질의 계획.

**Spec:** 이 채팅의 사용자 요청 및 앞서 확인한 count/limit 충돌 재현.

## 제약과 검토 항목

- 기존 고객사·매체·기간·담당자·상태·제외 조건·검색어·정렬을 유지한다.
- 서버에서 검증한 이전 Mantis count/search 계획이 있을 때만 적용한다.
- 단어별 정규식을 늘리지 않고 표현의 의미를 LLM이 판단한다. 단순 목록 전환과 상태 변경·재집계를 구분하고, 서버는 기존 상속·근거 검증 계약을 유지한다.
- 목록 최대 개수는 기존 계약인 200을 따른다.
- 다른 작업의 변경 파일은 수정하지 않고 메인 에이전트가 직접 수행한다.

## 진행 기록

- 기존 조사에서 count와 limit=200 조합이 화면과 동일한 오류를 반환함을 확인했다.
- 사용자가 요청한 수정·검증을 현재 작업 공간에서 직접 수행한다. 커밋·배포는 요청 범위에 포함하지 않는다.
- 새 테스트 9개 통과. 정규식 제거 전에는 LLM 호출 누락과 잘못된 계획이 그대로 우회 실행되는 12개 하위 사례가 실패했다.
- 실제 회사 Qwen 모델에서 최초 건수 조회, 다양한 목록 표현 7개, 건수 재질문, 종료 상태 포함 요청 등 총 10개 시나리오가 통과했다. 목록 표현마다 실제 LLM 호출 1회 및 기존 16개 이슈 ID의 정확한 일치를 확인했다.
- 외부 모델 병행 검증은 자동 승인 검토에서 전송 범위 문제로 거절되어 수행하지 않았다. AGENTS.md에서 사전 승인한 회사 모델만 사용했다.
- 전체 테스트 2,833개 및 compile, shell, ruff, mypy 통과. 전체 커버리지 90%. 이전 검사에서 보였던 별도 고객사 화면 스타일 실패는 이번 실행에는 발생하지 않았다. 해당 파일은 수정하지 않았다.
- 후속 확대 검증에서는 49개 시나리오 중 40개 통과, 5개 실패, 선행 실패로 4개 미실행이었다. 오래된 순의 후보 선택, 상태 제외 시 범위 확대, 할당 상태 계획 충돌, 고객사 한정 시 매체 해제, 담당자 조사 중복 추출 문제는 분석만 수행했다. 이 커밋은 해당 5건의 추가 수정을 포함하지 않는다.

## LLM 해석 방식으로 전환

- 사용자 피드백에 따라 앞서 추가한 전체 목록 정규식을 제거하고 기존 통합 LLM 플래너를 보완한다.
- 현재 프롬프트의 `형식만 변경하면 이전 operation 유지`가 보고서에 한정되지 않아 건수→목록 작업 전환과 충돌할 수 있었다. 이를 보고서의 표현 변경으로 한정하고, 조건 상속과 작업 전환을 별도로 판단하도록 명시한다.
