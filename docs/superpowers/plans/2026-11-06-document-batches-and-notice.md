# 문서 초안 분할과 고객 안내 보정 구현 계획

> 실행: `superpowers:executing-plans` 절차로 메인 에이전트가 직접 구현·검증한다. 사용자 지침에 따라 서브에이전트는 사용하지 않는다.

**Goal:** 사후 분석의 초안 잘림과 고객 안내의 보정 실패를 해결하고 기존 실패 12개 실행을 동일 조건으로 반복 검증한다.

**Architecture:** 읽은 원문을 최대 6건씩 작성·독립 검토하고 검증된 문장만 합친다. 고객용 허용 표현 규칙을 기존 검증기에서 작성·보정 모델에 전달한다. JSON 형식 오류는 공통 예산 안에서 한 번 재작성하며 서버가 임의로 괄호나 사실을 고쳐 채택하지 않는다.

**Tech Stack:** Python 3.12, 기존 ChatService·EvidenceLedger·문장 검증기, unittest.

**Spec:** `docs/evaluations/2026-11-06-agent-document-matrix.md`의 실패 기록과 현재 사용자 요청.

## 공통 제약

- 모델/도구 기본 최대 16회, 요청 180초, 문서 출력 최대 4,096 토큰, 컨텍스트 한도를 유지한다.
- 수치·영문·완료 수준·고객용 용어 검증, 같은 이슈의 문단 결속, 독립 검토는 완화하지 않는다.
- 승인된 17건 및 합성 자료만 기존 허용 모델·마스킹 정책으로 검증한다. 원본 목록·실패 결과를 덮어쓰지 않는다.
- 현재 작업 트리에는 이전 구현과 사용자 변경이 함께 있다. 필요한 파일만 수정하고 별도 커밋·배포는 하지 않는다.

## 검토 초점

- 뒤 묶음 생성 실패가 앞 묶음의 검증 문장을 잃게 하지 않는다.
- 예산이 부족하면 검토 없이 초안을 게시하지 않고 일부 범위를 표시한다.
- 묶음 밖 이슈·문단이나 중복 주장 ID로 검토 결과를 혼용하지 않는다.
- 보정에서 거절 항목을 생략해 완료로 바꾸지 않는다.
- 잘못된 JSON·잘린 출력의 복구가 검토 호출이나 다음 묶음 예산을 무제한 소비하지 않는다.

## 작업 1: 분할 작성과 검토 예산

파일: `backend/services/agent/documents.py`, `orchestrator.py`, `tests/test_agent_document_batches.py`.

- [x] 20건 작성, 중간 묶음 실패, 묶음 간 근거 혼입, 검토 예산 부족의 실패 테스트를 먼저 실행한다.
- [x] 초안·독립 검토·보정을 최대 6건씩 수행한다. 주장 ID를 묶음별로 구분하고 기존 표시 순서를 보존한다.
- [x] 목록 확보 후 필요한 작성·검토 호출과 제한된 보정 여유를 기존 전체 예산에서 예약한다.
- [x] 실패 묶음과 확보/검증 범위를 응답 메타에 남긴다. 이미 검증한 문장은 유지한다.

## 작업 2: 고객 안내 보정과 JSON 복구

파일: `backend/reports/document_narrative.py`, `backend/services/agent/documents.py`, `orchestrator.py`, 같은 테스트 파일.

- [x] 고객 안내의 실제 수신 대상, 허용 영문 목록, 거절된 용어 전달과 JSON 오류 복구 테스트를 먼저 실행한다.
- [x] 기존 고객용 검증 규칙을 데이터로 노출하고, 고객 문의와 회사의 실제 조치를 구분하도록 작성 지시를 보강한다.
- [x] OpenAI 초안·보정에는 JSON 스키마, 나머지에는 JSON 객체 옵션을 적용한다. 잘못된 초안 JSON만 한 번 재작성하고 독립 검토한다.
- [x] 거절된 문장의 보정·항목 병합은 기존 규칙을 유지한다. 검토 JSON 오류는 통과로 바꾸지 않는다.
- [x] 보정 대상 밖의 새 항목을 재작성·게시하지 않는다. 이미 검증한 문장은 보존하고 대상 누락은 미해결로 유지한다.
- [x] 기존 완료 검사로 계산한 문단 후보를 작성 모델에도 전달한다. 판정 규칙을 수정하거나 의미 검토를 생략하지 않는다.
- [x] 미완료 본문의 반복 읽기와 아직 읽지 않은 원문을 구분해 분할 보정 호출을 확보한다. 전체 16회 한도는 유지한다.

- [x] 통과 문장과 같은 턴의 독립 검토 기록, 범위·미완료 표시·한도 준수를 대조하고 전후 결과를 기록한다.

## 결과

최종 채택 v6의 12회 중 3회가 전체 기준을 통과했다. 12회 모두 출력 잘림·JSON 오류가 없고,
후속 최초 응답을 포함한 16개 답변에서 읽은 범위의 요약을 모두 확보했다. 9회는 일부 항목의 완료·의미 대조 거절이 남았다.
전체 3,134개 자동 회귀와 정적 검사를 통과했다. 게시 문장 622개는 같은 턴의 실제 독립 검토 기록과 일치했다.

고객용 검토 지시 추가 실험(v7)은 개선을 확인하지 못하고 구조 오류가 발생해 제외했다.
기존 판정 함수·기본 검토 지시 9개를 유지하며, 실제 v6 평가 소스와 최종 코드의 파일 해시를 대조했다.
고객 안내 보정과 의미 검토가 모두 해결됐다고 보지 않는다. 남은 실패는
`docs/evaluations/2026-11-06-document-batches-and-notice.md`에 기록했다.
