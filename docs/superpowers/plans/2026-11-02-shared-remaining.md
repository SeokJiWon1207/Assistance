# 전체 저장본 복구와 공용 계정 잔여 집계 계획

목표: 운영 전체 저장본 갱신을 확인하고 금주 이슈현황의 잔여현황에 `cs이슈`·`csissue`를 포함해 노션 기준과 맞춘다.

구조: 기존 팀원 13명 범위는 유지한다. 설정에 공용 계정 별칭을 두고 잔여현황에만 확장된 원본을 전달한다. 접수·완료와 상단 미종료·담당자 부하·채팅에는 확대 범위를 적용하지 않는다.

제약: Python 3.12, 메인 에이전트가 직접 수행. 기존 미커밋 변경을 보존하고 이번 변경분만 운영에 적용한다. 디스크 보호·저장본 유효기간·완전성 판정은 완화하지 않는다.

## 작업

- [x] 운영 디스크·전체 저장본·수집 잠금을 읽기 점검하고 필요하면 기존 수집 명령으로 복구한다.
- [x] 공용 계정 포함, 네 제외 상태, 별칭 정규화, 타 팀 제외, 접수·완료·다른 지표 범위 보존 테스트와 routing_cases 회귀 사례를 추가한다. 수정 전 실패를 확인한다.
- [x] `domain/team.py`와 `team_dashboard.json`에 공용 별칭을 정의하고 `filter_team_issues(..., include_shared=False)`의 기본 범위를 유지한다.
- [x] `weekly_issue_summary(..., remaining_issues=None)`에 잔여 전용 범위를 전달하고 UI에 공용 계정 포함을 표시한다.
- [x] 대상 회귀 검사와 `assistant_web/scripts/check.sh`를 실행하고 실제 전체 원본으로 노션과 비교한다.
- [x] 운영 파일의 변경 여부를 다시 확인하고 백업·구문 검사·서비스 재시작·health/ready·브라우저 검증 순으로 이번 변경분만 적용한다.
- [x] 주기 동기화의 후속 갱신 시각과 전체 조회 완전성을 확인하고 결과를 기록한다.

## 점검 중점

- `cs이슈`, `csissue`, 대소문자·공백 별칭을 중복 집계하지 않는다.
- `drfnnext`, 타 팀·미지정 담당자는 확대하지 않는다.
- 정보 부족·개발완료·해결·종료 제외와 부분 조회 표시는 유지한다.
- 최신 원본의 상태 변화로 건수가 변하면 동일 수집 시점과 ID를 함께 대조한다.
- 운영 중 다른 변경이 있으면 현재 파일을 덮어쓰지 않고 새 기준에 이번 수정만 적용한다.

## 진행

- 최초 점검에서 운영 전체 수집은 2026-11-02 14:54:18 KST, 31,328건, 두 차례 수집 일치 상태로 복구되어 있었다. 디스크 여유 약 12GB, 진행 중 수집과 잔여 임시 저장본은 없었다. 기존 복구를 다시 실행하지 않고 후속 자동 갱신을 확인한다.
