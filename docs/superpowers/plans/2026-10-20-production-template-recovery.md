# 운영 자원 복구와 템플릿 오류 수정 계획

사용자가 복구·수정·실제 운영 검증을 요청했으므로 메인 에이전트가 직접 실행한다. 서브에이전트를 사용하지 않는다.

**목표:** 기존 집계와 조건 해석을 보존하면서 운영 자원 부족을 복구하고 전체 12개 템플릿을 검증한다.
**근거:** docs/evaluations/2026-10-20-production-templates.md 및 runtime의 해당 질문 감사 기록.
**구조:** 단일 LLM 계획과 결정형 계산을 유지한다. 계획의 날짜 의미·보고서 종류·정렬을 실행에 전달하며 불완전 결과는 불완전 상태로 검증한다.

- [x] 운영 복구: 비활성 배포 DB 백업을 스트리밍 압축하고 원본 해시 대조 후 교체한다. 로그 보관 64MB, zram 압축 스왑 1GiB를 적용하고 단일 서비스만 실행한다. 운영 DB·인증·현재/직전 릴리스는 보존한다.
- [x] 메모리: 전체 원문 캐시가 아니라 필요한 행만 조회하는 경로를 테스트하고 적용한다. 집계 조건에 필요한 필드는 유지한다.
- [x] 계획/실행: 지난달 달력 범위, 오래된 순, 프로필·월간·주간·공수·유사 비교 라우팅을 실패 테스트로 고정하고 수정한다. 기존 숫자 계산은 재사용한다.
- [x] 검증: 일부 집계의 참고값은 전체 합계와 구분하고 숫자·근거가 다르면 차단하는 테스트를 추가한다. 기존 routing_cases 및 check.sh 전체 검사를 실행한다.
- [x] 운영 반영: 검증된 코드로 원자적 릴리스 전환, 저장본 동기화와 readiness 확인. 운영 화면의 실제 로그인 세션에서 12종을 순차 실행하고 별도 새 질문/후속 질문도 확인한다. 사용자·질문·실행 시각에 한정해 감사 기록을 수집한다.

시간은 서버 감사 기록으로 비교하고, 미응답/자원 거부는 정확도 통과로 계산하지 않는다. 현재 전체 건수는 최신 완전 저장본으로 독립 대조한다. 원문 근거의 존재만이 아니라 최종 답변이 질문에 직접 답하는지 평가한다.
