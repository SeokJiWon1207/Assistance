# 일반 에이전트 조회·집계 도구 연결 계획

> 실행: 메인 에이전트가 직접 수행한다. 사용자가 승인한 하네스 1단계 범위이며 별도 위임·커밋·배포는 하지 않는다.

**목표:** 모델이 건수·목록·집계 도구를 선택하고, 서버가 조건·전체 조회·숫자·표시 순서를 보증한다.

**설계:** 기존 AGENT_MODE_ENABLED 및 모델 전송 정책 안에서 Mantis count/search/aggregate와 Mantis+Notion 복합 읽기를 일반 에이전트에 연결한다. 기존 조건 계약을 확장해 집계 그룹·지표·기간·비교·상위 개수를 확정 계획과 대조한다. 전체 집계는 기존 서버 엔진으로 계산하며 원장 결과만 최종 수치로 출력한다. 부분 조회를 전체 0건으로 바꾸지 않는다.

**선택:** shadow 전용 도구를 일반 경로로 승격하고 기존 엔진을 감싼다. 프롬프트만 바꾸거나 별도 집계기를 만드는 방식은 조건·수치 검증이 중복되므로 사용하지 않는다. 모든 작업의 자유로운 재계획과 다른 보고서 도구화는 다음 단계다.

**제약:** Python 3.12, 기존 허용 모델·마스킹·호출 한도 유지. 사용자 변경 보존. 목록 1~200건 기존 계약 보존. 문서 작업의 원문 읽기 상한 20건 유지. Notion 단독 목록·쓰기 및 다른 보고서는 기존 경로 유지.

## 작업

- [x] 일반 에이전트 라우팅과 플래너 연결: 정책 비활성·원천 비활성·시간 부족에서는 기존 경로 유지. 회귀 fixture와 일반 요청 테스트를 먼저 추가한다.
- [x] aggregate_mantis_issues 도구: 단순 그룹 건수와 기간·지표 집계를 기존 엔진으로 실행. 인자 변조·참조 재사용·미완료·0건·상위 그룹/기타·기간별 날짜 기준을 검증한다.
- [x] 최종 답변/원장/평가 연결: 모델이 임의 숫자를 쓰더라도 서버 결과만 표시. 요청한 도구 결과가 없으면 미완료이며, 건수만 얻고 목록·집계를 완료로 처리하지 않는다.
- [x] 회귀 및 정적 검사 후 동일 저장본의 기존 경로와 일반 에이전트를 실제 Luna로 한투 복합 질문 3회 비교한다. 집계용 한투 보조 질문도 반복해 숫자·그룹·조건·완전성을 독립 기준과 대조한다.
- [x] 결과·제한·사용 설정을 AGENT_HARNESS.md와 평가 보고서에 기록한다.

## 검토 초점

- 목록 20건 초과/전체 표시에서 조용한 누락이 없는가.
- 집계 기간이 건수/목록에서 사라지거나 공수 날짜 기준으로 섞이지 않는가.
- 첫 호출과 condition_ref 재사용 모두 필터·그룹·기간 변조를 거부하는가.
- 모델/원천 장애, 0건, 잘린 결과가 성공으로 포장되지 않는가.
- Notion 참고자료가 대상 이슈의 실제 원인 근거로 승격되지 않는가.

## 진행 기록

- 일반 조회·집계·집계 설명의 모델 호출은 기존 전송 정책과 공통 예산을 사용한다. 검증기는 완화하지 않았고 최종 숫자/표 대조를 전달 차단 항목에 추가했다.
- 20건을 넘는 일반 목록, 원장에 없는 집계 완료 주장, 조건 참조를 통한 지표 변경을 회귀 검사했다.
- 실제 비교 예비 실행에서 기존 플래너가 기간 없는 질문에 오늘을 추가하는 사례를 발견했다. 기간 근거 검사를 강화하고 기간 없는 단일 그룹 건수 해석을 명시했다.
- 자체 리뷰에서 최신 N건 모집단 제한과 표시 개수의 차이를 확인했다. 특수 모집단 제한 요청은 기존 엔진에 남겨 전체 모집단으로 바뀌는 회귀를 막았다. 전체 자유 재계획·범위 창 도구화는 후속 단계다.
- 런타임 비교 산출물: assistant_web/runtime/agent-query-primary-20261106. 예비 실행과 코드 변경 중 실행은 보존하되 최종 동일 코드 반복과 구분한다.

- 최종 검증: check.sh tests compile shell ruff mypy → 종료 코드 0, 3,150건, 커버리지 90%, mypy 289개 소스.
