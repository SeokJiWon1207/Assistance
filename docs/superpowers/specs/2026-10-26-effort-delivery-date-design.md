# 고객사 전달일 기준 공수 집계

사용자가 승인한 기준: 공수 집계 기간은 고객사전달일이며, 질문 해석은 LLM이 하고 계산은 코드가 한다.

## 접근 방식

- 날짜 함수만 변경하면 등록일 조건과 페이지 조기 종료 때문에 과거 등록 이슈가 누락된다.
- LLM에 합산까지 맡기는 방식은 원문 재계산 검증을 약화한다.
- 기존 통합 플래너에 전달일·공수 기입자 조건과 공수 출력 형태를 추가하고, 검증된 계획을 결정형 계산기에 직접 전달한다.

## 동작

- 문의·서버·PC·QC의 이름별 기록을 합산한다. 개인 공수는 다른 담당자 이슈에 기록된 해당 인물 공수도 포함한다.
- 고객사전달일이 없는 이슈와 잘못된 날짜는 기간 집계에서 제외한다. 등록일이나 전달 목표일로 대체하지 않는다.
- 개인·조건별 합계·순위·월별 공수 추이에 전달일을 적용한다. 업무보고서의 등록 건수와 공수는 각자의 날짜 기준을 표시한다.
- 월별 추이의 건수는 등록 건수 의미를 유지하고, 공수는 전달 월에 배정한다.
- 유효한 전체 저장본을 우선 사용하고 실시간 조회는 날짜를 이유로 조기 종료하지 않는다. 제한에 도달하면 불완전 조회임을 표시한다.
- 질문에 명시된 고객사·매체·상태·추가 등록일 조건은 보존한다. 전달일 기간과 등록일 기간은 다른 필드다.
- 인증된 본인과 서버가 보관한 후속 조건만 이어받는다. LLM이 만든 숫자를 합계로 사용하지 않는다.

## 검증

월 경계·과거 등록/당월 전달·전달일 누락·타 담당자 공수·후속 질문·조회 상한·원문 재계산 회귀를 추가한다. 기존 결정형 전체 테스트 및 정적 검사를 실행하고 설정된 회사 모델과 실제 데이터로 읽기 전용 확인을 수행한다.
