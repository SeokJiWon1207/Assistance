# Mantis 전체 원본 운영

내 업무, 팀 대시보드, Mantis 페이지 검색과 구조화 검색은 같은 연결의 유효한 전체 원본이 있으면 먼저 사용한다. API의 앞 600/800/1,000건으로 전체 업무를 집계하지 않는다. 화면의 표시 개수만 별도로 제한한다.

## 최초 동기화

저장소 루트에서 실행한다. Mantis 조회와 로컬 SQLite 쓰기만 수행하며 LLM·임베딩 서비스는 호출하지 않는다.

```bash
assistant_web/.venv/bin/python assistant_web/scripts/sync_mantis_store.py
```

저장 파일은 `ASSISTANT_RUNTIME_DIR` 아래 `mantis_complete.sqlite3`이다. 기본 경로는 `assistant_web/runtime/`이며 Git에서 제외된다. 인증 토큰은 저장하지 않고 연결 지문으로 계정을 구분한다. 읽기 권한은 API 연결 계정의 범위와 같다.

전체 수집은 최대 3회 수행한다. 마지막 페이지까지 성공한 수집 두 번이 연속으로 같은 ID 집합을 반환하고 중복이 없을 때 최종 수집본으로 원자 교체한다. 단순한 내용 수정 때문에 동기화가 계속 실패하지 않도록 내용은 최종 수집 응답을 사용한다. 첫 수집의 중복이나 삭제에 따른 누락은 다음 수집과 비교해 재검증한다. 일시적인 통신 실패도 3회 예산 안에서 재시도한다.

계속 결과가 바뀌거나 전체 900초·수집당 1,000페이지 상한에 도달하면 이전 파일을 보존한다. API가 페이지 간 트랜잭션을 제공하지 않으므로 두 번의 일치가 원자적인 서버 스냅샷을 보장하지는 않는다.

## 주기적 갱신

Mantis API 주소와 토큰이 설정돼 있으면 앱 시작 후 백그라운드 동기화가 실행되고, 종료 후 30분 간격으로 반복된다. `.env`의 `MANTIS_COMPLETE_SYNC_ENABLED=false`로 끌 수 있다. 설정 변경 후에는 서버를 재시작한다. 여러 프로세스는 파일 잠금으로 수집을 중복 실행하지 않는다.

강제 새로고침은 저장본과 단기 API 캐시를 우회해 실시간으로 조회하고, 전체 원본이 있으면 백그라운드 전체 동기화도 요청한다. 실시간 조회의 범위가 제한돼 있으면 전체 집계 미확정으로 표시한다. 전체 수집을 사용자 요청 안에서 기다리지 않는다. 갱신 중인 저장본을 표시하는 화면은 10초마다 결과를 다시 확인한다.

조회 기준은 최종 확인에 사용한 수집의 **시작 시각**이다. 1시간이 지나면 검색과 업무 화면 모두 해당 저장본을 사용하지 않고 실시간 조회로 전환한다. 만료된 저장본만 남고 실시간 조회도 실패하면 오류를 표시하며 0건 집계나 오래된 집계를 반환하지 않는다. 제한된 API 조회에서 마지막 페이지를 확인하지 못하면 전체 조회 완료로 표시하지 않는다.

채팅 요청의 검색 단계는 같은 원본을 한 번 읽어 공유한다. 업무 집계는 읽기 전용으로 정규화한 캐시를 공유하고 개인 업무만 담당자 필터 이후 복사한다. 읽기 실패는 캐시하지 않는다. 화면의 데이터 시각은 `fetchedAt`이며, 서버가 지정하는 응답 재사용 기한 `cacheUntil`은 최대 60초와 원본 유효 기한 중 빠른 시각이다. 탭 이동은 이 기한 안에서 응답을 재사용한다.

조회 완료 판정은 검색 실행, 상위 N건 충족, 전체 범위 확인을 구분한다. 벡터 검색 상위 N건을 채워도 전체 건수·부재의 증거로 사용하지 않는다. 저장 필터의 짧은 마지막 페이지는 그 필터 범위만 완료이며, 첫 페이지가 가득 찼다면 미확인 범위를 경고한다.

## 확인과 한계

- 성공 결과에는 `count`, `fetchedAt`, `passes`, `status=complete`가 출력된다.
- 실패 시 스크립트는 종료 코드 1을 반환한다. 앱 로그의 `Mantis 전체 동기화 실패`도 확인한다.
- 프런트엔드의 데이터 기준 시각은 응답 생성 시각이 아닌 `fetchedAt`이다.
- 이 원본은 Chroma 의미 검색용 임베딩을 갱신하지 않는다. 의미 검색의 최신성은 기존 `scripts/make_vector_db.py` 작업으로 별도 관리해야 한다. 외부 모델로 내부 데이터를 보내는 배포에서는 연결 정책을 먼저 확인한다.
