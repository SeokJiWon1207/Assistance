# AI 비서 검증 질문 모음

이 문서는 팀원이 컨텐츠서비스 AI 비서를 테스트할 때 사용할 질문 예시와, 각 질문이 무엇을 검증하는지 정리한 문서입니다.

복합 조건과 연속 대화 중심의 추가 질문은 [`test_scenario_questions.md`](./test_scenario_questions.md)를 참고합니다.

검증 결과는 단순히 점수가 높고 낮은지만 보지 말고, 아래 기준으로 해석합니다.

- 정확 조회형: ID, 고객사, 담당자, 화면번호, 상태, 날짜처럼 조건이 명확하면 높은 점수가 나와야 합니다.
- 분석형: 원인 분석, 중요도 판단, 우선순위 추천처럼 모델 해석이 개입되면 `검토 필요`가 나올 수 있습니다.
- 애매한 질문: "최근", "중요한", "심각한", "늦어진"처럼 기준이 모호하면 검색 기준이 어떻게 잡혔는지 확인해야 합니다.
- Notion 질문: Notion DB의 제목, 상태, 담당, 기한, 수정일 기준으로 제대로 필터링되는지 봅니다.
- Mantis 질문: Mantis 원본 필드와 커스텀 필드가 근거로 표시되는지 봅니다.

| `고객사요청일 2026-04-27 관련 이슈 3개 보여줘` | Mantis 날짜 커스텀 필드 | 고객사요청일이 2026-04-27인 이슈가 나와야 함 | 날짜 커스텀 필드 검색과 날짜 포맷 변환 검증입니다. |

| `KB증권 HTS 이슈 원인 정리해줘` | 원인 분석 | 관련 이슈를 근거로 요약하되 검토 필요가 나올 수 있음 | 원인은 원본 필드가 아니라 모델 추론이므로 100점 검증 대상이 아닙니다. |

| `이번 달에 가장 심각한 이슈가 뭐야?` | 중요도 판단 | 심각도 기준을 먼저 밝히거나 추가 조건을 요구해야 함 | "심각한" 기준이 없으면 낮은 신뢰도가 정상입니다. |
| `고객 영향도가 큰 유안타 MTS 이슈만 뽑아줘` | 영향도 판단 | 고객 영향도 기준이 모호하다고 설명하거나 근거 기반 후보만 제시 | 영향도 필드가 없으면 추론 결과로 봐야 합니다. |
| `하이투자증권 이슈가 왜 자주 발생하는지 분석해줘` | 경향 분석 | 기간/대상/분류 기준을 명시하고 분석 | "자주" 기준이 불명확하므로 검증 점수가 낮을 수 있습니다. |

## 9. 고도화 확인용 질문

| 질문 | 용도 | 기대 결과 | 해석 |
| --- | --- | --- | --- |
| `KB증권 HTS 이슈 흐름 분석해줘` | 스타일 옵션 확인 | 답변 스타일이 자세히이면 배경/근거/다음 액션이 포함 | 단순 목록만 나오면 답변 스타일 적용 범위를 점검합니다. |
| `KB증권 HTS 이슈를 표로 정리해줘` | 표 스타일 | 이슈 ID, 제목, 상태, 담당자, 등록일 형태 표 | 출력 형식 옵션은 제거했으므로 자연어 요청으로 처리되는지 봅니다. |
| `노션에서 결재요청 상태인 항목을 담당자별로 정리해줘` | Notion 집계 | 담당자별 또는 상태별로 묶인 결과 | Notion 속성 파싱과 그룹핑 품질을 봅니다. |
| `Mantis와 Notion에서 KB증권 관련 내용을 같이 찾아줘` | 통합 검색 | Mantis 이슈와 Notion 항목이 분리 표시 | 출처가 섞이지 않고 명확히 표시되어야 합니다. |
| `이 답변의 근거와 검증 결과를 설명해줘` | 검증 설명 | 어떤 소스/필드/계산으로 답했는지 표시 | 감사 로그와 검증 카드가 의미 있게 나오는지 봅니다. |

## 결과 해석 가이드

### 높은 점수가 나와야 하는 경우

- 이슈 ID가 정확히 들어간 질문
- 고객사, 화면번호, 담당자, 상태, 날짜 필드가 명확한 질문
- 월별 건수나 공수처럼 원본 필드를 합산하는 질문
- Notion 제목을 따옴표로 정확히 지정한 질문

### 낮은 점수 또는 검토 필요가 정상인 경우

- 원인, 중요도, 심각도, 고객 영향도처럼 원본에 명시되지 않은 판단 질문
- "최근", "많이", "자주", "중요한"처럼 기준이 불명확한 질문
- Notion 문서 요약처럼 모델이 본문을 재구성하는 질문
- Mantis와 Notion을 함께 보고 결론을 내리는 종합 분석 질문

### 실패로 봐야 하는 경우

- 정확 ID 질문에서 다른 이슈가 나오는 경우
- 고객사 별칭이 명확한데 0건이 나오는 경우
- 상태 조건이 있는데 다른 상태가 섞이는 경우
- 일반 질문에 관련 이슈 카드가 붙는 경우
- 요청한 건수보다 적게 나오면서 이유 설명이 없는 경우

## 추천 테스트 순서

1. 정확 ID 조회 2개를 먼저 실행해 기본 연결을 확인합니다.
2. 고객사 별칭 질문으로 매핑 품질을 확인합니다.
3. 담당자/화면번호/상태/날짜 필드 질문으로 필터링을 확인합니다.
4. Notion 질문으로 두 DB가 모두 검색되는지 확인합니다.
5. 분석형 질문으로 검증 결과가 무리하게 100점 처리되지 않는지 확인합니다.
6. 일반 질문으로 불필요한 관련 이슈 표시가 없는지 확인합니다.
