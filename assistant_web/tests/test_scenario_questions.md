# AI 비서 확장 시나리오 질문 모음

이 문서는 [`test_questions.md`](./test_questions.md)의 기본 검증 질문을 보완하는 탐색형 테스트 모음입니다.
정확한 이슈 ID를 외우고 확인하는 방식보다, 실제 사용자가 여러 조건을 섞거나 앞선 답변을 이어서 묻는 상황을 중점적으로 다룹니다.

데이터는 계속 변하므로 특정 ID보다 아래 항목을 우선 확인합니다.

- 질문에 명시한 고객사·플랫폼·담당자·상태·날짜 조건이 빠지지 않았는가
- 건수 질문과 목록 질문을 구분했는가
- 근거가 부족할 때 추측하지 않고 기준 또는 한계를 설명하는가
- 후속 질문이 직전 답변의 대상과 조건을 올바르게 이어받는가
- Mantis와 Notion 결과의 출처를 섞지 않는가

## 1. 자연어 표현과 오타 변형

| 질문 | 검증 목적 | 확인할 내용 |
| --- | --- | --- |
| `케이비 증권 모바일 이슈 좀 찾아줘` | 고객사·플랫폼 구어체 | KB증권과 MTS로 해석하는지 확인합니다. |
| `한투 HTS쪽 최근 문제 뭐 있었어?` | 약칭과 구어체 | 한국투자증권 HTS 이슈만 조회되는지 봅니다. |
| `신한투자증권 엠티에스 이슈 세 개만` | 한글 음차 플랫폼 | MTS와 요청 개수 3개가 반영되어야 합니다. |
| `유안타증권 종료 안 된 건 보여줘` | 부정형 상태 | 종료 이슈가 제외되고 열린 상태만 나와야 합니다. |
| `노션에서 결제요청 상태 찾아줘` | 유사 오타 | 문맥상 `결재요청`으로 보정하거나 보정 사실을 설명해야 합니다. |
| `맨티스에서 차트 멈춤 관련건 검색해 줘` | 소스명 음차 | Notion이 아니라 Mantis를 조회해야 합니다. |
| `CAPE 증권 최근껀 뭐야` | 띄어쓰기 변형 | CAPE증권 고객사 조건을 유지해야 합니다. |
| `담당자가 DRFN_NEXT 인 이슈 보여줘` | 영문·기호 담당자 | 담당자명을 기술 키워드나 고객사로 오해하지 않아야 합니다. |

| `화면번호 7600 이슈 중 closed가 아닌 것만 찾아줘` | 화면번호+부정 상태 | 화면번호 정확 일치와 열린 상태가 함께 적용되어야 합니다. |

| `KB증권 이슈 중 제목에 로그인은 있지만 비밀번호는 없는 건 찾아줘` | 포함·제외 키워드 | 포함 조건과 제외 조건을 구분하는지 봅니다. |
| `상태가 confirmed 또는 assigned인 한투 MTS 이슈 보여줘` | 복수 상태 | 두 상태 중 하나인 결과만 표시되는지 확인합니다. |
| `노션 주요이슈현황에서 보관됨이 아닌 항목만 보여줘` | Notion 부정 상태 | 선택한 DB와 제외 상태가 모두 유지되어야 합니다. |

| `이번 달 유진증권 이슈를 등록일 순으로 보여줘` | 월 범위+정렬 | 이번 달 경계와 등록일 정렬을 확인합니다. |

| `2025년 12월 31일부터 2026년 1월 2일까지 등록된 이슈 보여줘` | 연도 경계 | 양쪽 날짜가 포함되는지 확인합니다. |
| `2026년 2월에 등록된 이슈 수 알려줘` | 윤년이 아닌 2월 범위 | 종료일을 2월 28일로 계산해야 합니다. |
| `고객사요청일은 지난달인데 등록일은 이번 달인 이슈 찾아줘` | 서로 다른 날짜 필드 | 등록일과 커스텀 날짜를 혼동하지 않아야 합니다. |
| `노션에서 이번 주 기한인 항목을 기한순으로 정리해줘` | Notion 주간 범위 | 주간 경계와 기한 정렬이 적용되어야 합니다. |
| `스냅샷 기준일 이후에 생긴 이슈가 있는지 확인해줘` | 데이터 신선도 | 스냅샷 기준일과 실시간 조회 범위를 설명해야 합니다. |

## 4. 건수·목록·정렬·집계 구분

| `신한투자증권 이슈가 총 몇 건인지 알려줘` | 전체 건수 | 화면에 표시한 일부 목록 길이를 총 건수로 답하지 않아야 합니다. |
| `신한투자증권 이슈 5개만 보여줘` | 제한 목록 | 총 건수 계산 대신 최신 5개 목록을 보여줘야 합니다. |
| `고객사별로 열린 이슈 수를 정리해줘` | 그룹 집계 | 고객사별 건수와 집계 기준을 표시해야 합니다. |
| `상태별 이슈 개수를 많은 순서로 보여줘` | 상태 그룹+내림차순 | 상태별 그룹과 정렬이 모두 맞아야 합니다. |
| `2026년 월별 이슈 건수 추이를 알려줘` | 월별 시계열 | 1월부터 현재 또는 12월까지의 범위를 명시해야 합니다. |
| `담당자별 공수 합계를 큰 순서대로 보여줘` | 담당자별 공수 집계 | 동일 담당자의 여러 공수 필드를 합산해야 합니다. |
| `작년에 공수를 기록한 사람을 모두 보여줘` | 전체 명단 | 임의 상위 N명으로 자르지 말고 전체 여부를 설명해야 합니다. |
| `가장 최근 이슈와 가장 오래된 이슈를 하나씩 보여줘` | 양방향 정렬 | 같은 결과를 반복하지 않고 정렬 방향을 구분해야 합니다. |
| `고객사별 최근 이슈를 하나씩 보여줘` | 그룹별 상위 1개 | 전체 최신 목록이 아니라 각 고객사 그룹에서 하나씩 선택해야 합니다. |
| `노션 결재요청 항목을 담당자별 건수로 정리해줘` | Notion 그룹 집계 | 담당자 미지정도 별도 그룹으로 처리하는지 봅니다. |

## 5. 대화형 후속 질문 시나리오

아래 항목은 각 시나리오의 질문을 같은 대화에서 순서대로 입력합니다.

### 시나리오 A — 목록에서 단일 이슈로 좁히기

1. `KB증권 HTS 최근 이슈 5개 보여줘`
2. `그중 두 번째 이슈를 자세히 설명해줘`
3. `그 이슈의 담당자와 상태만 다시 알려줘`
4. `비슷한 과거 이슈도 찾아줘`

확인할 내용:

- `그중 두 번째`가 직전 화면의 두 번째 결과를 가리켜야 합니다.
- 상세 조회 뒤에도 같은 이슈 ID가 유지되어야 합니다.
- 유사 이슈 검색에서 기준 이슈 자체는 결과에서 제외되어야 합니다.

### 시나리오 B — 조건 유지와 조건 변경

1. `신한 MTS 최근 이슈 5개 보여줘`
2. `종료된 건은 빼줘`
3. `이번에는 HTS로 바꿔줘`
4. `두 플랫폼 결과 수를 비교해줘`

확인할 내용:

- 고객사 조건은 계속 유지되어야 합니다.
- 2단계의 열린 상태 조건과 3단계의 플랫폼 변경을 구분해야 합니다.
- 마지막 비교에서 MTS와 HTS의 기준 기간·상태를 명시해야 합니다.

### 시나리오 C — 기간을 좁혀 건수 확인

1. `유진증권 2026년 이슈 보여줘`
2. `그중 4월 것만 남겨줘`
3. `총 몇 건이야?`
4. `최근 3개만 제목과 담당자로 정리해줘`

확인할 내용:

- 연도 조건을 유지한 채 4월 범위로 좁혀야 합니다.
- 3단계는 전체 매칭 건수, 4단계는 제한된 목록이어야 합니다.

### 시나리오 D — Notion 문서 후속 조회

1. `노션에서 결재요청 상태인 항목 보여줘`
2. `담당자별로 묶어줘`
3. `담당자 미지정 항목만 다시 보여줘`
4. `첫 번째 항목의 내용을 요약해줘`

확인할 내용:

- 후속 질문 중 Mantis로 소스가 바뀌지 않아야 합니다.
- 동일 제목의 Notion 페이지가 있어도 페이지 ID가 다르면 임의로 합치지 않아야 합니다.

### 시나리오 E — 정확 ID에서 이력과 유사 사례로 확장

1. `0030918 이슈 내용을 알려줘`
2. `이 이슈의 처리 이력을 시간순으로 정리해줘`
3. `핵심 해결 내용을 한 문장으로 요약해줘`
4. `이 이슈와 비슷하지만 다른 고객사 사례를 찾아줘`

확인할 내용:

- 모든 단계에서 기준 이슈 #30918을 유지해야 합니다.
- 이력에 없는 원인이나 해결책을 만들어내지 않아야 합니다.
- 마지막 단계에서는 원 고객사를 검색어로 강제하지 않아야 합니다.

## 6. Mantis·Notion 교차 검색

| 질문 | 검증 목적 | 확인할 내용 |
| --- | --- | --- |
| `Mantis와 Notion에서 로그인 장애 관련 내용을 함께 찾아줘` | 양쪽 소스 검색 | 결과를 소스별로 구분해야 합니다. |
| `노션 공지와 Mantis 장애 이력을 함께 비교해줘` | 문서·이슈 비교 | 공지와 실제 이슈를 같은 종류의 레코드처럼 섞지 않아야 합니다. |
| `KB증권 관련 내용을 Mantis와 Notion에서 각각 3개씩 보여줘` | 소스별 개수 제한 | 한쪽 결과가 6개가 되는 식으로 개수를 합치지 않아야 합니다. |
| `Mantis의 최근 장애와 관련된 Notion 회의 자료가 있는지 찾아줘` | 단계적 교차 검색 | 연결 근거가 제목·키워드인지 명시해야 합니다. |
| `양쪽 소스에서 공통으로 자주 나오는 고객사를 정리해줘` | 교차 집계 | 데이터 범위와 공통 기준을 먼저 밝혀야 합니다. |
| `Notion에는 있지만 Mantis에서는 찾지 못한 KB증권 항목을 알려줘` | 차집합 | 정확 일치가 어려우면 비교 방식을 설명해야 합니다. |

## 7. 결과 없음과 오류 대응

| 질문 | 검증 목적 | 확인할 내용 |
| --- | --- | --- |
| `존재하지않는증권사123 최근 이슈 보여줘` | 미등록 고객사 | 다른 고객사 결과를 억지로 보여주지 않아야 합니다. |
| `화면번호 99999999 관련 이슈 찾아줘` | 비정상 화면번호 | 유사 숫자 이슈를 정확 일치 결과로 제시하지 않아야 합니다. |
| `2099년 1월에 등록된 이슈는 몇 건이야?` | 미래 기간 | 0건 또는 데이터 범위 밖임을 명확히 알려야 합니다. |
| `이슈 번호 0000000 자세히 알려줘` | 존재하지 않는 ID | 가장 비슷한 ID를 임의로 대신 조회하지 않아야 합니다. |
| `노션에서 완전히없는문서제목XYZ 찾아줘` | Notion 결과 없음 | Mantis로 자동 전환하지 않고 Notion 0건을 설명해야 합니다. |
| `Mantis 토큰이 없을 때 최근 이슈 보여줘` | 연동 오류 메시지 | 설정 누락과 결과 0건을 구분해서 안내해야 합니다. |
| `2026년 13월 이슈 보여줘` | 잘못된 날짜 | 잘못된 월을 조용히 다른 날짜로 바꾸지 않아야 합니다. |
| `최근 이슈 -5개 보여줘` | 잘못된 개수 | 유효한 개수를 요청하거나 안전한 기본값을 설명해야 합니다. |

| `처리가 늦은 이슈 찾아줘` | 지연 기준 부재 | 목표일 초과·장기 미종료 등 판단 기준을 밝혀야 합니다. |
| `담당자 성과를 비교해줘` | 민감한 평가 | 단순 공수·처리 건수를 성과 전체로 단정하지 않아야 합니다. |
| `최근 장애 원인이 뭐야?` | 대상 불명확 | 고객사·플랫폼·기간을 요청하거나 선택한 범위를 설명해야 합니다. |
| `저번에 본 그 이슈 다시 보여줘` | 대화 근거 부재 | 현재 대화에 기준 이슈가 없으면 정확한 ID나 조건을 요청해야 합니다. |

## 9. 출력 형식과 근거 표시

| 질문 | 검증 목적 | 확인할 내용 |
| --- | --- | --- |
| `최근 이슈 5개를 ID, 고객사, 상태, 담당자 표로 만들어줘` | 표 형식 | 열이 빠지지 않고 한 이슈가 한 행에 표시되어야 합니다. |
| `KB증권 이슈를 한 줄씩만 요약해줘` | 간결한 형식 | 근거 ID를 유지하면서 설명을 불필요하게 늘리지 않아야 합니다. |
| `검색 결과를 고객사별 제목 목록으로만 보여줘` | 그룹형 목록 | 고객사 그룹과 제목이 정확히 대응되어야 합니다. |
| `이번 답변에서 적용한 검색 조건을 JSON으로 보여줘` | 실행 조건 투명성 | 실제 적용한 고객사·상태·날짜·개수와 일치해야 합니다. |
| `각 결론 옆에 근거 이슈 ID를 붙여줘` | 근거 연결 | 존재하지 않는 ID를 생성하지 않아야 합니다. |
| `답변과 함께 데이터 기준일도 알려줘` | 신선도 표시 | 로컬 스냅샷 또는 실시간 조회 기준일을 구분해야 합니다. |

## 판정 가이드

### 통과

- 모든 명시 조건이 실행 계획과 결과에 반영됩니다.
- 목록과 건수, 등록일과 커스텀 날짜, Mantis와 Notion을 구분합니다.
- 후속 질문에서 직전 대상과 변경된 조건을 정확히 추적합니다.
- 결과가 없거나 기준이 모호할 때 한계를 솔직하게 설명합니다.

### 부분 통과

- 핵심 결과는 맞지만 정렬, 표시 개수, 근거 또는 기준일 설명이 일부 빠집니다.
- 분석형 질문에서 합리적인 기준을 밝혔지만 사용자가 의도한 기준과 다를 수 있습니다.

### 실패

- 질문의 고객사·플랫폼·상태·날짜 조건 중 하나 이상을 무시합니다.
- 일부 표시 결과의 개수를 전체 건수로 답합니다.
- 직전 대화와 무관한 이슈를 `그 이슈`라고 지칭합니다.
- 결과가 없는데 유사한 다른 데이터로 답을 꾸밉니다.
- Mantis 결과를 Notion 근거로, 또는 Notion 결과를 Mantis 근거로 표시합니다.
