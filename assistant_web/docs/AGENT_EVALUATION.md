# 하네스 평가 기준선과 운영 전환 기준

2026-11-09 기준. 제품의 조건·권한·근거·수치 검증은 그대로 유지한다. 이 문서는 평가기의 판정과 운영 전환에 필요한 증거를 정의한다. 평가 구현은 `scripts/accuracy/benchmark.py`, `benchmark_outcomes.py`, `benchmark_observation.py`, `benchmark_provenance.py`다.

## 전달 성공과 요청 완료

`agent_plan_clarification`과 `unified_plan_clarification`은 모두 확인 질문이다. `delivered`는 실패하고 `clarify` 기대값만 통과한다. 올바른 확인 질문을 요구한 문항의 정답률은 통과할 수 있지만 업무 완료율에는 포함하지 않는다. 정책 거절·검증 차단·취소·오류·미실행도 완료가 아니다. 계획 수립 실패가 확인 질문으로 표현된 경우도 확인 질문 비율에 포함하고 원래 종료 사유를 함께 보존한다.

응답을 전달했더라도 `requirements` 중 하나라도 실패하거나 미확인이면 부분 완료다. 실패 후 실행하지 못한 후속 질문도 예정 요청 수와 항목 수의 분모에 남긴다. 문항 전체 통과는 모든 턴의 기존 기대값과 모든 요청 항목을 충족해야 한다. 정상 0건은 전체 조회가 완료됐다는 수치 증명으로 검사한다. 부분 조회를 0건으로 채점하지 않는다.

```json
{
  "question": "한투 미해결 건수와 최근 3건을 알려줘",
  "expect": [{"type": "delivered"}, {"type": "plan", "customer": "한투", "statuses": ["open"]}],
  "requirements": [
    {"id": "count", "label": "전체 건수", "expect": [{"type": "count", "value": 5}]},
    {"id": "list", "label": "표시 목록과 후속 순서", "expect": [
      {"type": "displayed_issue_ids", "ids": [31659, 29186, 28764]},
      {"type": "followup_issue_ids", "ids": [31659, 29186, 28764]}
    ]}
  ]
}
```

숫자·ID 예시는 당시 저장본의 개발 사례다. 다른 저장본에서는 독립 SQL로 정답을 다시 확정한다. `issue_ids`는 출처 집합/순서, `displayed_issue_ids`는 실제 본문의 번호 목록, `followup_issue_ids`는 해당 사용자 감사 기록에 저장한 후속 목록을 각각 검사한다. 출처 카드 순서를 화면의 목록 순서로 추측하지 않는다. 표시 ID 파서는 현재 제품의 `1. #ID`, `- #ID` 형식을 지원한다. 다른 표시 형식은 통과로 추측하지 않고 파서를 검증한 뒤 지원한다. `groups`는 서버 집계 결과와 실제 표의 그룹별 숫자를 모두 독립 정답과 대조한다.

## 본문 읽기와 근거 관련성

두 지표를 따로 기록한다.

| 지표 | 통과 근거 |
|---|---|
| `current_body` | 이번 요청의 `get_notion_page_content` 성공, 현재 본문 확인, 서버의 본문 수집 완료, 반환 텍스트 존재 |
| `evidence_relevance` | 위 본문이 최종 출처에 남고, 사전에 고정한 해당 본문 버전의 독립 판정이 요구 수준을 충족 |

제목 일치, 검색 후보, 저장본 힌트, 제품의 `guide=true` 또는 모델 자신의 관련성 주장은 독립 판정이 아니다. 관측기는 원문을 중복 저장하지 않고 페이지 ID, 수정 시각, 반환 텍스트 SHA-256, 반환 길이·시작 위치·잘림 여부를 남긴다. 서버가 본문 수집을 마쳤어도 모델에 전달한 텍스트는 일부일 수 있으므로 잘림 여부를 별도로 확인한다. `body_sha256`은 **도구에 반환한 텍스트**의 해시다.

판정 자료는 `page_id`, `body_sha256`, `level`, `reason`을 가진다. `irrelevant`는 질문과 무관, `related`는 같은 화면·주제의 참고자료, `direct`는 질문한 기능·절차·사실을 직접 뒷받침하는 자료다. 기본 `body_scope=excerpt`는 기존 반환 텍스트 해시와 정확히 맞아야 한다.

전체 원문을 심사한 판정은 `body_scope=page`, 전체 원문의 `body_sha256`, `body_chars`, 실제 근거인 `supporting_ranges=[{"start":120,"end":240}]`를 지정한다. 관련/직접 판정에는 근거 구간이 필수이며 시작 포함·끝 제외 문자 위치다. 관측의 `page_body_sha256`, `page_body_chars`, `page_body_verified`는 현재 원장 본문과 실제 반환 구간을 대조한 값이다. 원문 버전이 같아도 필요한 구간을 전달받지 않았으면 통과하지 않는다. 여러 번 읽은 연속 구간은 합칠 수 있지만 중간에 빠진 구간은 덮어 읽었다고 간주하지 않는다. 빈 본문·미완료 본문은 읽기 완료로 인정하지 않는다.

새 관측은 도구 실행 결과를 즉시 읽기 증명으로 올리지 않는다. 공통 마스킹·최종 길이 제한을 통과한 메시지의 해시를 만들고, 성공한 모델 HTTP 요청에 그 도구 메시지가 실제 포함됐을 때 `delivery_verified=true`로 기록한다. 본문이 최종 직렬화에서 제거되거나 모델 요청에 포함되지 않으면 읽기 근거로 집계하지 않는다. 메시지 원문은 관측 로그에 저장하지 않는다. 최종 길이 조절이 본문을 더 줄이면 `next_offset`도 실제 전달 끝에 맞추므로 이어 읽기에서 빈 구간을 건너뛰지 않는다. 이 관측 이전의 과거 기록에는 실제 최종 전달 구간 증명이 없다는 한계를 별도로 표시한다.

`evidence_diagnostics`는 `supported`(근거 충족), `insufficient_relevance`(판정된 문서의 직접성/관련성 부족), `unassessed_version`(독립 판정 없음), `support_not_read`(판정된 근거 구간 미열람), `body_not_read`/`body_empty`/`body_incomplete`(본문 조회 부족), `source_not_retained`(최종 근거에서 제외)를 구분한다. 본문 미완료는 원천의 `content_incomplete_reasons`도 보존한다. 미판정은 `unassessed`로 남겨 완료에 포함하지 않는다. 관련 참고자료만 읽었다면 직접 가이드 확보는 실패다. 이것으로 문서 자체가 없다고 결론 내리지 않는다.

현재 버전은 사전 판정 자료가 있는 고정 문항 평가다. 모든 문서의 의미를 자동 판정하는 심사 모델을 추가한 것은 아니다. 새 문서·새 원문은 답변을 보지 않은 검토자가 판정하고, 새 문항 버전으로 별도 재평가해야 한다. 본문 관련성 통과 자체가 답변의 모든 서술이 정확하다는 뜻은 아니며 기존 사실·인용 검증도 계속 필요하다.

평가 자료를 확대한 효과와 제품 검색의 효과를 구별한다. 과거 실행의 원문 버전을 복원할 때는 저장된 감사 원문에서 같은 시작 위치·길이로 잘라 기존 발췌 SHA가 일치하는 경우만 사용한다. 과거 응답·실제 전달 구간은 변경하지 않는다. 사후 판정은 기존 실행 manifest나 사전 점수를 덮어쓰지 않고 별도 재채점으로 보존한다. 검색 누락은 실제로 존재하고 접근 가능한 직접 근거를 확인했는데 해당 실행이 놓친 경우에만 판정한다.

## 비용과 지연

전용 벤치마크 프로세스에서 `requests.Session.send`를 관측한다. 앞단 계획, 에이전트, 보고서 내부 모델 호출, 재시도, 대체 모델, 보정과 최종 검토를 포함한 실제 모델 HTTP 시도를 센다. 논리 도구 실행 수와 원천 HTTP 요청 수는 따로 기록한다. 도구 실패·네트워크 예외도 시도 수에 포함한다. 하네스 내부 호출 통계도 기존대로 함께 남겨 누락 여부를 비교한다.

입력·캐시 읽기·캐시 쓰기·출력 토큰, 사용량 미보고 호출, 단가 미등록 호출을 보존한다. 사용량이나 단가가 없으면 금액은 `null`/미산정이며 0으로 대체하지 않는다. 사용량이 있는 부분의 비용만 `known_subtotal`로 남긴다. 캐시 읽기와 쓰기는 전체 입력에서 각각 빼고 해당 단가로 한 번만 계산한다. 가격은 다음 형식의 **실제 계약/공식 단가**를 `run --prices`로 제공한다.

```json
{"currency": "USD", "as_of": "YYYY-MM-DD", "source": "계약서 또는 공식 가격표의 출처", "models": {
  "모델 ID": {"input_per_million": 0, "cached_input_per_million": 0, "output_per_million": 0}
}}
```

위 0은 형식 예시이며 실제 단가가 아니다. 단가 파일을 생략하면 금액을 산정하지 않는다. 로컬 임베딩 HTTP는 현재 원천 HTTP에 포함된다. 이 계측은 모델 토큰 비용이며 서버·스토리지·로컬 임베딩 인프라 비용을 계산하지 않는다. 다른 전송 클라이언트를 도입하면 관측 경계를 먼저 확장해야 한다.

공식 Luna 단가 예시는 `scripts/accuracy/prices/openai-luna-2026-11-09.json`에 있다. 표준 처리·입력 272,000토큰 이하·글로벌 API에 한정하며 실제 응답의 처리 등급을 대조한다. 캐시 쓰기 단가가 있는 모델은 쓰기 사용량 미보고를 0으로 추측하지 않는다. 요청의 기본 30분 TTL과 보고된 30분/12시간 쓰기 내역을 구분한다. 가격 구간·처리 등급·엔드포인트·사용량이 맞지 않으면 사유별 미산정 호출로 남긴다. 평균·nearest-rank p95 요청 비용은 모든 요청 비용이 확인된 경우에만 계산한다. 장애로 Gemini를 사용했지만 해당 단가가 없다면 총비용도 미산정이다.

여러 고객사의 고정 평가 문항은 `benchmark_matrix.py`가 만든다. 정답 계산은 제품의 필터 함수와 분리해 원본 프로젝트 ID·명시적인 미해결 상태·UTC 생성 시각과 동률 ID 순서를 사용한다. 미지 상태나 잘못된 생성 시각은 정답 생성 오류다. 복합 조회 뒤 순번 질문, 이어서 고객사만 변경하는 질문으로 적용 조건과 이전 이슈 ID 제거를 검사한다. 고객사와 질문 유형별로 나누어 보고하며 반복 횟수를 독립 문항 수로 세지 않는다.

질문의 고객사 표기와 실행 계획의 정규 키는 별도로 고정한다. 예를 들어 표시명 `KB`의 계획 기대값은 `kb`다. 잘못 만든 기대값이 발견되면 기존 실행을 예비 실행으로 보존하고 새 문항 버전으로 재측정한다. 답변의 실제 오답을 기대값으로 바꾸지 않는다.

승인이 특정 원문 범위에 한정된 실측에서는 `benchmark_scope.approved_mantis_issues`로 승인 ID를 고정한다. 조회 결과나 집계 모집단이 승인 범위를 벗어나면 원장 게시 전에 예외를 내며, 내부 모델 호출이 있는 보고서 도구도 이 문항 범위에서는 실행하지 않는다. 조회 조건을 승인 목록으로 자동 교체하거나 틀린 결과를 제거해 정답으로 만들지 않는다. 차단된 턴과 실행할 수 없는 후속 턴은 실패 분모에 남는다. 이 장치는 전용 평가 프로세스의 추가 전송 보호이며 운영 제품의 조건 승계 문제를 해결한 것은 아니다. 순차와 병렬에 동일하게 적용하고 차단 횟수와 사용량을 따로 보고한다.

지연은 `ChatService.build_response`의 시작부터 반환/오류까지의 경과 시간이다. 신선도 검사·평가 파일 저장은 제외하고 내부 재시도·대기·검토는 포함한다. 성공·확인 질문·차단·오류 모두 측정하며, 실행하지 못한 턴은 지연 표본에는 없지만 완료율 분모에는 남긴다. 브라우저 전송·렌더링·첫 토큰 시간은 이 수치에 포함되지 않는다. 분류별 n·평균·중앙값·nearest-rank p95를 제공한다. 3회 반복의 p95는 최댓값이므로 운영 SLO 증거로 사용하지 않는다.

## 재현성과 최신성

- 코드의 Git HEAD뿐 아니라 수정·추가된 Python 코드, 모델/고객사 설정의 파일별 해시를 고정한다. 비밀값은 기록하지 않는다.
- 문항, 가격표, 공개 실행 설정, Mantis/Notion 저장본과 인덱스 해시, 실행 날짜와 시작/종료 시각을 기록한다. 날짜 조건은 실행 날짜에 결속한다.
- 실행용 저장본은 SQLite backup으로 복제한 뒤 격리한다. 반복마다 동일 초기 저장본에서 새 프로세스·감사 DB를 사용한다. 로컬 색인 외 Notion 원문은 현재 API로 검증하므로 반환 본문 해시와 수정 시각을 함께 본다.
- 실행 전과 각 요청 전후 Mantis·Notion 최신성을 확인한다. 만료되면 중단/환경 불량으로 기록하고 정상 기준선 채점을 거절한다. TTL을 늘려 유효한 실행으로 만들지 않는다.
- 실행 중 코드·설정 또는 Mantis 저장본이 바뀌면 무효다. Notion 본문 캐시는 실제 읽기로 갱신될 수 있으며 읽은 버전을 개별 증명으로 남긴다.
- 다른 문항 파일로 사후 채점하거나 기존 실행 폴더를 덮어쓰지 못한다. 구현에 사용한 문항은 `dev`, 새로운 최종 평가 문항은 `final`로 분리한다. 동일 질문 반복은 변동성 관측이며 독립 문항 수를 늘리지 않는다.

## 운영 적용 판정 기준

제한 병렬 실행을 비교할 때는 동일 코드·초기 저장본·문항·모델 허용 정책에서 `AGENT_MAX_CONCURRENT_TOOLS`만 1과 2로 바꾼다. 순서를 교차하고 설정 상한과 실제 병렬 묶음 수(`parallelGroups`), 최대 동시 실행 수(`maxConcurrentTools`)를 함께 기록한다. 한 번의 도구 응답에 여러 호출이 있다는 사실만으로 병렬 실행을 주장하지 않는다. 저장본 검색 스트림의 잠금으로 원천 계산이 직렬화될 수 있으며, 모델이 선택한 탐색 경로도 달라지므로 소표본의 응답 시간 차이를 병렬화만의 효과로 확정하지 않는다. 논리 도구 시도·원천 HTTP·내부 단계 시간 합계·사용자가 기다린 경과 시간은 각각 구분한다.

다음은 기능별 적용 목표다. 모든 필수 항목을 통과해야 해당 기능의 적용 범위를 넓힌다. 이번 3회 반복은 기준선이며 운영 통과 판정이 아니다.

| 기준 | 적용 조건 |
|---|---|
| 표본 | 기능별 서로 다른 final 요청 100개 이상, 고객사 3곳 이상, 표현 3종 이상, 후속 대화 20개 이상. 0건·부분 조회·대량 결과·원천 장애·권한 거절·취소 포함 |
| 관찰 기간 | 제한 적용 상태에서 연속 7일 이상, 기능별 실사용 100요청 이상. 기간과 표본을 모두 충족 |
| 조건·숫자·목록 | 독립 정답이 있는 건수·ID·순서·그룹 집계 100% 일치. 부분 조회를 0건/전체 완료로 표현한 사례 0건 |
| 근거·보안 | 권한·전송 정책 위반, 검증 우회, 철회된 근거 재사용 0건. 기존 최종 검증의 전송 허용 조건 충족. warning은 항목별로 보고하고 근거 부족을 완수로 승격하지 않음 |
| 요청 완수 | 요청 항목 전체 완료율 95% 이상. 미확인은 실패와 함께 미완료에 포함 |
| 의미 관련성 | 직접 근거가 필요한 요청에서 독립 판정 direct 확보율 95% 이상. 읽기 성공률과 별도 보고 |
| 미완료/확인 질문 | 명확한 요청의 예상 밖 확인 질문 5% 이하, 오류·중단·부분 완료 합계 5% 이하. 의도적으로 확인/거절을 기대한 문항은 별도 층으로 보고 |
| 지연 | 기능별 n≥100에서 p95: 건수·목록·집계 30초 이하, 순번 후속 15초 이하, 복합 검색·설명 120초 이하. 기존 요청 마감 180초 유지 |
| 모델 비용 | 모든 모델의 출처 있는 단가 등록, 사용량 미보고·단가 미등록 0회. 고정 final 세트에서 **평균 및 p95 요청당 비용 모두 직전 채택 기준선의 120% 이하**. 첫 채택은 금액을 확정한 기준선이 필요하며 미산정이면 비용 기준 통과 불가 |
| 복귀 경로 | 기능별 활성화/복귀 가능. 기존 경로에서도 같은 권한·조건·수치·근거 계약을 통과. 검증 실패를 자유 서술로 우회 금지 |

기능은 건수, 목록, 집계, 복합 설명, 후속 조회로 나누어 판정한다. 이후 보고서 도구 확장에도 같은 기준을 기능별로 적용한다. 최초 노출은 해당 기능 대상 요청의 5%, 다음 25%, 마지막 100% 순서이며 각 확대 전에 위 표본·기간·품질 기준을 확인한다. 기능별 제어와 온라인 관측은 후속 운영 단계의 구현 범위다. 이번 작업에서 운영 플래그나 트래픽은 바꾸지 않는다.

정확성·권한·검증 우회가 한 건이라도 확인되면 해당 기능 확대를 중단하고 검증 계약이 같은 경로로 복귀한다. 품질·지연·비용은 최근 24시간의 기능별 100표본에서 기준 미달이면 확대 중단, 두 번 연속 일별 판정 미달이면 복귀한다. 표본이 부족하거나 금액/사용량이 미확인이면 통과를 선언하지 않는다. 검증에 막힌 답변은 복귀 후에도 검증 없이 전송하지 않는다. 기존 중복 경로 제거는 100% 적용 후 추가 7일 관찰을 통과한 기능에 한정한다.
