# 계정 생성과 첫 로그인

관리자는 관리자 센터의 사용자 초대 화면에서 이메일, 임시 비밀번호(8~128자), 권한을 지정해 계정을 만든다. 사용자에게 서비스 주소, 이메일(ID), 지정한 임시 비밀번호를 전달한다. 메일을 자동으로 발송하지 않는다.

사용자는 임시 비밀번호로 로그인한 뒤 현재 비밀번호와 새 비밀번호를 입력한다. 변경을 완료하기 전에는 채팅·업무·관리자 API에 접근할 수 없다. 페이지를 새로고침해도 비밀번호 변경 화면이 표시된다. 변경 완료 후에는 새 비밀번호로 다시 로그인한다.

기존 계정의 비밀번호나 로그인 절차는 바뀌지 않는다. 이미 등록된 이메일로 임시 비밀번호 계정을 다시 만들면 거절된다. 비밀번호를 잊었으면 기존 로그인 화면의 재설정 메일 기능을 이용한다. 재설정 메일로 비밀번호를 정했더라도 최초 변경 대상 계정은 로그인 후 변경 절차를 완료해야 한다.

비밀번호는 Firebase에만 전달하며 앱 사용자 DB에는 저장하지 않고 응답에도 포함하지 않는다. 새 계정에는 `passwordChangeRequired` 상태를 저장한다. 변경 시 현재 비밀번호를 확인하고 Firebase 세션을 폐기하며, 앱에서도 이전 인증 시각의 세션과 토큰을 차단한다.

사용자 DB는 시작 시 스키마 버전 1에서 2로 자동 마이그레이션된다. 기존 계정은 변경 대상에서 제외된다. 배포 전 사용자 DB를 백업하고, 구버전 코드로 롤백할 때는 버전 2 DB를 그대로 사용하지 말고 배포 절차에 따라 해당 백업도 복원해야 한다. 기존 초대 링크 API는 호환성을 위해 유지하지만 재초대로 비밀번호 변경 필요 상태를 해제하지 않는다.
