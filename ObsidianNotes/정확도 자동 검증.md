# 정확도 자동 검증

← [[00 Home]] · 관련: [[프로젝트 개요]] · [[Mantis 연동]] · [[Notion 연동]]

## 목적

`scripts/accuracy/dynamic_accuracy_check.py`가 실제 Mantis·Notion 데이터에서 재현 가능한 질문을 만들고, 실제 채팅 경로를 호출한 결과를 독립 스냅샷의 이슈 ID·제목·건수와 비교한다.

```bash
cd assistant_web
python3 scripts/accuracy/dynamic_accuracy_check.py --questions 10 --follow-up-scenarios 4
```

- 기본 질문 수: 10개
- 후속 질문 시나리오: 4개(대상 속성, 순번 참조, 조건 상속, Notion 문맥)
- 후속 질문은 통과한 1차 답변의 대화 이력과 `contextAuditId`를 이어받음
- 날짜별 시드를 사용하므로 같은 시드는 재현 가능하고 날짜가 바뀌면 표본이 달라짐
- 결과 위치: `runtime/accuracy_reports/accuracy-YYYYMMDD-HHMMSS.{json,md}`
- 팀 검증 질문: `assistant_web/tests/test_questions.md`
- 복합 시나리오: `assistant_web/tests/test_scenario_questions.md`

## 판정 모델

정확도와 연동 가용성을 분리한다. 외부 서비스 타임아웃을 검색 정확도 실패로 계산하지 않는다.

| outcome | 의미 | 정확도 분모 포함 |
| --- | --- | --- |
| `passed` | 기대값과 실제 답변이 일치 | 포함 |
| `assertion_failed` | 응답은 완료됐지만 ID·제목·건수가 불일치 | 포함 |
| `dependency_error` | Mantis·Notion 연결 또는 타임아웃 오류 | 제외 |
| `execution_error` | 검사 실행 자체의 예외 | 제외 |
| `blocked_by_prerequisite` | 1차 질문 실패로 후속 질문을 실행하지 못함 | 포함 |

실행 상태는 다음 세 가지다.

- `passed`: 요청한 문항을 모두 평가했고 모두 통과
- `failed`: 요청한 문항을 모두 평가했지만 정확도 실패가 존재
- `incomplete`: 스냅샷 수집 실패, 연동 오류, 실행 오류 또는 질문 수 부족

`incomplete` 실행에서 평가 가능한 문항이 하나도 없으면 점수는 `N/A`다. 일부 문항만 평가됐다면 점수는 평가 완료 문항만 기준으로 계산하고, 시도 문항과 연동 오류 수를 별도로 표시한다.

## 검색 회귀 방지 규칙

### Notion 정확 제목

`노션에서 '제목' 항목을 찾아줘` 형태의 따옴표 내부는 문자 그대로 제목으로 취급한다.

- 제목 안의 고객사명, `MTS`·`HTS`, `확인`, 사람 이름, `[화면번호]`를 구조화 필터로 해석하지 않음
- 따옴표 바깥에 명시된 조건만 추가 필터로 사용
- 내부 따옴표가 포함된 제목도 바깥쪽 첫·마지막 따옴표를 기준으로 전체 제목 보존
- Notion 서버의 제목 필터가 끝나면 전체 DB 스캔으로 확장하지 않음

### Mantis 상태와 스냅샷

- Mantis 원본 상태 `developed`는 내부 표준 상태 `dev_done`으로 매핑
- 담당자·상태처럼 바뀔 수 있는 필터는 로컬 스냅샷 상위 후보를 라이브 Mantis로 재조회
- 라이브 값이 조건과 다르면 오래된 스냅샷 후보를 제거
- 라이브 API를 사용할 수 없을 때만 스냅샷을 폴백으로 유지하고 기준일을 표시
- 담당자·상태 테스트 기대값은 제한된 800건 표본과 전체 로컬 인덱스의 라이브 검증 후보를 합쳐 생성

## 연동 오류 대응

- Notion 읽기 요청은 기본 12초 제한과 1회 짧은 재시도를 사용
- 정확 제목 검색은 서버 측 제목 필터만 사용해 수천 건 전체 스캔을 피함
- 한 Notion DB가 실패해도 다른 DB의 검색은 계속하며, 결과가 있으면 `partial_error`로 반환
- Mantis 또는 Notion 스냅샷을 만들지 못하면 해당 소스의 문항을 억지로 생성하지 않고 실행을 `incomplete`로 기록

튜닝 환경변수는 [[설정 및 환경변수#검색 파이프라인 관련 설정]] 참고.

## Slack·Obsidian 자동 기록

`scripts/accuracy/run_accuracy_check_and_notify.py`는 검증을 실행하고 다음 경우 Slack 알림을 보낸다.

- 정확도 실패
- 연동 또는 실행 오류
- 요청한 수만큼 문항을 만들지 못한 불완전 실행

모든 실행은 Obsidian 요약 노트로 남긴다. 요약에는 실행 상태, 평가 정확도, 시도 문항 수, 소스별 통과 수, 정확도 실패 문항, 연동 오류 문항, 직전 유효 점수 대비 변화가 포함된다.

```bash
cd assistant_web
python3 scripts/accuracy/run_accuracy_check_and_notify.py
```

```bash
SLACK_WEBHOOK_URL=https://hooks.slack.com/services/xxx/yyy/zzz
ACCURACY_CHECK_QUESTIONS=10
ACCURACY_CHECK_FOLLOW_UP_SCENARIOS=4
OBSIDIAN_VAULT_PATH=/absolute/path/to/your/vault
OBSIDIAN_ACCURACY_FOLDER=Automation Reports/Mantis Notion
```

- `OBSIDIAN_VAULT_PATH`가 비어 있으면 기본 후보 볼트를 자동 탐지
- 스크립트는 스스로 cron에 등록하지 않음

```cron
0 8 * * * cd /path/to/Assistance/assistant_web && /usr/bin/python3 scripts/accuracy/run_accuracy_check_and_notify.py >> runtime/accuracy_reports/cron.log 2>&1
```

## 문제 확인 순서

1. 리포트의 `summary.status`가 `failed`인지 `incomplete`인지 먼저 확인
2. `assertion_failed`이면 expected·actual·audit ID를 비교
3. `dependency_error`이면 `retrievalStages[].reason`과 소스별 타임아웃 확인
4. Mantis 담당자·상태 불일치는 `snapshot_as_of`, `live_revalidated_count`, `stale_removed_count` 확인
5. Notion 제목 실패는 `exact_title`, `common_filter_clauses`, `scanned_count` 확인
6. 수정 후 전체 회귀 테스트 실행

```bash
cd assistant_web
python3 -m unittest discover -s tests -p 'test_*.py'
```
