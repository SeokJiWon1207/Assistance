# 아키텍처 — 검색 파이프라인

← [[00 Home]] · 관련: [[백엔드 구조]] · [[Mantis 연동]] · [[Notion 연동]]

## 전체 흐름

```
자연어 질문
   → LLM이 QueryPlan 생성 (operation / 소스 / 필터 / 정렬 / 개수)
   → 코드가 계획을 검증·보정 (query_planning.py)
   → Mantis · Notion 읽기 도구 실행
   → 근거 기반 답변 생성
   → 감사 로그로 검증
```

`QueryPlan`은 다음을 포함한다.

- `operation`: `search` / `count` / `get` / `aggregate`
- 검색 소스 (Mantis 전체 인덱스 / 저장 필터 / 페이지 스캔 / ChromaDB)
- 고객사·플랫폼·상태·등록일 범위
- 정렬 기준, 표시 개수

연도, "몇 개/몇 건" 같이 규칙으로 명확히 검증 가능한 조건은 모델 출력과 **독립적으로 재검사**해서 누락되거나 잘못 해석된 계획을 보정한다 (`app.py`의 `extract_query_constraints`, `merge_query_plan_constraints` 등).

## Mantis 도구 선택 우선순위

1. **Mantis 전체 로컬 인덱스** — 고객사·플랫폼·화면번호·담당자·등록일처럼 구조화 필터로 완전히 표현되는 목록/건수 집계. 건수 집계는 상위 N개가 아니라 전체 인덱스를 스캔.
2. **Mantis 저장 필터 API** — `config/mantis_filters.json`에 질문 키워드 ↔ `filter_id`가 매핑된 경우 (예: `신한투자증권` → `filter_id=123`).
3. **Mantis 페이지 스캔** — 자유 키워드 검색처럼 구조화 필터만으로 처리 불가할 때. `page_size=100`으로 최대 8페이지 조회 후 고객사/매체/키워드로 필터링.
4. **ChromaDB 유사도 검색** — `data/mantis_chroma_db/chroma.sqlite3`에서 관련 과거 이슈 문서 검색. 정확한 목록 조회보다는 유사 사례/과거 맥락 보조용.

## 감사(Audit) 검증

질문 의도 · 도구에 적용된 필터 · 조회 근거 · 계산 결과 · 최종 답변을 각각 검사한다. 아래 경우 통과 불가:

- 질문에 연도가 있는데 실행 계획에 등록일 범위가 없음
- 건수 질문이 목록 검색으로 처리됨

## 로컬 스냅샷과 데이터 기준일

로컬 인덱스(`data/mantis_chroma_db`)는 [[Mantis 연동#로컬 벡터 인덱스 (ChromaDB)|scripts/make_vector_db.py]]로 구축/갱신한다. 스냅샷 기반 답변에는 "데이터 기준: 로컬 스냅샷 YYYY-MM-DD 수집분" 안내가 붙고, 질문 범위가 스냅샷 기준일 이후를 포함하면 실시간 페이지 스캔을 병행해 최신 구간을 보완한다.
